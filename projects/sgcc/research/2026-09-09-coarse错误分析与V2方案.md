## 0. 结论速览

1. **主混淆方向 = partial↔upper 边界**：323/394 错误（82%），双向大致对称（185 + 138）。
2. **non_person 拦截不达标**：np recall 仅 **0.597**（74/124），是部署毒框拦截的直接风险。
3. **标签可疑占错误的 12.7%**（S1 doubao 分歧 ∪ S2 uncertain，基线 8.3%）；但"干净"子集准确率也只 82.6%——**77% 标签是 qwen 单模型独判**，边界噪声对怀疑标记不可见，根因是标注侧而非模型侧。
4. **复测修正**：test 实为 **0.817**（README 记的 0.826 是 val 值 0.825 误植）；**不存在 16pp val/test 落差**（val 0.825 / test 0.817，差 0.8pp；训练期 val 自 ep14 起平台在 ~0.82）。模型已撞到伪标签一致性天花板，不是过拟合问题——V2 若只调正则化方向就是错的。

## 3. V2 方案（按优先级）

1. **训练配方修复重跑（零成本，先做）**：V1 实跑 `scale=0.5, hsv_s=0.7, dropout=0`，三处均违背 2026-09-08 训练实践文档的明确建议（应为 0.1 / 0.3 / 0.1）。RRC 按 0.5 裁掉一半面积=把 upper 样本在线改造成"partial 长相"仍挂 upper 标签——直接污染承载 82% 错误的边界。**预期 +2~4pp**（边界格收缩），并消除与文档的配置偏差。
2. **doubao 全量重标 partial/upper 子集（约 16.5k 张 train+val+test）→ 共识留用 + 分歧 spark 三方仲裁**：把 77% 的 qwen 独判边界标签升级为双模型共识；分歧子集（估 5~10%，~1.5k）交 spark VLM 仲裁或降权。判例增强：把"整腿/鞋→partial、低头坐姿→upper"等判例写进 prompt 并配锚点。**预期 test 0.82→0.88~0.92**（网格判读显示约半数 PP→PU 错样模型本就判对，标签修好后直接回流）；test 同步重标保证口径一致。成本：doubao-lite ~18k 次（商用抽检级）+ spark 仲裁（局域网免费）。
3. **np 拦截专项**：np 训练池仅 1,049（1:9.3 失衡）→ 目录级过采样 3~4x；22 个 doubao 翻转 np 错样并入方案 2 的 spark 仲裁批；部署侧对 P(non_person)∈[0.3,0.7] 路由 VLM 二审（错样低置信分布已验证该路由可覆盖大部分 np 残余错）。**预期 np recall 0.60→0.75+，路由兜底后拦截 >0.95**。

**已评估未采纳**：coarse 合并为 {non_person, person} 二分类（+attr_upper_v1 承接 partial/upper）——二分口径可达 96.7%，但 np recall 仍 59.7% 未解决，且 upper 分类器在混淆子集上仅 42% 分辨率（upper=yes 在两类中大量重叠），边界信息实际丢失。仅当方案 2 后仍 <0.88 时作退路。

## 4. 验收口径（V2）

- test 三分类 top1 ≥ 0.88（双 VLM 共识标签口径）；np recall ≥ 0.75（模型侧）。
- 保留当前 0.817 结果作基线；混淆矩阵与错样清单复用 `coarse_v1_analysis/` 管线一键复跑。
