## 1. 验收设计

- **日期抽样**：iapx cache 盘点 src2 可用 10 个日期（06-22→09-03），选跨月差异最大的
  **06-22（6 月）/ 07-31（7 月末）/ 09-03（9 月）**；每日 6-7 MKV 时段铺开，含每日 1 个
  v3 零检出 MKV 作 FP 探针（12-10-01 / 09-40-03 / 09-40-03）。MKV 选择依据 = cache
  盘点的 in-ROI 检出量分布（各时段代表 + 零检出代表）。
- **v3 对照臂定源**：cache JSON 自带 `model_tag=person.pt@2026-09-09`（= v3 部署物
  `2026-09-09_person_n.pt` 日期），mtime 2026-09-13（早于 v4 上线与 09-15 回退）——
  v3 时代产物。**仍做了双保险**：用 v3 部署权重对同帧重跑（v3rerun 臂），与 cache 逐位
  对账（见 TL;DR 第 2 条）→ cache 可放心作 v3 臂；所有指标同时按 cache 与 rerun 两口径
  计算，结论一致（覆盖/det 命中均 99.92%，塌陷均 0）。
- **推理域**：crop640 部署域，crop_rect 读自 cache（三日期均 (255,0,640,640)，
  fail-loud 校验一致）；ultralytics 8.4.75，conf 0.5 / imgsz 640 / batch 16 共卡。
  （本机 NVML 监控层损坏、nvidia-smi 不可用，CUDA 正常；共卡纪律改用
  `torch.cuda.mem_get_info`，空闲 <2.5GB 等待。）
- **帧集**：每 MKV 抽全部 I 帧（ffmpeg `select='eq(pict_type,I)'` + ffprobe pts，
  镜像 iapx sampling 语义）→ 与 cache `frames[].time` join，**100% 对齐（0 帧失败）**。
- **in-ROI 判定**：检测框中心 ∈ ROI 多边形外接矩形（ROI 单一数据源 = cache `cfg_tag`
  第 6 分量 ×1920×1080，三日期同一多边形 x∈[360,789] y∈[163,384]）——与上轮验收同法。

分钟 presence 集合三日期**逐分钟相等**（v5 增益分钟 = 0，即 v5-only 帧全部落在 v3

## 5. 局限与残余风险（如实）

1. **单源**：语料仍限 src2（同机位/ROI）；src1 未覆盖（其 crop/ROI 配置不同，需另行
   验收或由生产灰度观察）。日期覆盖 3/9 个可用日期、20/114 个当日 MKV（时段代表性
   抽样，非全量）。
2. **det 级账目口径**：v5 独有 119 / v3 独有 79 为**非排他匹配**计数（一 det 可被
   多对引用，conf 0.5 边界抖动为主因），不与净增量（+48 raw）流守恒；净增量以
   face_stats 全量口径为准。
3. **VLM 单模型裁决**：豆包 lite 单模型判定真人/FP，8 例 FP 未经人工二审（渲染图
   已存档 `vlm/` 可复核）；玻璃反光与真人的边界判断存在模型主观性。
4. 帧级 v5-only 仅 10 帧 < 30，抽样下限以 det 级独有池达成（35 例）——口径已在 §2
   如实说明。
5. best.pt（PyTorch）≠ 生产 onnx（同上轮局限 3）；Rust presence/session 全链路未重跑。
6. 4 个 pts 毫秒碰撞帧双侧同额剔除（5332→5328，<0.1%，方向中性）。
