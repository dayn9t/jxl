# PAR 行人属性识别标准调研——多属性分类器属性词典对标业界（2026-09-08）

> 调研目的：把《2026-09-08-多属性分类器体系构想存档.md》§5 属性词典初稿建立在业界标准上，避免自造轮子。
> 重点回答四个问题：① PAR 标准数据集的属性集与标注口径；② 模糊属性（edge case / 逻辑约束）处理惯例；
> ③ 哪些属性实践中难学；④ 俯视/柜台截断场景的标注特例。
> 所有论断附来源 URL（项目规则）；术语保留英文。

## 1. 执行摘要

|---|---|---|---|---|---|
| PETA | 2014 | 19,000 图 / 8,705 人，10 个源数据集混合 | 61 binary + 4 multiclass（11 色 × 4 部位） | **identity-level**（每人抽 1 帧标注，跨帧传播，不可见也标）——被 RAP/PA-100K 论文一致批评 | 低（口径反面教材） |

| RAP v2 | 2019 | 84,928 图 / 2,589 ID / 25 场景 | 同 v1 | 同 v1；专业标注公司 + 3 轮抽检 | **高**（同上） |

| （检测侧）CrowdHuman | 2018 | 15,000 图 / 470K 框 | fbox/vbox/**hbox** 三框 | fbox 补全不可见部分（amodal）；bare ≤30% 遮挡 / partial 30–70% / heavy >70% | **高**（头部框 + 遮挡分级） |

**核心结论**：

1. **PAR 业界没有我们要的可见性属性**。PAR 属性全集是穿着/携带/人口学软生物特征（颜色/长度/包/性别/年龄），
   `is_person / head_visible / face_visible / upper_body_visible` 这类**可见性属性在 PAR 数据集中不存在**。
   可见性的操作化标准在两处：RAP 的 body-part bbox + 遮挡标注、检测侧数据集（CityPersons/CrowdHuman）的
   amodal/visible 双框 + 遮挡比例。**我们的属性词典 = PAR 的属性分组思想 + 检测侧的可见性操作化，两边都应对标**。
2. **标注口径两派，必须站 image-level**。PETA/Market-1501 是 identity-level（同人属性跨帧传播、不可见也标），
   被 RAP、PA-100K、UPAR 论文逐一点名批评为不适合视觉感知任务；后起数据集全部 image-level「只标当前帧可见」。
   我们 crop 级属性天然 image-level——正确，但要在词典里明写「以当前帧可见证据为准，不做身份推断」。
3. **业界 PAR 属性标注不用可见百分比阈值**。可见性判定全部 binary（RAP：「部位不可见即标遮挡」，无分级百分比）；
   百分比只出现在检测评测分层（CityPersons 遮挡 ≤0.35 为 reasonable；CrowdHuman bare ≤30%/partial 30–70%/heavy >70%）。
   我们草案的「≥50%」不是业界口径，但作为 VLM prompt 的锚定话术可用——**50% 的分母必须是「该部位完整大小（amodal 估计）」，
   不是检测框大小**（CityPersons/CrowdHuman 的 amodal 教训，见 §6）。
4. **模糊属性业界惯例 = 第三态 + 判例**。UPAR：不可判 → unknown，且 unknown 图**直接丢弃不入训练集**；
   PARSE-27K：遮挡/出画面边界 → N/A；BAP：<4/5 标注员一致 → unspecified；CrowdHuman：head_attr 有 unsure 标志；
   UPAR 补充材料用**问答式边界判例**（"打底裤算下装长吗？算。长靴算吗？不算。"）。我们草案的 uncertain 与业界一致，
   需补两条：uncertain 样本不入分类器训练；prompt 里为每个属性写边界判例。
5. **组内互斥是 UPAR 官方设计**（Age 三选一、Hair Short/Long/Bald 三选一、衣长二选一）——我们的四粗类互斥 = 同构，有先例。
   **face_visible→head_visible 的蕴含约束业界无先例**（因为没人有 face_visible 属性），需自建并写入一致性校验。
6. **难学属性规律 = 小区域 × 极端不平衡**（ALM：BaldHead 正例仅 0.4%、Hat、Muffler 最难；抽象属性如 Clerk 需全图语义）。
   映射到我们：`face_visible`（最小区域）预期最难，`upper_body_visible`（大区域）最易——与我们「负例定向补样」对策直接对齐。
7. **两处澄清**：① 检索不到名为 **WPA** 的公开 PAR 数据集（arXiv API、两份综述列表、PEARL/UPAR 相关工作、ACM TOMM
   检索均无；疑与 WIDER Attribute / PEARL 混淆，见 §2.8）；② **PETA-Z/RAP-Z 并非隐私重标注版**，实为
   **PETA-ZS / RAP-ZS**（zero-shot 身份切分，Wang et al. TCSVT 2024）——但其动机（PETA/RAP 的 identity 泄漏）对我们有直接警示（§5.4）。

## 2. 标准数据集逐个盘点

### 2.1 PETA（ACM MM 2014）——identity-level 反面教材

- 规模：19,000 图（8,705 人），来自 10 个小规模 re-ID 数据集混合，分辨率 17×39 ~ 169×365。
- 属性：61 binary + 4 multiclass（footwear/hair/上装/下装各 11 色）。61 个中 31 个「平衡」（大小类比例 ≤20:1）。
  含 15 个 UK Home Office/警方推荐的追踪与刑侦关键属性。基准子集 35 属性 = 15 个专家选定 + 20 个「难而有趣」（覆盖全身各部位与不同出现率）。
- **口径缺陷（后续论文点名）**：每人随机抽 1 帧标注、属性跨帧传播——「即使某些属性在该帧不可见也继承标签」
  （PA-100K 论文原话：samples "share the same annotated attributes even though some of them might not be visible"）；
  且随机切分导致同人跨 train/test（信息泄漏）。
- 来源：<http://personal.ie.cuhk.edu.hk/~ccloy/files/acm_mm_2014_pedestrian.pdf>（DOI: 10.1145/2647868.2654966）；
  项目页 <http://mmlab.ie.cuhk.edu.hk/projects/PETA.html>

### 2.2 RAP v1（arXiv 2016）/ RAP v2（IEEE TIP 2019）——与我们场景最同构的标注体系

- 规模：v1 41,585 图；v2 84,928 图 / 2,589 身份 / 25 室内场景（同一商场 HD 1280×720 监控网，30 天素材，GMM 检测+跟踪过虚拟线取样本）。
- 属性：72 = 69 binary + 3 multiclass（含 UK Home Office/警方推荐属性）；基准用 51 binary（正例率 >0.01 者保留，baldhead 因实际场景显著性破例保留）。
  长尾严重：多数属性正例 <10%，单人属性数 4–26（均值 12.2）。
- **与可见性直接相关的附标注（对我们最有价值）**：
  - **body-part bbox**：只标 3 个粗部位框——**head-shoulder / upper body / lower body**。
    原文理由：监控里行人小而模糊，"exact part positions, such as the arm and foot, are hard to be annotated in practical systems"——
    细部位（手臂/脚，更不用说脸）在监控画质下不可可靠标注，这是他们**放弃细部位、选 3 粗部位**的明确裁决。
  - **viewpoint**：F/B/L/R 四值，按全身朝向相对标注者判定（单值）。
  - **occlusion**：位置 4 类（上 T/下 B/左 L/右 R，多值）+ 来源 4 类（**persons / environments（含 camera border、desk）/ attachments（大件携带物）/ other**）。
    操作化原文："The occlusion is annotated when its corresponding parts are invisible"——**部位不可见即标，无百分比分级**。
    约 28% 图有遮挡（室内场景遮挡是常态）。
  - 属性为 image-level：同一身份不同帧可持不同属性标签（视角/遮挡/时间所致）——「只标可见」原则的落地。
- 质量控制：专业数据公司标注 + 3 轮抽样检查（workers 与论文组双重）。
- 实验证据：遮挡图上属性 mA 明显下降（Fig.10：occluded vs clean 对比）；视角变化同样拉低识别（Fig.7）。
- 来源：v1 <https://arxiv.org/abs/1603.07054>；v2 <https://zhangzhang80.github.io/RAP.pdf>（DOI: 10.1109/TIP.2018.2878349）；
  数据 <https://github.com/valencebond/RAP-dataset>

### 2.3 PA-100K（ICCV 2017, HydraPlus-Net）

- 规模：100,000 图 / 598 室外监控场景，1080p 采样。
- 属性 26 个（官方 LLM-PAR 模板代码验证的分组）：
  性别 1（Female）+ 年龄 3（<18 / 18-60 / >60）+ **朝向 3（Front/Side/Back）** + 头部 2（Hat/Glasses）+
  携带 4（HandCarrying/ShoulderBag/Backpack/Bag）+ 上装 6（短袖/长袖/stride/logo/plaid/splice 上衣）+
  下装 7（stripe裤/pattern裤/长外套/长裤/短裤/裙装/靴子）。
- **操作化惯例（对我们有用）**：
  - **丢弃规则**：模糊运动、分辨率低于 50×100 的行人直接弃标（不硬标）。
  - **tracklet 切分**：同一人的帧按 tracklet 整体分配进 train/val/test，防 identity 泄漏（明确批评 PETA 随机切分）。
- 来源：<https://openaccess.thecvf.com/content_ICCV_2017/papers/Liu_HydraPlus-Net_Attentive_Deep_ICCV_2017_paper.pdf>；
  代码 <https://github.com/xh-liu/HydraPlus-Net>；
  26 属性分组模板 <https://github.com/Event-AHU/OpenPAR>（`MSP60K_Benchmark_Dataset/LLM-PAR/PAR_Template_Scripts/process_pa100k.py`）

### 2.4 UPAR（2022 数据集 + WACV 2023/2024 Challenge）——口径统一基准

- 组成：PA100K（室外）+ PETA（混合）+ RAPv2（室内）+ Market1501-Attributes（室外，27 属性）四数据集统一；
  2023 版私有测试加 RAP2 + P-DESTRE（无人机 5.5–6.7m 俯拍）；2024 版加 MEVID 作新测试域（110 万新标注）。
  新增标注共 330 万 binary（主要为补齐各数据集缺失属性）。
- **40 属性 / 12 类目官方清单**（WACV 2023 论文 Table 1，加总 = 40）：

| 类目 | 属性 | 组内关系 |
|---|---|---|
| Age | Young / Adult / Elderly | **三选一互斥** |
| Gender | Female | 单属性 |
| Hair length | Short / Long / Bald | **三选一互斥** |
| UB clothing length | Short | 与 Long 隐含二分 |
| UB clothing color | Black/Blue/Brown/Green/Grey/Orange/Pink/Purple/Red/White/Yellow/Other（12） | 多标签 |
| LB clothing length | Short | 同上二分 |
| LB clothing color | 同 12 色 | 多标签 |
| LB clothing type | Trousers&Shorts / Skirt&Dress | 二选一 |
| Backpack | Backpack | — |
| Bag | Bag | — |
| Glasses | Normal / Sun | 二选一 |
| Hat | Hat | — |

- **unknown 处理**：长度类属性有 long/short/**unknown** 三态；年龄无法明确判定（非明显的未成年/成人/老人）→ unknown。
  **相关身体区域不可见、灰度/伪彩图 → unknown → 该图从 UPAR 剔除**（不进训练也不进测试）。
- **质量控制 = dual control 原则**：每帧由一名从未标注过该帧的独立校验员（validator）复核，操作错误当场纠正
  （MEVID 扩展：2,848 图 113,920 标签照此流程）。
- **边界判例**（补充材料，Fig.3 例）：「打底裤算下装长吗？→ 算。长靴算下装长吗？→ 不算。」——判例式边界定义，直接可抄进 VLM prompt。
- 每图独立标注（image-level）：同一人不同帧因可见区域/光照不同可持不同属性值。
- 来源：数据集论文 <https://arxiv.org/abs/2209.02522>；仓库 <https://github.com/speckean/upar_dataset>；
  Challenge 2023 <https://openaccess.thecvf.com/content/WACV2023W/RWS/papers/Cormier_UPAR_Challenge_Pedestrian_Attribute_Recognition_and_Attribute-Based_Person_Retrieval_--_WACVW_2023_paper.pdf>；
  Challenge 2024 <https://openaccess.thecvf.com/content/WACV2024W/RWS/papers/Cormier_UPAR_Challenge_2024_Pedestrian_Attribute_Recognition_and_Attribute-Based_Person_Retrieval_WACVW_2024_paper.pdf>
  （HTML：<https://openaccess.thecvf.com/content/WACV2024W/RWS/html/Cormier_UPAR_Challenge_2024_Pedestrian_Attribute_Recognition_and_Attribute-Based_Person_Retrieval_WACVW_2024_paper.html>；
  ChaLearn 页：<https://chalearnlap.cvc.uab.cat/dataset/45/description/>）

### 2.5 PEARL（WACV 2025）——含显式遮挡字段的最新数据集

- 规模：30K 图，12 国、7 类公共场所（街/公园/机场/车站/校园/海滩/市场）、4 种天气；Faster R-CNN 从 25h 监控视频提取，弃极模糊样本。
- 属性：25 类目 / 146 子属性（body posture、accessories、bag、clothing style/color、activity…）。
- **标注字段含 `Is Occluded?`（是否遮挡）与 `Which Part Occluded?`（哪部分被挡）**——遮挡本身作为属性schema 的一等公民（与 RAP 附标注同思路，但并入属性表）。
- 动机陈述直指我们的痛点：(i) 天气/遮挡/低光/相机角度/模糊使属性外观失真（如低光下帽子被标成黑发）；
  (ii) 视角阻碍属性判读（背面视角无法判眼镜/口罩）。
- 来源：<https://openaccess.thecvf.com/content/WACV2025/papers/Vijay_CLIPping_Imbalances_A_Novel_Evaluation_Baseline_and_PEARL_Dataset_for_WACV_2025_paper.pdf>

### 2.6 MSP60K（2024, LLM-PAR）——LLM prompt 标注同构先例

- 规模：60,122 图 / 57 属性 / 11 组（性别/年龄/体型/**视角 Front-Back-Side**/**头部 9 个：Bald、Long Hair、Black Hair、Hat、Glasses、Mask、Helmet、Scarf、Gloves**/上装 10/下装 6/鞋 5/包 7/动作 4/姿态 6）。
- LLM-PAR 用模板把属性扩展为句式（"What are wearing on their head?" 按身体区域分组提问）——与我们「VLM 一次调用回收全属性、按区域分组」同构。
- 跨域结论：随机切分下的 SOTA 换到跨域切分大幅掉点（HAP mA -18.22、DeepMAR 70.46→54.84），LLM-PAR 跨域 66.29 mA 仍是最优但差距 ~14 mA——**跨场景泛化是 PAR 未解难题**。
- 来源：<https://arxiv.org/abs/2408.09720>（HTML <https://arxiv.org/html/2408.09720v1>）；框架 <https://github.com/Event-AHU/OpenPAR>

### 2.7 检测侧邻接标准：CityPersons / CrowdHuman——可见性操作化的真正出处

**CityPersons**（arXiv 1702.05693）：
- **双框体系**：full box（amodal，头顶至双脚连线、固定纵横比 0.41 自动生成）+ visible box（「完全包住分割 mask 的最紧框」）。
  遮挡比例 = 由 visible/full 面积导出。
- **评测分层阈值**：reasonable = 行人高 ≥50px 且遮挡 ≤0.35（即可见 ≥65%）；后续文献将 CityPersons 分级归纳为
  Reasonable（遮挡 ≤35%）/ Heavy（35–75%）。
- **假人规则（正对我们红毛绒判例）**：ignore 区域含「annotator cannot tell if a person is present or absent」的模糊区、
  不可分的 person group、以及 **fake humans："people on posters, statue, mannequin"**、镜面/橱窗倒影——检测评测不计错、训练不计损失。
- 坐姿/非常规姿态者只标 visible（segment）框，不强行画 amodal 全身框。

**CrowdHuman**（arXiv 1805.00123）：
- **三框体系**：fbox（full，标注员**补全不可见部分**画框）+ vbox（crop 上画可见框）+ **hbox（head box）**——头部可见性有专门一等标注。
- 遮挡分层：bare ≤30% 遮挡 / partial 30–70% / heavy >70%。
- 类人目标（雕像等）单独标签、评测 ignore；tag 字段 `mask` = crowd/reflection/something like person → ignore（官方 download 页 JSON schema）。
- 质量控制："All the annotations are double-checked by at least one different annotator"。
- 来源：CityPersons <https://arxiv.org/abs/1702.05693>；CrowdHuman <https://arxiv.org/abs/1805.00123>、
  <https://www.crowdhuman.org/>、标注格式 <https://www.crowdhuman.org/download.html>；
  遮挡分级解读 <https://www.sciencedirect.com/science/article/pii/S0167865522003270>

### 2.8 WPA 与 PETA-Z 的检索澄清（诚实记录）

- **WPA**：arXiv API（`all:"pedestrian attribute" AND all:"WPA"` 零命中）、PAR 综述论文列表
  （<https://github.com/wangxiao5791509/Pedestrian-Attribute-Recognition-Paper-List>，20 个数据集无 WPA）、
  PEARL/UPAR/MSP60K 相关工作、ACM TOMM 检索——**均无名为 WPA 的公开 PAR 数据集**。任务书中的 WPA 疑为记忆偏差
  （可能混自 WIDER Attribute（14 属性，57,524 图）或 PEARL）。本调研以 PEARL/MSP60K 作为 2024-2025 数据集代际代表。
- **PETA-Z / RAP-Z**：不存在「隐私保护重标注版 PETA」。实际存在的是 **PETA-ZS / RAP-ZS**（zero-shot 身份切分，
  Wang et al., "Pedestrian Attribute Recognition via CLIP based Prompt Vision Language Model", IEEE TCSVT 2024,
  <https://arxiv.org/abs/2312.10692>）——把测试集换成训练中从未出现的**身份**，暴露传统切分下 mA 虚高。

## 3. 属性对照表（我们草案 × PAR 标准 × 采纳建议）

我们草案 = 四粗类（non_person/person_upper/person_full/person_partial）+ 布尔属性（upper_body_visible/head_visible/face_visible/is_partial）。

| 我们属性 | 业界最接近的定义 | 业界操作化 | 采纳建议 |
|---|---|---|---|
| **is_person**（框内主体是真人） | PAR 全体默认前提（无人标 non-person）；CityPersons/CrowdHuman 的 fake human / 类人 ignore 规则 | CityPersons：海报人/雕像/mannequin 标 ignore 不计错；CrowdHuman：雕像等单独标签+ignore；RAP 无此概念 | **照抄 CityPersons 假人清单做负面判例**：海报/照片/屏幕中的人、雕像、人体模型、玩偶/毛绒玩具、镜面倒影 → non_person。红毛绒判例直接入 prompt |
| **person_full**（粗类） | 无直接对应（PAR 假设全身可见 crop）；CityPersons full box（amodal） | amodal 全身框；reasoning 阈值可见 ≥65% | 保留；定义=头+躯干+下肢主体均可见（含 amodal 推断的界外部分不计） |
| **person_upper**（粗类，首个业务需求） | RAP body-part「upper body」bbox（躯干区）；UPAR「UB clothing length/color」属性组暗示上装区为独立判定单元 | RAP：upper body 作为三个粗部位框之一独立标注；UPAR：上装属性独立成组 | **采纳 RAP 部位框思想**：upper 的判定单元=躯干（肩线至腰），不含头、不含手臂要求（RAP 连手臂框都不标——监控下不可靠）。下半身被柜台截断不影响本类 |
| **person_partial**（粗类） | CrowdHuman heavy occlusion（>70% 遮挡）/ CityPersons heavy；PARSE-27K N/A 场景 | 遮挡比例阈值（检测侧 0.35/0.3/0.7）或部位不可见（RAP） | 采纳，但操作化按部位而非比例：头与躯干均不可辨识（见 is_partial 行） |
| **upper_body_visible** | RAP upper body 部位框 + UPAR 上装组 | binary 部位可见（RAP 式），无百分比 | 修订草案：主判据=**躯干（肩线至腰）轮廓可见 ≥50%**；手臂从「必要条件」降为辅助证据（草案要求"至少一条手臂"——RAP 经验：监控下手臂判定不可靠，且柜台场景手臂常被挡）。50% 分母=躯干完整大小（amodal），非检测框 |
| **head_visible** | CrowdHuman hbox（头部一等标注）；RAP head-shoulder 部位框；MSP60K 头部组（Bald/Long Hair/Hat…）；PEARL Which Part Occluded? | binary（hbox 有就标）；RAP 部位不可见才标遮挡 | 保留；锚定：**头顶至下颌的头形轮廓可见 ≥50%（含头发/后脑）；戴帽算可见**（业界 hat 是头上独立属性，不改变头部可见性——RAP/MSP60K/UPAR 一致） |
| **face_visible** | **业界无先例**（RAP 明言细部位难标故只取 3 粗部位；PAR 无面部可见属性） | 最近亲：PEARL 的 Mask 属性（口罩是否遮挡）、UPAR Glasses Normal/Sun | 保留草案（正面或侧脸 ≥50%，后脑勺不算）+ 补判例：**口罩/墨镜/手部遮挡不否定 face_visible（面部区域在，五官不必全露）；判据是面部皮肤/五官区域可见比例**。业界无对标，此属性词典须全自建并重点抽检 |
| **is_partial**（无人身主干，仅碎片） | CrowdHuman tag mask（something like person→ignore）；CityPersons 模糊区 ignore | binary | 修订「人身主干」为可执行定义：**头（head_visible）与躯干（upper_body_visible）二者均 <50% 可见 → is_partial**；仅手/腿/衣角碎片典型 |

## 4. 模糊属性处理惯例（edge case / 逻辑约束）

### 4.1 可见性百分比：业界 PAR 不用，检测侧只用于评测分层

- PAR 数据集标注阶段**零百分比阈值**：RAP「部位不可见即标遮挡」、UPAR「区域不可见→unknown→丢图」，全是 binary。
- 百分比只出现在**评测分层**：CityPersons reasonable（遮挡 ≤0.35）、CrowdHuman bare/partial/heavy（30%/70%）。
- 对我们：VLM 标注用「≥50%」可以，但必须**锚定解剖结构 + 判例**才能稳定（"头部可见 50%"这种裸百分比在标注员间不可复现——
  PEARL 论文批评既有数据集 "the presence of inaccurate guidelines during annotation introduces challenges"）。
  修订稿（§7）每属性给出锚定结构与 2-3 条判例。

### 4.2 模糊/不可判 = 第三态，且 unknown 不入训练

| 数据集/做法 | 第三态 | 后续处理 |
|---|---|---|
| UPAR | unknown（长度/年龄不可判；区域不可见/伪彩图） | **该图整体剔除**（训练测试都不进） |
| PARSE-27K | N/A（属性因遮挡或**出画面边界**不可判） | 记录但不计分 |
| BAP（Berkeley） | unspecified | 标注员一致度 <4/5 即触发 |
| CrowdHuman | head_attr.unsure | 可选字段 |
| APiS | ambiguous 标志 | 存在字段 |
| PA-100K | 无第三态，但**预处理即丢弃**模糊/小分辨率样本 | 丢弃 |

对我们的规则：VLM 输出 uncertain（已有裁决）→ **不进分类器训练集**（UPAR 惯例：宁缺毋滥），触发二审（doubao 交叉）或人工；
统计 uncertain 率作口径健康度指标（某属性 uncertain 率突增 = 词典措辞漂移信号）。

### 4.3 逻辑约束

- **组内互斥（业界先例）**：UPAR 12 类目中 Age（3 选 1）、Hair length（3 选 1）、LB type（2 选 1）显式互斥——
  我们四粗类 one-hot 同构，直接成立。
- **co-occurrence（业界警示）**：属性间相关是 PAR 核心难题之一——survey（1901.07474）指出 gender 与 clothing style 相关、
  label-based 指标忽略属性间相关；IJCAI 2023 有专文解 co-occurrence bias（A Solution to Co-occurrence Bias: Attributes
  Disentanglement via Mutual Information Minimization，见论文列表 <https://github.com/wangxiao5791509/Pedestrian-Attribute-Recognition-Paper-List>）。
  我们独立分类器族（不共享头）在结构上规避了负迁移，但**数据层的 co-occurrence 偏置仍在**（如「红毛绒玩具被 gdino+la 当人」
  = 特征 co-occurrence 欺骗），靠词典负面判例 + 负例定向补样对冲。
- **蕴含约束（自建）**：`face_visible=1 → head_visible=1`（解剖蕴含，业界无先例因无人有 face_visible）；
  `head_visible=1 ∨ upper_body_visible=1 → 粗类 ≠ person_partial`；
  `粗类=non_person → 全部布尔属性=0`。校验失败 → 打回 uncertain 流程（与我们 §6 已有「face=True 而 head=False 校验」裁决一致）。

### 4.4 质量控制惯例（人力侧，可降维用到 VLM/人工流程）

- BAP：≥4/5 标注员一致才采信；
- UPAR：**dual control**（独立校验员复核每帧）；
- RAP：专业公司 + 3 轮抽样检查；
- CrowdHuman：至少一名不同标注员复检；
- 我们的对应：VLM(qwen) 首标 → doubao 抽检交叉（已有裁决）→ 金标冻结集人审（已有设计）。
  UPAR 的 dual control 是「我们 doubao 抽检」的业界同构，可对外部表述时引用。

## 5. 哪些属性难学（低精度）与原因 → 对我们的预期

### 5.1 业界实证

- **ALM（ICCV 2019, arXiv 1910.04562）**：RAP 上最难属性 = BaldHead（正例率仅 0.4%，基线最差、ALM 提升 +23.1 mA 后仍属最难）、
  Muffler（+13.5）、Hat（+12.4）——**小区域 + 极端类不平衡**叠加。RAP/PETA 基准干脆把正例率 <1%（RAP）/ <5%（PETA）的属性剔除出评测。
- **抽象/全局属性**（Clerk、BodyFat、age）：需要全图高层语义，局部定位无效——另一类难法。
- **遮挡与视角**：RAP Fig.10 遮挡图属性 mA 全面低于 clean 图；Fig.7 显示视角变化同样拉低；survey 指出遮挡像素"使模型混淆导致错误预测"。
- **跨域**：MSP60K 上随机切分 SOTA 换跨域切分掉 14–18 mA——属性分类器**换场景即失效**是常态。
- **弱信号小目标**：survey 引 PANDA 例——"wear glasses" 在全身小图上信号极弱，随头姿/镜框/发型遮挡变化。

### 5.2 映射到我们的属性（预期难度排序）

| 属性 | 区域大小 | 预期难度 | 依据 |
|---|---|---|---|
| face_visible | 最小（面部） | **最难** | ALM 小区域规律 + RAP 弃细部位裁决 + PANDA 弱信号例 |
| head_visible | 小 | 中 | CrowdHuman hbox 一等标注可行，但小 crop 上仍属小区域 |
| upper_body_visible | 大（躯干） | 最易 | 大区域 + 窗口场景几乎恒 True（正例极多——反向不平衡，需负例定向补样，已有对策） |
| is_person / 四粗类 | 全框 | 易-中 | 大区域全局判据；难点在假人判例覆盖度（红毛绒教训） |

### 5.3 identity 泄漏警示（PETA-ZS/RAP-ZS）

PETA/RAP 因同身份跨 train/test 被 MSP60K 论文点名 information leakage；PETA-ZS/RAP-ZS（<https://arxiv.org/abs/2312.10692>）
把测试集换成未见身份后 SOTA 掉点。**我们固定机位同人反复出现，同险**——对策已在基建中：dino embedding 聚类去重 +
采样按簇（= tracklet/身份级分组），切分须按簇整体分（PA-100K tracklet 切分同构）。词典之外要写进造集规范：
**属性库切分以聚类簇为原子，禁止同簇跨 train/test**。

## 6. 俯视/柜台截断场景特例（收费窗口同构证据）

1. **RAP 是最近的同构先例**：室内商场监控，遮挡源显式含 **camera border（画框截断）与 desk（柜台）**——
   柜台截断在 RAP 体系里就是 occlusion 的 environment 来源，与行人互挡、携带物互挡并列，约 28% 图有遮挡。
   我们窗口场景「下半身恒被柜台截断」= RAP 常态，**不是异常样本，应作为一等分布对待**（person_upper 粗类单列正确）。
2. **amodal / visible 分离是处理截断的标准姿势**（CityPersons full box 补全不可见部分、visible box 只包可见；
   CrowdHuman fbox 同）：截断场景下「可见性百分比」的分母必须是 **amodal 估计的部位完整大小**，
   否则一个只露出头肩的人 head_visible=100% 而 upper_body_visible 也是 100%（相对其可见框）——语义完全错。
   我们的 VLM prompt 必须写明分母约定。
3. **出画面边界的属性不可判 → N/A**（PARSE-27K）：截断导致属性无法判定时不是硬猜而是第三态——与我们 uncertain 流程一致。
4. **坐姿/非常规姿态只标 visible**（CityPersons）：窗口顾客侧身/俯身取物等姿态下不强行推断全身——粗类判定只依据可见证据。
5. **俯拍有专门数据集**：P-DESTRE（无人机 5.5–6.7m 高度俯拍，UPAR 2023 私测集）证明俯视 PAR 是公认难域；
   我们摄像头虽非无人机，柜台俯视机位的头部/面部可见性与平视差异大（俯视更易看到头顶而非面部）——
   face_visible 在俯视机位天然稀少，预期正例率低，需在造集时定向补正面样本。

## 7. 属性词典操作化定义修订稿（v2，供用户裁决）

> 修订原则：每属性 = 一句主判据（锚定解剖结构）+ 分母约定（amodal）+ 边界判例（UPAR 问答式）+ 一致性约束。
> 同一措辞复用于 VLM prompt / 分类器验收 / 人工终审（防口径漂移，构想存档 §6 已裁决）。

### 7.1 词典 v2

| 属性 | 主判据（修订） | 边界判例（入 prompt） | 相对草案的变化 |
|---|---|---|---|
| is_person | 框内主体为真人或其一部分（任何可见比例）；判断对象是**框内像素主体**，非推断 | 海报/照片/屏幕里的人→0；雕像/人体模型→0；**玩偶/毛绒玩具→0**（红毛绒判例）；镜面倒影→0；只有一只手→1（是人的部分） | 增负面判例清单（抄 CityPersons fake humans） |
| 粗类 person_full | 头+躯干+下肢三区均可见（≥50%，amodal 分母） | 柜台挡住腿但髋以下隐约可辨→不算 full，算 upper | 新锚定：三区判据 |
| 粗类 person_upper | 头或躯干可见，下肢 <50% 可见（被截断/遮挡） | 只有头肩露出柜台→upper；全身在但半透明玻璃后→按可见比例 | 正面定义截断常态 |
| 粗类 person_partial | 头 <50% 且躯干 <50%，仅肢体/衣物碎片 | 一只手臂/一条腿/衣角→partial；头顶露 30%→partial | 「人身主干」操作化=头∪躯干 |
| upper_body_visible | **躯干（肩线至腰）轮廓可见 ≥50%**；分母=躯干 amodal 完整大小 | 柜台挡到胸口→上半躯干可见，算 1（≥50%）；只露肩膀→0；双臂全被挡不影响判 1 | 手臂从必要条件降级为辅助证据（RAP 手臂不可靠教训） |
| head_visible | 头顶至下颌头形轮廓可见 ≥50%（含头发/后脑）；分母=头部 amodal 大小 | **戴帽子→1**（hat 是独立属性不改头部可见性，RAP/MSP60K/UPAR 惯例）；后脑勺→1；只剩下巴→0 | 明确帽子/后脑判例 |
| face_visible | 面部区域（额头-下颌、左右耳前）可见 ≥50%；正面或侧脸均可；分母=面部 amodal | 后脑勺→0；**口罩遮口鼻→1**（面部区域在，判据是区域不是五官）；墨镜→1；俯拍只见头顶→0；侧脸 45°→1 | 业界无对标，全自建；增口罩/墨镜判例 |
| is_partial | = person_partial 粗类的布尔镜像（冗余字段，供校验） | 同粗类 | 与粗类绑定，仅作一致性校验用 |
| uncertain（第三态） | 任何属性判据落 borderline（40–60% 可见或证据矛盾）时输出 | 光线极差/运动模糊→uncertain；证据自相矛盾→uncertain | **明定：uncertain 不入训练集**（UPAR unknown 剔除惯例），触发 doubao 交叉或人工 |

### 7.2 一致性校验规则（schema 级，自动执行）

1. `face_visible=1 → head_visible=1`（违背 → 全记录打回 uncertain 流程）
2. `head_visible=1 ∨ upper_body_visible=1 → 粗类 ∈ {person_upper, person_full}`（不允许 partial）
3. `粗类 = non_person → 全部布尔属性 = 0`
4. `is_partial = 1 ↔ 粗类 = person_partial`
5. 四粗类 one-hot 恰一为真（UPAR 组内互斥同构）

### 7.3 VLM prompt 设计要点（对标 MSP60K LLM-PAR + UPAR 判例）

- 按身体区域分组提问（"head / face / upper body 各自可见多少"），组 ≤6 属性/次（已有裁决，MSP60K 模板同构）；
- 每属性 prompt 内嵌 2–3 条判例（§7.1 第三列原文照抄——UPAR 补充材料的问答式风格）；
- 输出含 uncertain 显式选项（不给「不知道」出口 VLM 会硬猜，PA-100K 干脆预处理丢弃模糊样本是同一教训的另一种解法）；
- 分母约定一句话写死：「所有可见比例均相对于该身体部位的完整大小估计，不是相对于检测框」。
