# YOLO26 分类器族训练实践调研（ultralytics 8.4.75）

> 2026-09-08 · 主题：用 yolo26l-cls 训练「1 个互斥四粗类 + 若干独立布尔属性」检测框 crop 级分类器族。
> 方法：官方文档 + 本地安装包 8.4.75 源码逐条实证（标注【源码】）+ 本机 RTX 4060 Ti 微基准（标注【实测】）。
> 配套背景：`projects/sgcc/archive/2026-09-08-多属性分类器体系构想存档.md`、`projects/sgcc/archive/2026-09-08-泛化验证毒标注发现存档.md`。

## 0. 结论速览

1. **ultralytics 分类的默认增强管线是为 ImageNet 全景图设计的，对紧框 crop 有三处毒点**：RandomResizedCrop（面积下限默认 50%）、RandAugment（默认开启，含 rotate/shear/translate 几何算子）、RandomErasing（默认 p=0.4，最多抹掉 33% 面积）。对我们的标签语义（四粗类=可见部位比例；head 可见=布尔）这些增强会**改变标签本身**，必须关闭或调到接近 0。
2. **val/inference 默认 Resize+CenterCrop 会把高瘦 person crop 的头/脚切掉**（实测 200×500 crop 顶部头部区域存活 0 像素）。数据侧 pad-to-square 或用官方文档的 custom trainer 模式改 transforms。
3. **分类无 class weights / 多标签 / sigmoid binary 模式**：loss 是裸 `F.cross_entropy`；「布尔二分类」= 两文件夹 softmax；不平衡靠目录级过采样或自定义 WeightedRandomSampler；毒框拦截靠推理侧调阈值。
4. **预训练迁移是"只重置最后 Linear"**：加载 yolo26l-cls.pt 后 backbone+neck 的 ImageNet 权重全部保留，自动适配 nc。
5. **全族部署无需特殊基建**：实测 6×yolo26m-cls 顺序推理（fp16, batch=64, RTX 4060 Ti）2.34 ms/crop、427 crops/s——一帧几十个 crop 过全部 6 个分类器 ~0.1 s，够用。

## 1. 数据组织（ImageFolder）

【文档】https://docs.ultralytics.com/datasets/classify/ ；【源码】`ultralytics/data/utils.py:check_cls_dataset`、`data/dataset.py:ClassificationDataset`

```
ds_coarse4/                 # 互斥四粗类
├── train/{non_person, person_upper, person_full, person_partial}/
├── val/{...同四类}/        # 缺失时回退用 test；都没有则自动 8:2 切分
└── test/{...}/            # 可选；model.val(split="test") 单独评
ds_head_visible/            # 每个布尔属性一套独立目录树（用户裁决：分类器不合并）
├── train/{yes, no}/
└── val/{yes, no}/
```

- torchvision `ImageFolder` 兼容格式，JPEG/PNG 均可；**每个 split 的类文件夹集合必须一致**（多出的类会被警告并跳过样本，【源码】`classify/train.py:get_dataloader` 有 nc 对齐过滤）。
- 【源码】类索引 = **train 目录下文件夹名字典序**（`sorted(names)`）。我们的映射固定为：non_person=0, person_full=1, person_partial=2, person_upper=3（字母序）。ckpt 里保存 names dict，推理侧以 `model.names` 为准，不要硬编码。
- 【源码】没有 val/test 目录时自动 `split_classify_dataset(train_ratio=0.8)` 切分（还能自动把散图归类）；但我们已有按帧划分的 train/val/test 约定（防泄漏），**自行落盘三个目录，勿用自动切分**——同帧相邻 crop 必须留在同一 split。
- val 缺失回退链：val → validation → valid → test（【源码】`check_cls_dataset`）。
- 布尔属性分类器：**没有 sigmoid 单输出 binary 模式**，nc=2 softmax 即"二分类"；阈值在推理侧对 `probs[positive]` 调（见 §6）。
- 【源码】`cache_ram` 被强制禁用（已知内存泄漏，issue #9824）；`cache='disk'` 可用（数万张 crop 全量进内存也就几 GB，实际不痛）。

## 2. 增强默认值逐条实证（毒点分析）

【源码】`ultralytics/data/augment.py:classify_augmentations` + `data/dataset.py:1024`（本机 8.4.75 实跑打印的 Compose）：

```
RandomResizedCrop(size=224, scale=(0.5, 1.0), ratio=(0.75, 1.333), interpolation=bilinear)
RandomHorizontalFlip(p=0.5)
RandAugment(num_ops=2, magnitude=9)          # auto_augment='randaugment' 默认开
ToTensor()                                    # 0-1 归一化；yolo26-cls 无 ImageNet mean/std
Normalize(mean=0, std=1)
RandomErasing(p=0.4, scale=(0.02, 0.33), ratio=(0.3, 3.3))
```

val/inference：【源码】`classify_transforms` = `Resize(短边→224) + CenterCrop(224) + ToTensor`。

### 2.1 为什么对紧框 crop 是毒点

| 默认项 | 默认值 | 对紧框 crop 的危害 |
|---|---|---|
| RandomResizedCrop | `scale=0.5` → RRC 面积 (0.5,1.0)，ratio 强制 (0.75,1.33) | ① 可裁掉 50% 面积（边长 ~71%），person_full 可能被裁成"person_upper 长相"但标签仍是 person_full → **标签噪声**；② 高瘦人框（w:h≈1:2.5）被 ratio 强制裁掉两侧或上下 |
| RandAugment | 默认开，2 ops @ magnitude 9 | 含 Rotate/ShearX/ShearY/TranslateX/Y 等几何算子，平移/旋转等效于随机裁切+出框，同样破坏"可见比例"语义 |
| RandomErasing | p=0.4，矩形 2%~33% 面积 | **head_visible 分类器的头可能被直接抹掉**（标签=yes 但图里没头）→ 直接污染布尔属性标签 |
| CenterCrop（val/推理） | 短边 224 → 中心裁 224 | 高瘦 crop 头/脚全切。【实测】200×500 紧框（顶部 100px 涂红=头）：resize 后 560 高、CenterCrop 取 168..392 行，**头部红色像素存活 0**。模型在 val/线上根本看不到头，head_visible 类任务必挂 |

### 2.2 参数级解法（推荐）与官方替代

- `scale`：classify 的映射是 `RRC scale=(1.0-args.scale, 1.0)`（【源码】dataset.py）。**`scale=0.1` → RRC (0.9,1.0)** 温和小裁（近似平移抖动）；`scale=0.0` → RRC (1.0,1.0) 退化为纯 resize（比例极端时按图像自身比例中心裁=无损）。文档明确 tuple 形式 "not for `classify`"（https://docs.ultralytics.com/usage/cfg/ 增强表），【实测】tuple 过了 cfg 校验但在 `1.0 - tuple` 处 TypeError 崩溃——classify 只能传 float。
- `auto_augment=''`：关闭 RandAugment（【实测】空串过校验且 falsy 生效）。副作用：关闭后 ColorJitter 转为开启（`if not disable_color_jitter`），参数接 hsv_*。
- `erasing=0.0`：关 RandomErasing（布尔属性分类器必须关；四粗类也建议关或 ≤0.1）。
- `hsv_s` 默认 0.7 太强（ColorJitter saturation 0.7），建议 0.3；hsv_v 0.4 保留（窗口场景白天/灯光照度变化大，亮度/对比度抖动是有益不变量）；hsv_h 0.01。
- `fliplr=0.5` 保留（行人朝向无语义）；`flipud=0`。
- **CenterCrop 毒点的两个解法**：
  1. **数据生成侧 pad-to-square（推荐）**：写 crop 时按长边补成正方形（优先用原图周边像素扩 context，贴帧边处用常数灰 (114,114,114)）。正方形输入下 Resize+CenterCrop 无损，且训练/推理链路保持 ultralytics 原生零改。dino 去重/聚类用原图不受影响。
  2. custom trainer/dataset 覆盖 transforms（官方给完整示例：自定义 `ClassificationDataset`/`ClassificationTrainer`，用 `T.Resize((224,224))` 直方拉正或 LetterBox）：https://docs.ultralytics.com/tasks/classify/ （"cropping-based transforms assume square inputs … may inadvertently crop out important regions from images with extreme aspect ratios" 的官方警告即此问题）。
- 归一化：yolo26-cls 的 DEFAULT_MEAN/STD=(0,0,0)/(1,1,1)——预训练就只做 /255。**自建 serving 预处理只需 ToTensor 风格 /255，别套 ImageNet mean/std**（会全错）。

## 3. 类不平衡

- 【源码】`utils/loss.py:v8ClassificationLoss` = 裸 `F.cross_entropy(preds, cls, reduction="mean")`，**无 weight 参数**；`engine/trainer.py:set_class_weights` 只被 detect/semantic trainer 覆盖，classify 不支持；cfg 里也没有 class_weights 参数（社区确认：issue #2208、#23972、#20259，https://github.com/ultralytics/ultralytics/issues/2208 ）。
- 三种替代（按实施成本排序）：
  1. **目录级过采样（推荐）**：构建数据集时对少数类复制/软链接文件至目标配额（如每类 ≥ 一定张数）。零代码、可复现（symlink 不占空间）；缺点是 epoch 内少数类样本重复出现等于放大其学习信号，配合早停即可。
  2. WeightedRandomSampler 自定义 trainer：覆盖 `get_dataloader` 换 sampler（教程：https://y-t-g.github.io/tutorials/yolo-class-balancing/ 、https://community.ultralytics.com/t/balance-classes-during-training-yolov11/692 ）。我们数万样本规模收益有限，暂不引入。
  3. **推理侧阈值调整（对我们最重要）**：softmax 输出后对 P(positive) 用非 0.5 阈值，按"负类召回（毒框拦截率）→ 正类误杀率"的 operating point 选（§6）。
- CutMix/MixUp/Mosaic：cutmix 参数只作用于检测 YOLODataset 路径（【源码】`data/dataset.py` YOLODataset 分支），**classify 管线不生效**，不用考虑。
- 我们的具体不平衡面：non_person 起步样本少（毒框审计后干净负例有限）→ 过采样 + VLabel 审核回流持续补；person_partial 大概率最稀缺（截断框天然少）。

## 4. 小数据（数千~数万 crop）防过拟合

- **预训练底座**：`YOLO("yolo26l-cls.pt")` finetune 是标准路径（ImageNet 预训练，top1 79.0 / top5 94.6）。【源码】`nn/tasks.py:reshape_outputs` 在 nc≠1000 时只重建最后 `Linear(in→nc)`（随机初始化），backbone/neck/Classify-head 的 conv 全保留——这就是官方迁移学习机制，无需手工 load。
- 参数量更正：yolo26l-cls = **14.1M** 参数 / 6.0 GFLOPs（fused；不是 19M）。yolo26m-cls 11.6M / 5.0 GFLOPs，top1 78.1——l 只比 m 高 0.9pt；**布尔属性这类简单二分任务建议 m 起步**（更快更不易过拟合），四粗类用 l。表：https://docs.ultralytics.com/tasks/classify/
- **freeze**：`freeze=N` 冻结前 N 个模块（`model.0.` ~ `model.N-1.`，【源码】trainer.py 按 named_parameters 前缀匹配；list 可指定任意层）。yolo26-cls 结构 = 9 个 backbone stage 模块（Conv/C3k2/C2PSA）+ 1 个 Classify head（l 因 depth 放大内部 repeat 展开为 176 层，但模块索引仍是 0..9）。freeze=9 即全 backbone 冻结只训 head。实践建议：先全量 finetune（数万样本足够喂 14M 模型），val 曲线过拟合再试 freeze。
- **dropout**：`dropout=0.1~0.2`（classify-only 参数，作用于 Classify head 内 nn.Dropout，【源码】`classify/train.py:get_model` 设置 `m.p`）。
- **early stopping**：`patience` 默认 100 ≈ 不早停；设 **20**。best.pt 按 fitness=mean(top1,top5) 选（【源码】`utils/metrics.py:ClassifyMetrics.fitness`）。
- **epochs**：官方 tips 起步 300、小数据酌减（https://docs.ultralytics.com/guides/model-training-tips/ ）；我们数万张 crop + ImageNet 底座，**50~80 epochs + patience 20** 足够收敛，先跑 1 个属性分类器看曲线再定。
- **optimizer=auto**（【源码】trainer.py `build_optimizer`）：`iterations = ceil(n_train / max(batch, nbs=64)) × epochs`；>10000 → MuSGD(lr=0.01)，否则 AdamW(lr=0.002×5/(4+nc))。我们 nc=4 → AdamW lr=0.00125。例：20k crop、batch 128、50 epochs → iterations≈15625 → MuSGD。两者都可用；若想稳定走 AdamW，显式 `optimizer=AdamW lr0=0.001`。
- **快速迭代**：`fraction=0.2` 子集先调配方再全量（官方 tips 推荐）；`seed` 固定 + `deterministic=True`（默认开）保证复现。
- imgsz：保持 **224**（与预训练分辨率一致，迁移最稳；crop 源 ≥100px 时上采样信息量足够。小脸 crop(<60px) 本身信息不足，靠检测器框质量而非加大 imgsz 解决）。

## 5. 训练配方建议表

四粗类与布尔属性共用数据底座，差异在增强强度与模型档位：

| 参数 | 四粗类 coarse4 | 布尔属性（head/face…） | 理由 |
|---|---|---|---|
| model | yolo26l-cls.pt | yolo26m-cls.pt（快速迭代 n/s 亦可） | 类间差异细（partial vs upper）需容量；布尔任务简单 |
| data | ds_coarse4/（4 类目录） | ds_<attr>/（yes/no 两类目录） | 独立分类器不合并（用户裁决） |
| imgsz | 224 | 224 | 与 ImageNet 预训练一致 |
| epochs / patience | 80 / 20 | 50 / 20 | 小数据 |
| scale | **0.0~0.1**（禁 0.5 默认） | **0.0** | RRC 大裁改变"可见比例"语义；布尔属性更脆 |
| auto_augment | **''** | **''** | RandAugment 几何算子破坏 crop 语义 |
| erasing | 0.0（≤0.1 可试） | **0.0（必须）** | RandomErasing 可抹掉属性判据（头/脸） |
| hsv_h/s/v | 0.01 / **0.3** / 0.4 | 0.01 / **0.3** / 0.4 | 关 AA 后 ColorJitter 生效；0.7 默认过强，照度抖动保留 |
| fliplr / flipud | 0.5 / 0.0 | 0.5 / 0.0 | 无朝向语义 |
| dropout | 0.1 | 0.1~0.2 | 小数据正则 |
| freeze | None（过拟合时 freeze=9） | None | 全量 finetune 优先 |
| optimizer | auto（MuSGD 0.01 / AdamW 0.00125 自动二选一） | 同左 | |
| batch | 64~128（4060 Ti 16G @224 无压力） | 同左 | |
| 不平衡 | 目录级过采样少数类 | 同左（yes/no 常天然不平衡） | 无 class weights 支持 |
| 数据预处理 | **crop pad-to-square 落盘**（正方形后 Resize+CenterCrop 无损） | 同左 | 见 §2.2；这是最重要的一条 |

一条命令形态：

```python
from ultralytics import YOLO
YOLO("yolo26l-cls.pt").train(
    data="targets/cls/ds_coarse4", imgsz=224, epochs=80, patience=20,
    scale=0.1, auto_augment="", erasing=0.0, hsv_s=0.3, dropout=0.1, batch=128,
)
```

## 6. 验收指标惯例

- 训练中 val 指标：`top1_acc`、`top5_acc`；**nc≤5 时 top5 恒等于 1.0（无意义，忽略）**。主线看 top1 + 混淆矩阵。
- 【源码】classify val 自动输出**混淆矩阵**（`confusion_matrix.png` + 归一化版，`classify/val.py:finalize_metrics` 调 `ConfusionMatrix.process_cls_preds`+plot）。per-class recall = 混淆矩阵对角 / 行和，从图读或用 `results.confusion_matrix.matrix` 自算。
- 我们的核心验收不是 top-1 而是**负类召回（毒框拦截率）**：
  - 四粗类：`non_person` 行的 recall（红毛绒玩具等假人目标必须被拦）+ `person_full/partial` 的 recall（人不得误杀）。目标形态：non_person recall ≥ 0.98 且 person 合计 recall ≥ 0.99（数字待第一轮实测后与用户定标）。
  - 布尔属性：对 `probs[positive]` 扫阈值画 PR/ROC，选满足"正类 recall ≥ X 的最大精度"点；阈值落盘进属性库随模型版本走。softmax 温度无需改，CrossEntropy 训出的概率排序可靠，绝对值靠阈值校准。
  - 对照集：用毒标注审计产出的 1,508 毒框簇（已 VLabel 终审）作为 non_person 验收金标准——它们是真实分布上的 FP 样本，比随机负例严苛。
- 集外验证：泛化教训（2026-09-08 存档）表明 train/val/test 同源会互相污染——test 集必须按帧/时段隔离，且加一个"未参与任何标注轮次的新时段抽样集"做最终把关。

## 7. 分类器族部署推理

### 7.1 吞吐量【实测，RTX 4060 Ti 16G，torch fp32/fp16，batch=64，224px】

| 配置 | 每 batch | 每 crop（全族） | 吞吐 |
|---|---|---|---|
| 6× yolo26m-cls 顺序 fp32 | 296.7 ms | 4.64 ms | 216 crops/s |
| 6× yolo26m-cls 顺序 fp16 | 150.0 ms | **2.34 ms** | **427 crops/s** |

结论：**同进程顺序执行即可**，无需 ensemble 特殊基建。yolo26l-cls（6.0 vs 5.0 GFLOPs）按比例估 ~2.8 ms/crop。监控场景单帧 person 框典型 <30，全族一帧 <0.1 s；4060 Ti 即富余，ds 的 5080 更快。官方参考：yolo26l-cls T4 TensorRT 2.8 ms、CPU ONNX 23.2 ms（https://docs.ultralytics.com/tasks/classify/ 表）。

### 7.2 推荐服务形态

1. **torch 直出（首选，起步）**：单进程加载 N 个 `.pt`，`model.fuse()` + `half()`，共享一份预处理（pad-square→resize 224→/255→CHW batch tensor），依次 forward，collect 各模型 `probs`。镜像现有 la-serve.sh 的 HTTP 服务模式即可。注意 eval 模式 forward 返回 `(softmax, logits)` 元组（【源码】head.py `Classify.forward`）。
2. **ONNX Runtime**：`model.export(format="onnx", dynamic=True, batch=N)` 动态 batch（https://docs.ultralytics.com/modes/export/ ）；每模型一个 session 共享输入 buffer，CPU 部署（无 GPU 的边缘机）走这条。
3. **TensorRT**（要极限延迟再上）：`format="engine"` 导出，或 ONNX 交给 trtexec，动态 batch 用 optimization profile（--minShapes/--optShapes/--maxShapes，把 opt 设为最常见 batch；见 https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/dynamic-shapes-basics.html 与 trtexec 手册 https://developer.nvidia.com/docs/drive/drive-os/7.0.3/public/drive-os-tensorrt-developer-guide/command-line-programs.html ）；INT8 用 `quantize=8`，分类任务校准数据传目录（export 文档明确支持）。
4. 独立分类器间无依赖（用户裁决），若未来出现"四粗类结果 gating 布尔属性"的级联需求，在服务层做条件转发即可省算力（如 non_person 直接跳过全部 person 属性模型）。

### 7.3 predict/val API 备忘

- 批量：`model.predict([path1, path2, ...], imgsz=224)` 一次 forward 多图；结果 `r.probs.top1 / r.probs.top1conf / r.probs.data(C,)`（【实测】yolo26m-cls 批量推理通过，probs shape (1000,)）。族服务建议绕过 predict 的文件 IO，直接组 tensor forward。
- 训练后 test 集评估：`model.val(data="ds_root", split="test")`（【源码】`check_cls_dataset` 支持 split 参数）。

**本地源码实证（ultralytics 8.4.75，`.venv/lib/python3.12/site-packages/ultralytics/`）**
- `data/augment.py:classify_augmentations / classify_transforms` — 训练/val 变换管线
- `data/dataset.py:1024` — `RRC scale=(1.0-args.scale, 1.0)` 映射
- `data/utils.py:check_cls_dataset` — 类名字典序、80/20 自动切分、val/test 回退
- `utils/loss.py:v8ClassificationLoss` — 裸 CrossEntropy 无权重
- `nn/tasks.py:reshape_outputs` — nc 不匹配只重建末层 Linear
- `engine/trainer.py:build_optimizer` — auto 优化器选择与 lr 公式
- `models/yolo/classify/{train,val}.py` — imgsz 224 默认、混淆矩阵输出
- `nn/modules/head.py:Classify` — eval 返回 (softmax, logits)、dropout
