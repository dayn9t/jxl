# 共识分层阈值数据分析（n001 crop640 毒标注 GT 反演）

> 日期 2026-09-08。用 1,508 个已确证毒框（purge_final.jsonl GT）反演三分层共识标注的界限阈值。
> 分析脚本：`/mnt/data/jiang/ws/sgcc/person/datasets/sgcc-n001/crop640_persons/gencheck/threshold/`（01-07，独立可重跑）。
> 结论速览：现行 k=2 闸门对毒框拦截率仅 **0.4%**（①毒率 7.96%）；推荐 **k≥2 ∧ strong≥1**（拦截 97.3% / 误伤 3.1%）；
> **任何共识闸门都做不到零残留**（k=4 全一致仍漏 1 框）→ ①免 VLM 但不可免位置扫描；端到端「①闸门 + ②位置聚类 + 区域兜底」在 GT 上残留 **0/1,508**。

## 1. 数据集口径

| 项 | 值 | 来源 |
|---|---|---|
| 训练集 | 13,788 帧 / 18,999 框（dataset_v2） | `dataset_v2/labels` |
| 毒框 GT（正例） | 1,508 框 / 1,501 帧（cam1 1,481 + cam2 27） | `gencheck/purge_final.jsonl` |
| 毒框构成 | cam1_toy_region 1,480（区域判据）+ mixed 簇 VLM object 28 | 同上 |
| 真框（视为干净） | 17,491 框 | 18,999 − 1,508 |
| 验证器输出 | 4 模型（yoloe/gdino/rfdetr/la）归一化 xyxy+conf，逐帧 join 覆盖 **100%** | `consensus/validators_all.jsonl` |
| 帧 level | L0 10,437 / L1 2,348 / review 1,003 | 同上（13,788 = 全量帧） |

- **分析单位 = dataset_v2 标注框**（真实训练框），毒/真以 IoU≥0.5 匹配 purge 框判定（1,508 全匹配、0 漏配）。
- **支持（vote）定义**：某验证器在该帧有与标注框 IoU≥0.5 的重叠框（取 IoU 最高者）。管线原值 0.4，敏感性见 §7。
- 现行管线参数（`mining_report.json` 实录）：`consensus=2`，IoU 0.4，权重 rfdetr .35 / gdino .30 / la .20 / yoloe .15。
  yoloe/rfdetr 为闭集强验证器，gdino/la 开放词汇弱验证器（la conf 恒 1.0）。`strong` = yoloe ∪ rfdetr。
- 注意：dump 中 `target` = person.pt 框（L0 直采源）；L1 标签 = 共识框、review = 仲裁框。本分析不依赖 target 字段，
  支持签名直接由 validators 计算，与 18,999 框的来源解耦。
- 位置聚类复现：eps=30 / min_samples=20 下 20 簇与 `audit_clusters.json` **20/20 大小完全一致**。

## 2. 毒框 vs 真框的共识签名

### 毒框签名（n=1,508）

| 签名 | 数量 | 占比 |
|---|---|---|
| **gdino+la（双弱、零强验证器）** | **1,461** | **96.9%** |
| rfdetr+gdino | 12 | 0.8% |
| 含 yoloe 的组合 | 21 | 1.4% |
| 含 rfdetr 的组合 | 27 | 1.8% |
| 4 票全一致 | 1 | 0.07% |
| <2 票（仲裁来源框） | 6 | 0.4% |

- 票数分布：2 票 1,482（98.3%）/ 3 票 19 / 4 票 1；强验证器数：0 强 1,466（97.2%）/ 1 强 36 / 2 强 6（≥1 强共 42，2.8%）。
- **gdino conf 中位 0.37（max 0.70）**，与真框（中位 0.81）明显分层；la conf 恒 1.0 无信息；
  rfdetr 在毒框上 conf 中位也仅 0.34（强验证器误支持时同样低 conf）。
- **帧级 score 完全无告警**：1,485/1,508（98.5%）毒框位于 L0（score=0「全一致」）帧——
  现行帧级争议分对这类毒标注零分辨力，问题在框级闸门而非打分。

### 真框签名（n=17,491）

| 签名 | 数量 | 占比 |
|---|---|---|
| yoloe+rfdetr+gdino+la（4 票） | 14,078 | 80.5% |
| 3 票（任一缺席） | 2,275 | 13.0% |
| **gdino+la（与毒框同签名）** | **416** | **2.4%** |
| ≤1 票 | 123 | 0.7% |

- ≥3 票 93.5%；≥1 强 97.1%；2 强 85.5%。真框 gdino conf p10=0.47 / 中位 0.81。
- **416 个真框与毒框同签名（gdino+la）**——这是任何纯共识签名闸门的误伤下限（≈2.4%），
  说明共识签名只能分流、不能终判，必须与位置签名（②层）互补。

## 3. 门槛扫描（核心）

闸门语义：框通过 → 进①免检直采；被挡 → 进②深度处理。误伤 = 真框被挡（进②后被漏斗+VLM 挽回 92.5%，成本非损失）。

| 规则 | 毒框拦截 | 残留毒框 | 真框误伤 | ①毒率 | ①框数 | →②帧数 |
|---|---|---|---|---|---|---|
| **R1 k≥2（现行）** | **0.40%** | 1,502 | 0.70% | 7.96% | 18,870 | 123 |
| R2 strong≥1 | 97.21% | 42 | 2.89% | 0.247% | 17,028 | 1,927 |
| **k≥2 ∧ strong≥1（推荐）** | **97.28%** | **41** | **3.08%** | 0.241% | 16,993 | 1,958 |
| k≥2 ∧ (strong≥1 ∨ gdino≥.5) | 97.08% | 44 | 2.34% | 0.257% | 17,125 | 1,840 |
| R1 k≥3 | 98.67% | 20 | 6.51% | 0.122% | 16,373 | 2,503 |
| R4b wsum_conf≥0.35 | 98.67% | 20 | 6.32% | 0.122% | 16,406 | 2,480 |
| R3 strong≥2（k≥2 ∧） | 99.60% | 6 | 14.53% | 0.040% | 14,955 | 3,666 |
| R4b wsum_conf≥0.45 | 99.60% | 6 | 10.07% | 0.038% | 15,735 | 3,029 |
| R1 k≥4（全一致） | 99.93% | 1 | 19.51% | 0.007% | 14,079 | 4,365 |
| R4b wsum_conf≥0.70 | 100.00% | 0 | 27.66% | 0.000% | 12,653 | 5,458 |

- R4（纯 wsum，不含 conf）在 0.55 处有一次跳变（gdino+la=0.5 被切掉，拦 97.8%/误伤 3.85%），
  本质是 strong≥1 的粗糙替身；**乘 conf 后（wsum_conf）分离度显著更好**，0.35 ≈ k≥3 但误伤略低。
- **满足「拦截≥95% 且误伤最小」的最优操作点：k≥2 ∧ strong≥1**（拦截 97.28% / 误伤 3.08%）。
  想再压残留取 k≥3（+1.4pp 拦截换 +3.4pp 误伤）；wsum_conf≥0.45 与 strong≥2 同拦截但误伤低 4.5pp，若要严格档应选前者。
- la conf 恒 1.0 使其在 wsum/wsum_conf 中贡献固定 0.2/0.2——la 的「验证力」被系统性高估，权重体系建议单独重估（本次不动）。

## 4. 强共识免检安全性检验（架构裁决章）

协调者追加问题：①层「多模型一致确认，直接采信」是否安全免检。各强共识子集的毒框残留：

| 子集 | 子集框数 | 毒框残留 | 子集毒率 | 真框保留率 |
|---|---|---|---|---|
| k≥3 | 16,373 | 20 | 0.122% | 93.5% |
| **k≥4（全一致）** | 14,079 | **1** | **0.007%** | 80.5% |
| strong≥1 | 17,028 | 42 | 0.247% | 97.1% |
| strong≥2 | 14,955 | 6 | 0.040% | 85.5% |
| k≥4 ∧ strong≥2 | 14,079 | 1 | 0.007% | 80.5% |

**裁决：任何共识闸门（含 4/4 全一致）都有非零毒框残留，「强共识即完全免检」不成立。**

- k=4 残留框 `1_0_2026-06-22_09-10-02.000_00031`：四模型全票 + wsum_conf 0.67，全部检测器在那一帧把玩具看成了人。
  strong≥2 的 6 个残留中 4 个也是玩具区（yoloe+rfdetr+gdino 三票），另 2 个是画面边缘条状框（y 0–0.045 / 0.95–1.0）。
- 但残留框的共同点：**全部落在静态物位置**——k=4 残留框中心 (599,377) 在玩具簇外接矩形内，
  即共识签名漏掉的，位置签名（②-lite 聚类扫描）能零成本兜住。
- 因此正确架构不是「①②合并为全覆盖深度审计」，而是：**①免 VLM（成立）但免不了零成本的位置聚类扫描**；
  位置扫描对 18,999 框跑 DBSCAN <1s CPU、0 VLM，应作为①的常驻卫兵而非②的专属步骤。
- 前提限定：本 GT 毒型单一（静态物）。若出现「四模型+VLM 全都认同」的毒型（镜面/海报/电视人像），
  此结论不外推——①的免检安全性只对该毒型已证。

## 5. ①② 与 ②③ 界限

### ①→② 界限 = 共识闸门

推荐 **k≥2 ∧ strong≥1**（yoloe/rfdetr 至少一个支持）。理由：
1. 拦截 97.28%，与更严闸门的差距（≤2.7pp）全部由②的位置签名补齐（§6 端到端残留 0）；
2. 误伤仅 3.08%（505 框），②漏斗对其挽回率 92.5%（345/373 高危框 VLM 判 person 保留）；
3. ②帧体量 1,958（占有框帧 13,176 的 14.9%），是各≥95%拦截闸门中最小档（k≥3 要 2,503 帧/19.0%）。
   （13,788 帧中 612 帧为空标负样本，无框可闸，不参与帧级统计。）

保守替代：k≥3（或连续版 wsum_conf≥0.35），适用于不上②位置扫描的轻量场景，代价 6.5% 误伤 + 仍漏 20 框。

### ②→③ 界限 = 位置签名参数 + VLM 抽样判定

**聚类签名（②-lite，扫全部框含①）**——eps×min_samples×嫌疑判据网格（7×3×27 组合）结论：

| 参数 | 稳定带 | 依据 |
|---|---|---|
| DBSCAN eps | **30**（25–40 均稳） | 复现 20/20 簇；纯物簇 (1,0) 在全网格（15–50）都被召回 |
| min_samples | **20** | 10–30 簇数 12–21，毒召回不变 |
| 簇大小 N | **≥20** | 纯物簇 1,460 ≫ 阈值；真实 mixed 小簇 23/34 也需纳入（N≥50 会漏） |
| 跨日期 D | **≥3** | D=2 与 D=3 在本数据无差异（簇日期数 4–10） |
| 尺寸变异 C | **禁用（不作为排除判据）** | 见下 |

- **C 判据（size_cv<0.3）是本次审计的隐藏陷阱**：mixed 簇 (2,0) cv=0.627、(1,6) cv=0.384，
  被 C 判据永远排除——全网格毒召回因此卡在 ~97%（1,460/1,508）。去掉 C（只留 N≥20∧D≥3）召回 98.7%（1,488）。
  实际审计没漏是因为对所有 20 簇做了 VLM 定性，没有信任 suspect 标志本身。
- 嫌疑簇必含大量常驻人员（(1,1) 5,163 框 / (2,1) 4,683 框，cv 0.19 同样「位置恒定」）——
  **静态物签名区分不了「常驻的人」和「常驻的物」，这一步只能靠 VLM 定性**，成本 3 calls/簇。
- 噪声散框（20 毒框，1.3%）任何聚类参数都覆盖不了，靠**确认 object 簇的外接矩形+10px 区域全扫兜底**：
  残留 10 框（闸门通过∧非嫌疑簇）全部位于玩具区域矩形内 → 区域兜底后 GT 残留 0。

**VLM 簇代表抽样（n=3/5/帧）判定翻转率**——用 3 个 mixed 簇 373 高危框逐帧 VLM 全扫作 GT：

| 簇 | 高危帧 | object 率 | n=3 日期分层漏检 | n=5 | 均匀 n=3（高危内） |
|---|---|---|---|---|---|
| cam2 cid0 | 341 | 7.9% | **95.7%** | 93.0% | 78.0% |
| cam1 cid6 | 10 | 10% | 87.4% | 79.0% | 70.0% |
| cam2 cid4 | 22 | 0% | —（无 object 可漏） | — | — |

- **n=3 抽样对低毒占比 mixed 簇的漏检概率 88–96%**：本次审计两簇都抽中 object 帧（联合概率 ~0.5%）是幸运而非设计。
  「抽样判 person」不可作为终判——它对 1% 级毒占比的簇几乎无分辨力（后验 ~15% 的「person」簇实为 mixed）。
- n=3 抽样的可靠用途只有一个：**全一致 object → 纯物簇快判**（纯物簇漏检 ≈0%）。全一致 person 仍必须走漏斗。
- 误报向：55 个簇抽样 call 中 1 例 LR 帧 object 误报（cam2 cid4 判 mixed，漏斗后 0 object，浪费 22 call）≈ 1.8%/call。
- **漏斗交叉（现网模型 IoU≥0.5 支持=低危）是②里真正可靠的压缩器**：3,136 框 → 373 高危（压缩 88.1%），
  逐帧 VLM 373 → 28 object（高危中 object 占 7.5%）。stats.json 佐证现网对该毒物不敏感：
  cam1 玩具在 disagree 对比中属 only_new（新模型 conf 0.91 检出、现网不报）16,352 帧大类。

### ③ 界限 = VLM 弃权/翻转疑难 + 终审抽查

- 本次 373 逐帧 VLM 无弃权（person/object 二值强制）→ ③输入实际为 0；
  引入弃权语义（vlm_ensemble 已有）后，③=弃权帧 + object 簇清洗终审。
- 实测人工层形态：purge 清单 1,501 帧 VLabel 预标终审（框已画好只判删/留），约 5–10s/帧 ≈ 2–4 人时。

## 6. 操作化定义（推荐流水线）与端到端验证

| 层 | 数据驱动判据 | 体量（本数据集） | 单位成本 |
|---|---|---|---|
| ① 直采 | **k≥2 ∧ strong≥1**（≥2 票且 yoloe/rfdetr 至少一票，IoU≥0.5） | 16,993 框 / 11,218 帧 | 0（验证器输出已在，纯过滤） |
| ① 卫兵（②-lite） | DBSCAN(eps=30, ms=20) 按 cam，嫌疑簇 **N≥20 ∧ D≥3**（禁用 size_cv），扫全部框 | 17 嫌疑簇 / 16,908 框 | <1s CPU，0 VLM |
| ② 簇定性 | 嫌疑簇 n=3 日期分层 VLM 抽样：全一致 object → 清洗候选；否则进漏斗 | 51–55 calls | ~3 calls/簇 |
| ② 漏斗 | 现网模型交叉（IoU≥0.5 支持=低危）→ 高危逐帧 VLM | mixed 簇 373 calls / 全嫌疑簇估 2,011 calls + 现网推理 12,640 帧 | 1 call/高危框 |
| ② 区域兜底 | 确认 object 簇外接矩形 +10px，中心在内全扫 | 2 区域（本次 1 个） | 0 |
| ③ 人工 | VLM 弃权帧 + object 簇清洗终审 + ①抽查（建议 1%≈112 帧） | 1,501 帧终审（实测形态） | 5–10s/帧 |

**端到端仿真（07_final_flow.py，GT 代真）：①闸门漏 41 毒框 → 全部被②嫌疑簇/区域兜底覆盖 → 最终残留 0/1,508。**
②对误伤框挽回 92.5%；全流程 VLM ≈ 428 calls（2.3% 覆盖率）即可全覆盖审计本数据集。

## 7. 局限性

1. **单场景单毒型**：GT 只含 n001 两相机的静态物误标（红色毛绒玩具 + 黑色包帽）。其他毒型
   （海报/镜面/屏幕人像、遮挡残影）未在 GT 中；「强共识免检」对这些毒型不外推，①的 1% 抽查是必要保险。
2. **真框纯度未全验**：17,491「真框」= 未被判毒，非人工确认；person 簇仅 3 帧抽样定性，
   person 簇内低比例毒框（同 mixed 簇逻辑）存在漏检可能——正是 §5 抽样分析警告的盲区。
3. **cam2 GT 部分循环**：purge 的 28 个 mixed 框由 VLM 判定产生，又用作 VLM 效果的 GT，存在自证风险（未人工复核）。
4. **阈值场景耦合**：gdino conf 0.5、wsum_conf 0.35、玩具区域矩形均从本场景反演，换场景需重标定；
   IoU 支持阈值 0.4/0.5 已做敏感性检验（k≥3 拦截 98.5%/98.7%，结论稳定）。
5. **la conf 恒 1.0**：wsum/wsum_conf 中 la 权重贡献虚高，权重体系未重估（本次只测闸门）。
