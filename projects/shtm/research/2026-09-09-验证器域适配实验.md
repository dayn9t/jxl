## 1. 设置

- 样本：`trash/cabin/samples` 分层抽 150 帧（每类配额 30 帧取并集、随机补足，seed=31，只读）。
  类覆盖 opening 108 / lid 67 / dump 35 / person 43 / can 51 帧；GT 框 opening 232 / lid 122 /
  dump 36 / person 51 / can 114
- 评测：GT=现行训练标注，IoU 0.4 贪心匹配（conf 降序）；检测 conf=0.25 全验证器统一
- 文本 prompt（yoloe/gdino/la 共用英文类名）：trash bin opening / trash bin lid /
  garbage pile / person / trash bin
- rfdetr-base：COCO 闭集仅 person（rf-detr 官方 person=1）；cabin.pt（2025-12-14 现役）全 5 类基线
- la=LocateAnything-3B @ ds:18306（**sdpa attn 显式降级**——flash_attn 预编译 wheel 无
  sm_120/RTX 5080 内核），协议单类单请求 ×5 类；其余验证器本机 4060Ti
- 产物：`/tmp/val_exp/`（sample.json、preds/*.json、metrics.json、实验脚本）

## 3. 每验证器强弱

- **cabin.pt**：全类 F1≥0.97——但样本即其训练集（自检循环），对 samples 无独立验证价值；
  对 snapshot 新帧非循环，可作 1 票
- **yoloe**：person R0.92；opening P0.77（R0.43）；can P1.00 但 R0.07（"trash bin" prompt
  对整桶几乎失明）；lid/dump 无效。定位=高精度低召回的弱确认者
- **gdino**：全类召回中高（person 0.96 / dump 0.92 / opening 0.61 / lid 0.48 / can 0.54），
  精度全线低
- **rfdetr**：仅 person（R0.94 / P0.42）——person 召回支柱；桶类 COCO 闭集结构性缺席
- **la**：桶类召回王（can R0.98 / lid R0.97 / person R0.98 / opening R0.81 / dump R0.86），
  精度全线低（P 0.09-0.53）

## 4. 结构性发现：桶类 FP 主体是跨类混淆

la/gdino 的桶类 FP 绝大多数压在真实目标上、仅类名错（la lid 280 FP 中 206 个跨类命中他类 GT；
can 290 FP 中 217；gdino 同构）：opening↔lid↔can↔dump 互相串。开词汇验证器**能定位、
不能区分嵌套桶类**。→ 共识须拆两级：**目标存在性**（框级投票，可靠）与**类归属**
（yoloe 高 P 票 / VLM 仲裁）。person 无此问题（跨类 FP≤6）。

## 5. 推荐共识组合与 strong/weak 闸门（对齐 k≥2 ∧ strong≥1）

| 类 | strong（高 R） | weak | 闸门 |
|---|---|---|---|
| person | rfdetr、la | yoloe、gdino | k≥2∧strong≥1 直接沿用（jxl person 体制平移） |
| opening | la | gdino、yoloe | la ∧ (gdino∨yoloe)；yoloe 命中可直采 |
| lid | la | gdino | la ∧ gdino；不足两票 → VLM |
| dump | gdino、la | — | gdino ∧ la 双高 R 交集提 P + VLM 二审 |
| can | la | gdino、yoloe | la ∧ gdino；yoloe 单独命中≈强证据 |
| cabin.pt（新帧） | — | — | snapshot 重标时非循环，可入投票 |

- 类归属争议（lid/can/dump 为主）一律 VLM 仲裁（spark qwen3.5），验证器只供框+存在性
- person 18 帧无 GT 但 ≥2 验证器命中（例 0468 帧 gdino/la 在 (0.46,0.13)-(0.51,0.20)
  紧凑同框、GT 缺席）——候选 GT 漏标，正是 k≥2 闸门要捞的对象，路由 VLM

## 6. det_mine 多类支持结论：不支持（记录，未改源码）

单类端到端：profile.yolo_text 单串 → yoloe `set_classes([单类])`、gdino 单 prompt 且解析
丢弃 label 文本、la 单类 query、rfdetr 单 cls_id；hardmine `Box`=5 元组无类字段，
score_sample 类无关共识；labels 输出单 cls_id；target 预测不按类过滤。适配需求：
1) Box 加类字段 + per-class 共识评分；2) profile 支持类列表（各类 text/rfdetr_id 映射）；
3) gdino 解析保留 label→类映射；4) la 单类循环天然满足；5) yoloe set_classes 原生多类。
本实验以原生 API（ultralytics/transformers/rfdetr）直测多类，绕过 det_mine。

## 7. 注意事项

- dump GT 仅 36 框 / person 51 框，F1 波动大，S1 执行期持续复核
- prompt 单版本未迭代（yoloe can R0.07 疑 prompt 敏感，可试 dumpster / garbage can）
- LA 无 confidence（恒 1.0），阈值策略不适用；sdpa 与 la_flash 精度未 A/B
- GT 本身 zero-trust 待检——"FP"中含真漏标（§5 person 例），矩阵按现行标注口径
