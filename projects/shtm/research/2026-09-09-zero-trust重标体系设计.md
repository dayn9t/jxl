## 1. 目标与总原则

**不把任何数据当作已确认数据**：SHTM 全部四源样本用新模型/新标准重新过检，低置信部分进自动标注循环重标，产出干净训练基准。

## 3. 源④ 时间切割与抽样（用户裁决 2026-09-09）

- **基准时间 = 2025-12-14**（现役检测模型 `2025-12-14_cabin.pt` 定版，部署 symlink 切于
  2025-12-23；实锤路径 `/opt/ias/project/shtm/model/cabin/cabin.pt`）
- **基准之前的样本全部放弃**——含 `n1.old`(76G)、`_arch`、各节点 2025-12-15 前的全部日期
- 基准后实有 **32,570 帧 / 9 日期 / n1+n7+n5 三节点**（三个批量日：2026-06-25=18,512、
  07-13=6,707、07-14=6,487；尾部 07-15=420、08-31=73）
- **B 方案抽样（≤5,000）**：尾部日期全取（07-15 420 + 08-31 73 + 零星 11 = 504）+
  三个大批量日按**摄像头分层**共抽 4,496（按各日摄像头数的比例配额，日内再按摄像头均摊）
- 抽样后叠加**置信度双轨筛选**（§4），低置信优先；若低置信子集 <5,000 则全取差额用分层样本补

## 4. 置信度筛选（双轨，阈值统计先行）

- **统计先跑（只读）**：抽样池 JSON 全量扫描 `prob_class.confidence`（检测）与
  `properties[].confidence`（属性，sort/amount/side 分别统计）→ 分位数分布 → 双峰谷点定绝对阈值候选
- **双轨判据**：`conf < 绝对阈值` ∪ `同摄像头同类最低 10-20% 分位`（分组=每摄像头，摄像头间难度差异大）
- **属性分层重标**：检测 conf 高但属性 conf 低的帧只重标属性，不重标检测（省算力）
- 解析兼容：properties.key 两版 schema 并存（旧数字 0/1 与新字符串 "sort"/"side"，meta/det_obj_msg.json vs 实测样例）——按 m31.json 定义统一映射

## 5. 重标执行（复用共识标注循环 + SHTM 域适配）

- 共识验证器**按垃圾桶域重配**：5 类（opening/lid/dump/person/can，m31 定义，opening/lid 挂
  parent=can）；闭集检测器无 opening/lid/dump 类——验证器组合与 strong/weak 闸门定义（k≥2∧strong≥1）
  需先做小样本适配实验标定（方案文档 §3.3）
- **位置卫兵按类反转**：can/lid 静态簇=正常业务；person/dump 静态簇=可疑（S0 已实测存量 0 可疑簇）
- VLM 仲裁 spark（qwen3.5，enable_thinking=False + json_object——SGCC 试跑定型参数直接复用）；
  uncertain→doubao 二审
- 属性词典 = m31 绑定关系（opening→sort+amount+illegal、lid→sort+side）进 prompt
- 产物落 VLabel 项目（m31 同源 schema）

## 6. 执行序与优先级（缺省建议，未获用户明确裁决项）

1. **统计先行**：抽样（B 方案）+ 置信度分布统计 + 阈值产出（全只读）
2. **源① samples 主体重检**（建议优先：现有训练集质量修复先行——去重 110 组 + 全量重推理打分）
3. 抽样池低置信帧共识重标（源②③并入）
4. 重训对比（干净 benchmark = 去重后 8,349 重切分）

## 7. 风险与边界

- snapshot 帧分辨率/ROI 与训练样本（1536x864 crop 640）的同构性需抽样核验
- 三个批量日可能对应特定事件（回放/事故），分层抽样后需按摄像头多样性抽查
- 5,000 重标的 VLM 仲裁成本：spark 免费主力（crop ~2帧/s），doubao 仅二审
- 本 spec 只动「重标输入筛选」，实际删除 samples 110 组重复仍需单独批准
