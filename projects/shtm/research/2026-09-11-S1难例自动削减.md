# S1 难例自动削减（双 VLM 一致闸门 + 隔离池，2026-09-11）

> 动机（用户 2026-09-10）：SHTM S1 难例人工审核量太大（1,957 hardcase + 1,528 backlog
> 候选 = 3,485 对象），用模型削减。裁决：**自动判定部分单独隔离，未经晋升不得混入正式
> 样本**（未定状态）。工具 `s1/hardcase_prune.py`（幂等可重跑）。

## 1. 方法

**统一问题**：对每个对象 crop（15% margin + 红框标注，同 S1 流水线风格），spark
qwen3.5-35b（spark:8000，temp 0）与 doubao-seed-2-0-lite-260215（ark，temp 0.1）
同 prompt 独立判定 `{is_bucket, cls, form, attrs, reason}`。

**闸门**（consensus-labeling k≥2 精神，双票逐字段全一致才自动，否则 HUMAN）：

| 情形 | 处置 |
|---|---|
| 任一模型 error/crop 超时 | HUMAN |
| is_bucket 不一致 | HUMAN(bucket_conflict) |
| 双判非桶 | hardcase→AUTO_DELETE / backlog→AUTO_REJECT |
| 双判真桶 cls 异 | HUMAN(cls_conflict) |
| 双判真桶 cls 同 + 该类全部适用属性有共识 | 与预填同→AUTO_CONFIRM / 异→AUTO_RECLASS |
| 属性有缺（判不准 null） | HUMAN(attrs_unresolved) |

**Prompt 迭代实证**（pilot 60，假设-实证循环）：
- v1（简略类目）自动率 28%，cls_conflict 集中 opening/can 粒度之争
- v2（注入类别草案全判据，~700 字）cls_conflict 18→3 但 bucket_conflict 15→26：
  **长 prompt 压垮 qwen3.5-A3B（3B 激活 MoE），向 none 塌缩**——26 例肉眼核对 spark
  几乎全错、doubao 大多正确。教训：小激活模型配短 prompt
- v3（紧凑版，保留判歧规则一行）自动率 48%（pilot），定稿
