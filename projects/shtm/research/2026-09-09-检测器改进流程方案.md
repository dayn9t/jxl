# SHTM 检测器改进流程方案（2026-09-09）

> 用户 2026-09-09 口述设想 + 主会话流程评审的整合方案。第一步只改进检测器（cabin 5 类），
> 属性分类轨道（sort/amount/direction/side/illegal）不在本方案范围。
> 上游：`2026-09-08-trash数据盘点.md`；工具与教训出处 n001 crop640（consensus-labeling skill）。

## 1. 目标与范围（用户设想忠实版）

用户口述原意（忠实保留）：

1. 已有大量从其他设备下载的数据（outside/_arch 等未标池），相当于已标注——旧模型伪标签
2. 从中筛选**置信度低**的图片作为样本，重新自动标注（借助已建立的自动标注循环：
   det_mine 五检测器共识 + VLM 仲裁）
3. **当前样本集**（cabin 9,064 对已有标注）同样筛低置信度部分重新自动标注
4. 目标：全面改进垃圾桶检测器

范围限定：只做检测（cabin.pt，opening/lid/dump/person/can）；分类器不动。

## 2. 流程设计（修订后完整流程）

```
S0 体检（先建 benchmark，否则"改进"无从度量）
   ├─ cabin.pt 泛化验证：gencheck 式差集 + VLM 仲裁
   │    对比双方 = 版本链权重（2025-12-14 现行 vs 2025-12-10 / TRAIN.md 横评权重）
   │    验证数据 = 未入集部分（新厢房 ~1,100 张 + 误报回流池）
   └─ 9,064 对老标注 label_audit：gate(k≥2∧strong≥1) + cluster 位置卫兵 + VLM 漏斗
   → 产出：干净 val/test benchmark + 存量标注污染清单（即 README 待裁决点 #4）
S1 筛选（双通道，覆盖两个数据源）
   ├─ 源 1：其他设备下载的未标池（outside/_arch/新厢房，范围待弃留裁决）
   ├─ 源 2：cabin 现有 9,064 对存量
   ├─ 通道 A：旧模型(cabin.pt)低置信度（conf 切点待标定，见 §6-1）
   ├─ 通道 B：位置聚类静态簇——高置信但几何签名像静态物（label_audit cluster 思路，
   │          判据须按类分别定义，见 §6-3）
   └─ 通道 C（可选）：新旧模型差集（gencheck 思路，首轮无新模型，第二轮起生效）
S2 共识重标
   ├─ det_mine 五检测器共识——验证器组合须为垃圾桶域重配（§3-3）
   ├─ 争议帧 VLM 仲裁（doubao 二级 → vlm_ensemble 三 VLM；批量优先局域网 spark/182）
   └─ 残余人工兜底（review_pack 拼图终审）
   ★ 旧伪标签/老标注只做筛选信号，标注框一律从共识投票重新产生（§3-2）
S3 合并重训
   ├─ 重标产物落 VLabel 基准（m31.json schema）→ vlabel-convert 导出 YOLO
   ├─ consensus_dataset 合并 → jxl_split 划分（复用 stem 保可复现）→ yolo_train（sgcc0）
   └─ S0 审计通过的存量老标注是否直接并入 vs 全量重标：开放问题（§6-2）
S4 验证闭环
   ├─ S0 benchmark 上新旧模型干净口径对比（mAP + 差集复验 + 位置误检簇复查）
   └─ 不达标 → 差集回流 S1 作新筛选信号（通道 C 生效），进下一轮
S5 飞轮循环
   └─ 生产误报回流 + dates/ 增量批次，按 S1→S4 周期滚动
```

## 3. 流程评审结论（主会话评审 2026-09-09，待用户确认）

1. **只筛低置信度不够**：n001 血训——高置信也可能系统性错（静态物位置固定误检：
   cam1 红玩具 1,480 框；L0 弱共识毒标注共 1,508 框，test mAP50-95 虚高至 0.895）。
   筛选信号须双通道：①旧模型低置信度 ②位置聚类静态簇（label_audit cluster 思路，
   高置信但几何签名像静态物）。可加第三信号：新旧模型差集（gencheck 思路）。
2. **旧伪标签只做筛选信号，不进训练集**：否则确认偏误循环——旧模型的错误模式经
   「重标」洗白后传回新模型。重标样本的标注框一律从共识投票重新产生。
3. **五模型共识需为垃圾桶域重配**：n001 验证器组合（yoloe/gdino/rfdetr/la + person 类）
   不能直接用——cabin 5 类是 opening/lid/dump/person/can，闭集检测器（rfdetr）COCO
   类表没有 opening/lid/dump（person 有；can 在 COCO 是易拉罐，语义≠整桶）；开放词汇系
   （yoloe/gdino/la）需改 prompt。验证器权重与强/弱分类（k≥2∧strong≥1 闸门的 strong
   定义）需在垃圾桶域小样本画像后重新标定。
4. **先体检再改进**：改进前对现 cabin.pt 做泛化验证（gencheck 式差集 + VLM 仲裁）+
   对 4 年老标注跑 label_audit——建立干净 benchmark，否则「改进」无从度量。
   这正是 README 待裁决点 #4，本方案将其升格为流程第一步（S0）。
5. **重标产物落 VLabel 基准**：jxl_label 即 VLabel 前身、m31.json schema 已在盘点报告
   识别；审计/手术/人工终审全走 VLabel 项目，训练导出走 vlabel-convert
   （n001 round-trip PASS @IoU≥0.99 先例）。

## 6. 开放问题

1. **低置信度切点**：通道 A 的 conf 阈值——S0 体检时看 cabin.pt 全量置信度分布 +
   差集误报簇 conf 水位再定，不预先拍脑袋。
2. **存量老标注信任级别**：S0 审计通过的部分直接并入训练 vs 全量共识重标
   （成本 vs 确认偏误风险的权衡，含 4 年迭代中可能已混入伪标签的历史）。
3. **通道 B 判据按类反转**：垃圾桶本身是静态物——can/lid 常驻位置正常，person/dump
   出现静态簇才可疑；与 n001（目标是人）判据逻辑相反，需逐类定义。
4. **outside 池价值**：62 万张 2021/2022 室外快照是否进筛选池（场景偏移 vs 数据量），
   依赖弃留裁决 + S0 泛化验证的域差结论。
5. **首轮新模型缺失**：通道 C 首轮不可用，S1 只有双通道；是否先训「过渡版」模型提前
   启用差集信号，待成本权衡。
6. **person 弱类策略**：val 中 person 仅 16 实例、R=0.85 最弱，但属 COCO 类、验证器
   适配最易——是否单独加强待裁决。
7. **属性轨道衔接**：检测框→裁切→属性分类联动（illegal TODO + 2025-12 批次 properties
   空洞）何时并入飞轮，待检测轨道跑通后裁决。
