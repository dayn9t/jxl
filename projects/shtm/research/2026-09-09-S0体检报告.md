## 3. benchmark 现状盘点

- 现行 val = `cabin/dataset/val` **890 张 / 2,199 框**（TRAIN.md 头部 706/1,453 是 2024-03 前旧口径，
  演进 706→889→890；2025-12-14 终评 all mAP50=0.974 / mAP50-95=0.916）。
- md5 join 溯源：val 890 帧全部映射回 dates/ 原图——**与 train 同池同源**（45 个批次随机划分，
  非时间 holdout；230/239 个 val 摄像头组同时出现在 train，固定机位近邻帧本身近似重复）。
- **内容级泄漏：79 个 hash 跨 split**（25 个同时进 train+val+test，val 涉及 46 个），
  全部源自上述重复拷贝被随机划分到不同 split；train 内部另有 421 冗余、val 8、test 17。
- val 类分布：opening 1,555 / lid 385 / can 162 / dump 53 / person 44——person 仍是弱类。
- 在集「新厢房」仅 10 张（2025-12-14 批 s12×5+s14×5）+ n5 节点 37 张（2025-12-10）：
  **val 完全不含新厢房视角，2025-12 迭代的泛化从未被度量过**。
- 可用性结论：现 val 不能直接当 S4 benchmark——须先去重（79 泄漏 hash + 内部冗余）、
  按摄像头+日期感知重切分，再增补审计后的新厢房帧作域外 test。

## 4. S1 启动建议

1. **先去重再一切**：dates/ 去重（8,349 唯一帧）是零成本高收益的第一刀，不做则 7.9% 冗余 +
   跨 split 泄漏继续虚高所有指标（n001 test 0.895 虚高的同型事故）。
2. 通道 A（低置信）切点建议 conf<0.5 起步、box 级 13%（1,307 框）、帧级 74.5%（540 帧），
   但因分布无肘部，叠加「同类框 conf 低于帧内中位」的相对判据；**ch16 全量优先**
   （低置信框 84% 来自 ch16，且 VLM 复核确认贴合差）。
3. 通道 B（静态簇）在存量上可轻量化：person/dump 无 ≥50 簇，唯一 person 候选（19 框）进 VLM 复核即可；
   通道 B 主战场应移到新厢房/生产回流（误报事件 0.94-0.96 高置信复现，正是高置信静态误检的形态）。
4. benchmark 重建以去重后 dates/ 为基座、摄像头+日期分层切分（复用 stem 保复现），
   新厢房 725 审计后单独作 test-domain 集；person 弱类（44 实例）趁机补样。
