## 0. 总则（五类共用）

- **可见比例基准（SGCC 属性词典风格）**：一切「可见多少才标」均以**完整物**为分母
  （完整桶体/完整口面/完整盖面/完整垃圾堆），**不以检测框或画面为分母**；
  截断、遮挡、出画是一等分布，不是例外。
- **嵌套结构**：opening/lid 是 can 的部件（parent_id=4），框可嵌套但**语义各指实物**，
  不允许用 can 框代替部件框，反之亦然。
- **待定出口**：判不了 → `pending` 类 / `common=pending` 属性，**禁止猜一个像的类**
  （No Silent Degradation；hardcase 轨道承接特殊形态人工核实，见形态词典 §2）。

## 1. opening 筒口（id 0，红）

- **操作化定义**：垃圾投入面（桶口平面）的**可见开放区域**。口面可见比例相对**完整口面**
  估计；≥ 建议阈值 1/3 即标，被盖/袋/大件垃圾遮住的部分从口面里扣掉。
- **正判据**：①无盖或盖开、口平面可见；②套袋桶**袋口开面视同桶口**（形态词典 bagged）；
  ③属性挂点：`amount`（桶内垃圾量，从口面观察）与 `illegal` 必须随框给。
- **负判据**：①盖完全闭合（口面 0 可见）→ 只标 lid；②口面被垃圾完全塞满无从判量 →
  不标 opening（见开放问题 O3）；③非桶的开口：墙洞、雨篦子、坑、池。
- **边界判例**：
  1. 满溢桶：垃圾冒出口面 → opening 照标 + `amount=full`；溢出体是否另标 dump → 开放 D1。
  2. 袋沿外翻的套袋桶 → opening 框贴**袋口开面**，不贴桶沿。
  3. 盖半开（口与盖同见）→ opening+lid 并存，口面比例只数开放部分。
  4. 斜俯视圆桶：椭圆口面按**口平面投影**框，不按可见内壁。
- **开放问题**：O1 袋口=桶口是否无条件成立？O2 最小可见口面比例 1/3 是否合适？
  O3 口被垃圾塞满（判不了量）时标 opening+`amount=pending` 还是不标？

## 2. lid 筒盖（id 1，橙）

- **操作化定义**：桶盖本体的可见部分，相对**完整盖面**估计；斜置/竖开/手提均按盖的实际朝向框。
- **正判据**：①闭合在桶上的盖；②翻开竖起、掀在桶侧的盖；③已脱离桶体的盖（斜靠、落地）
  ——仍标，parent 归属见开放问题 L2；④`side`（正/反面）随框给。
- **负判据**：①无盖桶（敞口、筐状）不造盖；②桶口金属圈/包边不算盖；③盖形杂物
  （砧板、纸板斜靠桶边——C4_emptyfp 实证同型误检）不算。
- **边界判例**：
  1. 盖闭合 → lid+can 双标，opening 不标（本文件 §1 负判据 ①）。
  2. 盖半开 → lid+opening+can 三标并存，各框各实物。
  3. 盖与桶同色融为一体 → 只框可辨盖沿，可见比例仍相对完整盖面。
  4. 手提盖对准桶口瞬间 → lid 标，parent 挂目标桶。
- **开放问题**：L1 半开三标是否确认为终稿口径？L2 脱离桶体的盖 parent 挂最近桶+pending，
  还是允许 orphan？L3 需否给 lid 加 aspect filter（盖通常扁宽）？

## 3. dump 垃圾堆（id 2，黄）

- **操作化定义**：**脱离容器**、堆积于地面/台面/桶顶的散装垃圾集合；相对**完整垃圾堆**
  估计，不按单件垃圾逐个标。
- **正判据**：①地面成堆散装垃圾；②堆在桶顶/桶旁贴靠桶身的垃圾体；③装修渣土、成堆袋装垃圾。
- **负判据**：①桶内不可见垃圾（只记 `amount`，不开框）；②单个散落小件（一袋一瓶）不足成堆；
  ③刚投放、仍在人手中未落地的垃圾（跟 person/dump 边界见 P2）。
- **边界判例**：
  1. 满溢溢出桶外的部分 → 与 opening/can 并存各标（是否并入 → 开放 D1）。
  2. 垃圾堆压住桶身 >1/2 → can 与 dump 并存，**不合并、不互删**（域适配实验 §4：合并正是混淆源）。
  3. 扎口完整垃圾袋堆 → 倾向 dump（开放 D3 确认）。
  4. 簸箕/斗车内的垃圾 → 容器承载，不标 dump（容器是否 can → 难例轨道）。
- **开放问题**：D1 溢出体：另标 dump 还是只 `amount=full`？D2 成堆最小规模
  （建议 ≥2 件或占桶容 1/4）？D3 扎口整袋堆算 dump 确认？

## 4. person 人员（id 3，绿）

- **操作化定义**：现场真人；可见比例相对**完整人体**估计，截断（半身入画）照标。
- **正判据**：①全身/半身/出画截断的真人；②正在投放垃圾动作中的人（投递物另判）。
- **负判据**：①海报、镜面、人形玩偶、雕像（SGCC fake-human 判例平移）；②监控回显屏里的人
  （二次成像）；③人形垃圾袋轮廓（C4_emptyfp 实证）。
- **边界判例**：
  1. 人弯腰探入桶内 → person 照标，与 can/opening 嵌套并存。
  2. 推车/骑车经过者 → person 标人，车不标。
  3. 域适配实验 §5：18 帧 ≥2 验证器同框但 GT 缺席 → 此类是漏标，补标不回避。
- **开放问题**：P1 截断下限（可见比例 <1/4 是否仍标）？P2 手持垃圾未落地 = person 单标确认？

## 5. can 整桶（id 4，蓝）

- **操作化定义**：一个**承担垃圾桶职责的容器**个体的全部可见部分（桶体+口+盖+附着袋）；
  相对**完整桶体**估计。形态四分：standard / round / bagged / basket（形态词典 V1），新形态走难例轨道。
- **正判据**：①方/圆/套袋/筐状四形态桶；②翻倒的桶（框随倒伏姿态）；③被遮但桶型可辨
  （建议可见 ≥1/2 完整桶体）；④属性 `direction` 随框给。
- **负判据**：①临时容器：编织袋、纸箱、塑料箱（C4_emptyfp 实证：红色编织袋/红色塑料箱被误检为 can）
  ——除非难例轨道核实其确承担垃圾桶职责；②桶形贴图/宣传画；③桶的倒影。
- **边界判例**：
  1. 套袋桶 → can 框含外翻袋沿，opening 贴袋口（与 §1 判例 2 咬合）。
  2. 筐状/编织篓 → 已入形态词典的 basket 形态，正常标 can 并 `form=basket`。
  3. 双连桶/桶阵 → 每桶一框，不并框。
  4. 桶被 dump 埋半截 → 与 dump 并存（§3 判例 2）。
- **开放问题**：C1「承担垃圾桶职责」的操作化判据（有垃圾+位于投放点？还是人工核实唯一通道）？
  C2 遮挡上限 1/2 合适否？C3 form 是否正式入 schema（现为 hardcase 字符串散落）？

## 6. 标注工具改进建议（由上述定义推导，m31.json 落点）

1. **联动标注**：新建 can 后弹「盖状态」二选一 → closed 自动挂 lid 框（贴盖沿）/ open 自动挂
   opening 框（贴口面）；半开则两者都挂。删除 can → 级联确认 child，防 orphan。
2. **互斥仲裁**：同一 parent 下 opening 与 lid 框重叠超阈值（建议 IoU>0.5）→ 报警强制改口
   （closed/open 二选一）；跨桶重叠不报。
3. **属性联动**：`sort` 沿 can→opening/lid 继承（同桶一色，改一处联动）；`amount`/`illegal`
   无默认值，建 opening 即强制显式给值（不得静默补默认）。
4. **orphan 检查**：导出校验 lid/opening 无 parent can 可匹配 → 打 `common=error`（复用 m31 现值）。
5. **form 入 schema**（开放 C3）：can 增 `form` 枚举 standard/round/bagged/basket，
   承接 hardcase_list 现散落的 `form=bagged/round/basket` 字符串。
6. **aspect filter 扩容**：opening 已有 [0.25,4.0]；lid 建议扁宽向、can 建议立桶向（数值待 L3/C3 裁决）。
