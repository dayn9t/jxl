# SHTM 垃圾桶形态词典（标注参考，2026-09-09 用户口述建立）

> 用途：共识标注 prompt、VLM 仲裁词典、难例归集判据。发现新形态持续增补。

## 1. 已知形态（V1）

| 形态 | 描述 | 标注要点 |
|---|---|---|
| 标准方桶 | 常见方形/矩形垃圾桶 | 基准形态，opening/lid/can 类直接适用 |
| **圆桶** | 圆柱形桶（非方形） | 同属 can；opening 为圆口/圆盖 |
| **套袋桶** | 桶口套塑料袋（袋沿外翻可见） | 桶体可辨则标 can；袋口满溢=amount 判据之一 |
| **筐状桶** | 篮/筐形（镂空或编织感） | 场景中承担垃圾桶职责即算 can |
| （待增补） | —— 发现新形态先入难例核实，确认后正式入表 | |

## 2. 难例归集原则（用户裁决 2026-09-09）

场景中**可能承担垃圾桶职责**的特殊、难以确定的容器/结构 → 一律归入**难例（hardcase）轨道 → 人工手动核实**，不得由共识闸门自动放行。核实确认后：①正式入形态词典；②其标注样本入训练集。

## 3. 提示词反哺（关键词自学习，用户提出的核心机制）

**从已标注的特殊垃圾桶样本中提取描述关键词 → 反向用作标注新数据的提示词**：

```
已核实特殊样本（圆桶/套袋/筐状…）
  → VLM 生成外观描述关键词（"圆柱形绿色桶，桶口外翻白色塑料袋"…）
  → 人工核一遍关键词
  → 注入开放词汇检测器 prompt（yoloe/gdino/la 的文本 query）
    与 VLM 仲裁词典（形态判例）
  → 标注新数据（覆盖面扩大）
  → 新特殊样本再进难例轨道 → 循环
```

价值：开放词汇检测器对「垃圾桶」的文本理解默认偏标准形态；反哺关键词把域内形态多样性喂给它，直接提升共识验证器（§5 重标循环）对该域的召回——**形态词典与提示词共同演化**。
