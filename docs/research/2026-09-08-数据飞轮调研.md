## 1. 执行摘要

| 技术 | 机制一句话 | 对我们场景的适用判断 |
|------|-----------|---------------------|
| SAM 数据引擎（Meta 2023） | 三阶段递进「模型辅助人工→半自动预标注→全自动标注」，模型每轮重训后承担更多标注、人只补模型不会的（多样性前沿） | **最核心参照**。用户记忆中 Meta「少量人工+循环得巨量样本」即此。其阶段 2「预填高置信、人补遗漏」正是我们要的循环形态 |
| SAM 3 数据引擎（Meta 2025） | 在 SAM 1/2 基础上引入 LLM 微调的 **AI verifier**（替代大部分人工验收）+ 失败样本主动回流挖掘 | AI verifier ≈ 我们的 VLM 仲裁层；证明「VLM 当仲裁」是当前 Meta 官方路线 |
| 主动学习（Active Learning） | 用模型的不确定度/分歧度排序未标注池，只把预算花在最 informative 的样本上 | 适用于**扩量阶段**（采新数据标注什么）；对已标数据的错误发现用 label error detection 更直接 |
| 自训练/Noisy Student | teacher 生成伪标签→带噪声训练更大 student→student 变新 teacher 迭代 | 适用于**海量无标注视频帧**的扩样；必须配置信度过滤+类平衡，检测上需 EMA teacher（Unbiased Teacher） |
| Confident learning / Cleanlab | 用模型预测概率估计「噪声标签×真实标签」联合分布，给每个样本打 label quality 分 | **最直接的错标筛查工具**，官方有 object detection 教程；需 K 折交叉验证产生 out-of-sample 预测 |
| Dataset cartography | 训练过程中记录每样本的置信度/变异性/正确性，hard-to-learn 区≈错标区 | 零额外推理成本（训练时顺手记录），可作辅助信号 |
| 干跑对照（model-vs-label） | 训练好的模型回推全数据集，预测与标注不匹配处即疑似错标/难例 | 我们循环的**主信号**；配合多检测器即天然 query-by-committee |
| Tesla 数据引擎 | 影子模式跑真车→trigger 触发回传→离线大模型自动标注→重训 OTA | 固定机位监控的「时序一致性 trigger」可直接借鉴（轨迹断续≈疑似 FP） |
| Model-assist 工具（Label Studio/CVAT/Roboflow 等） | 模型预测预填标注，人只做 accept/edit/reject | 人工兜底环节提效手段；预标注已是我们共识标注的既有形态 |

**核心结论**：数据飞轮的本质不是「自动标注越多越好」，而是 **模型承担 routine、人（或 VLM 仲裁）专攻 frontier + 错误信号驱动定向修正 + 固定金标评测集防自我强化**。SAM 系列三年三代数据引擎（2023/2024/2025）都保持这一骨架，演进方向只是「验收者从人→AI verifier」「标注物从 mask→概念/3D」。

## 2. SAM 数据引擎详解（重点章）

### 2.1 SAM 1（2023）：三阶段数据引擎 → SA-1B

**原始论文**：<https://arxiv.org/abs/2304.02643>（ICCV 2023 版：<https://openaccess.thecvf.com/content/ICCV2023/papers/Kirillov_Segment_Anything_ICCV_2023_paper.pdf>；官方博客：<https://ai.meta.com/blog/segment-anything-foundation-model-image-segmentation/>；仓库：<https://github.com/facebookresearch/segment-anything>；数据集页：<https://ai.meta.com/datasets/segment-anything/>）

最终产出 SA-1B：**11M 图像、1.1B masks**，比既有最大分割数据集多 400 倍 masks（官方博客口径），约为第二名的 6 倍。论文摘要明确将其表述为「在数据采集循环（data collection loop）中使用高效模型」建成的数据集（ar5iv 版：<https://ar5iv.labs.arxiv.org/html/2304.02643>）。

#### Stage 1：辅助人工标注（Assisted-Manual）

- **规模**：120k 图像，4.3M masks。
- **交互**：浏览器工具，点击前景/背景点，SAM 实时（预计算 embedding）出 mask，再用像素级 brush/eraser 精修。
- **质量规则**：无语义约束（stuff/things 都标）；按显著度顺序标对象；**单个 mask 超过 30 秒就跳过**（防低效死磕）。
- **模型演进**：初始模型用公开分割数据集训练；期间 image encoder 从 ViT-B 扩到 ViT-H，**共重训 6 次**——每轮新数据都让模型更强、标注更快。
- **效率**：每 mask 耗时从 34 秒降到 14 秒；14s 比 COCO mask 标注快 6.5 倍，仅比「带极值点的框标注」慢 2 倍。
- **控制**：质量由人驱动精修，无自动阈值。

#### Stage 2：半自动（Semi-Automatic）——飞轮的关键一跃

- **规模**：新增 180k 图像、5.9M masks（累计 10.2M）；期间模型重训 5 次。
- **机制**：用一个在**全部 Stage-1 masks 上训练的通用 "object" 类检测器**（box 输出）**自动预填高置信度对象的 mask**；标注者**只标模型尚未覆盖的剩余对象**。
- **设计意图（论文原意）**：提高 mask 多样性——如果不预填，人会反复标模型已会的显著对象；预填把人力逼到多样性前沿。
- **代价**：每 mask 耗时回升到 34 秒（排除自动 mask），因为剩下的都是难对象——这是「人专攻难例」的直接证据。
- **效果**：每图 masks 从 44 涨到 72（含自动）。

#### Stage 3：全自动（Fully Automatic）

- **规模**：应用于全部 11M 图像，产出 1.1B masks，**99.1% 的 SA-1B masks 是全自动的**。
- **两个前置条件**（论文明确指出）：① 数据多样性已足够（歧义场景见得多）；② **歧义感知模型**（ambiguity-aware）——每点输出 subpart/part/whole 3 个 mask。
- **机制**：32×32 规则点阵 prompt → 每点至多 3 mask → 用 **IoU 预测头选高置信 mask** + **稳定性检验**（概率图在 0.5−δ 与 0.5+δ 两个阈值下二值化结果相似才算稳定）→ NMS 去重 → 放大 crop 处理小对象。
- **训练过滤**：训练时丢弃面积 < 100×100 px 的 mask（前两阶段的 mask 也参与）。
- **质量验证（事后抽检）**：随机抽 500 图（约 50k masks）由专业标注员修正，自动 mask 与修正 mask 的 IoU **94% 对 > 90%、97% 对 > 75%**，超过人工标注者间一致性（85–91% IoU）；人工评分研究（1=nonsense ~ 10=pixel-perfect）SAM 均分 7–9。
- **消融**：只用全自动 mask 训练相比用全部三阶段数据仅损失 ~0.5 mIoU → SA-1B 最终只发全自动 mask。

#### 对我们的借鉴点

1. **三阶段的本质是「模型置信度覆盖率」的递进**：Stage 2 的预填=「模型会的自动出，人补不会的」，与我们要做的「训练好的 YOLO 回推数据集筛错」完全同构——只是我们筛的是**错误**而非**遗漏**。
2. **每轮重训是必须的**：SAM Stage 1 重训 6 次、Stage 2 重训 5 次；飞轮不转=模型不更新。
3. **质量用「事后抽检+修正对照」量化**：94%/>90% IoU 这种验收口径可直接借鉴为「修正前后 IoU 分布」指标。
4. **全自动阶段必须有置信度+稳定性双过滤**（IoU 头 + 阈值扰动稳定性），单一置信度阈值不够。
5. **30 秒跳过规则**：人工兜底也要有止损规则，防止预算耗在病态样本上。

### 2.2 SAM 2（2024）：视频版数据引擎 → SA-V

**论文**：<https://arxiv.org/abs/2408.00714>（HTML：<https://arxiv.org/html/2408.00714v1>；官方页：<https://ai.meta.com/research/sam2/>）

三阶段按「模型辅助程度」递进，量化数据（论文 Table 1）：

| 阶段 | 机制 | 耗时/帧 | 需编辑帧占比 | 每编辑帧点击数 | 产出 masklets |
|------|------|---------|-------------|---------------|--------------|
| 1 | 仅 SAM 逐帧 + brush/eraser，无时序传播 | 37.8 s | 100% | 4.80 | 16K（1.4K 视频） |
| 2 | SAM 2 Mask 接受 mask prompt 做时序传播，错误帧重标后再传播；模型重训 2 次 | 7.4 s（5.1×） | 23.25% | 3.61 | 63.5K |
| 3 | 完整 SAM 2（点+mask prompt），人只需 occasional refinement clicks；模型重训 5 次 | 4.5 s（8.4×） | 19.04% | 2.68 | 197.0K |

- **质量对齐**：Phase 3 与 Phase 1（纯人工）标注的 IoU>0.75 占比 89.1%（大对象 100%）——即模型辅助标注与纯人工一致性近 9 成。
- **自动 masklets**：首帧 32×32 点阵 + 4 个放大 crop 16×16 + 16 个放大 crop 4×4 prompt 生成候选，**全部经独立标注员池验收**（satisfactory/unsatisfactory 二元判定 + 是否有清晰边界），不合格者回流人工用 in-the-loop SAM 2 精修或直接拒绝。
- **评测保护**：SA-V val/test **刻意用最慢的 Phase 1 纯人工方式标注**，避免 SAM 2 自己评自己的偏置。
- **最终 SA-V**：50.9K 视频、642.6K masklets（190.9K 人工 + 451.7K 自动）、35.5M masks，为既往 VOS 数据集 53 倍。

**借鉴点**：① 「验收由独立池执行、评测集永不用模型辅助标注」是防坍缩的关键制度；② 视频场景中「点一次+时序传播+偶尔修」的人机分工使编辑帧占比降到 19%。

### 2.3 SAM 3（2025）：AI verifier 进环 → SA-Co

**论文**：<https://arxiv.org/html/2511.16719v2>；官方博客：<https://ai.meta.com/blog/segment-anything-model-3/>

数据引擎四阶段（Phase），核心变化是**用 Llama 3.2 微调出的 AI verifier 替代大部分人工验收**：

| Phase | 机制 | 增量数据 |
|-------|------|---------|
| 1 | 人工验收：captioner 提名名词短语(NP)，SAM 2 + 现成开词汇检测器提案 mask，人 verify | 4.3M 图像-NP 对 |
| 2 | **人+AI 验收**：Llama 3.2 用 Phase 1 的 accept/reject 标签微调成 Mask Verification (MV) 与 Exhaustivity Verification (EV) 两个 verifier；SAM 3 重训 6 次；LLM 流水线主动提名为难负样本的 NP | +122M 对 |
| 3 | 扩域：15 个数据集 + 基于 Wikidata 的 22.4M 节点本体挖长尾概念；SAM 3 迭代 7 次、AI verifier 3 次 | +19.5M 对 |
| 4 | 视频：场景/运动过滤器 + 定向挖掘，人集中在拥挤场景与跟踪失败处 | SA-Co/VIDEO 52.5K 视频、467K masklets |

- **反馈回路**（论文 §4）：SAM 3 + 人工标注者 + AI 标注者组成反馈环，**主动挖当前模型失败的媒体-短语对**送人工修正——即「模型失败点=下轮数据重点」。
- **验收效果**：AI verifiers 达到 near-human accuracy；消融显示 EV 有无差 +7.2 cgF1、MV 差 +1.1，合计关闭约一半与人工的差距。
- **吞吐**：AI verifier 使数据引擎吞吐 **约翻倍**（vs 纯人工流水线）。
- **规模**：高质量数据 4M 独特短语 / 52M masks；另加合成数据 38M 短语 / 1.4B masks。
- **歧义处理**：Gold 集每个样本 3 位专家标注 + oracle 评测协议。

**借鉴点**：① **用「人验收过的 accept/reject 历史微调一个 AI verifier」**——与我们「VLM 仲裁」完全同构，且给出了升级路径：把人工兜底的裁决记录拿去调 VLM/小判别器，逐步自动化验收；② **MV（这个 mask 对不对）+ EV（该标的都标了吗）两步验收**，EV（漏标检查）是检测数据集最常被忽略的维度；③ 难负样本由 LLM 主动提名。

### 2.4 SAM 系列数据引擎三年演进小结

| 维度 | SAM 1 (2023) | SAM 2 (2024) | SAM 3 (2025) |
|------|-------------|--------------|--------------|
| 标注物 | mask | 视频 masklet | 概念（NP）mask / 3D |
| 验收者 | 人工 | 人工（独立池） | AI verifier（Llama 微调）+ 少量人工 |
| 错误回流 | 隐式（下轮重训） | unsatisfactory → 人工精修 | 主动挖失败样本 |
| 防坍缩机制 | 阶段门控（模型不够强不开全自动） | val/test 纯人工标 | MV/EV 双验收 + 3 专家 Gold 集 |

## 3. 主动学习（Active Learning）

### 3.1 机制

经典框架见 Settles 综述（2009，引用近万）：<https://burrsettles.com/pub/settles.activelearning.pdf>。核心 query 策略：

- **Uncertainty sampling**：选模型最不确定的样本（least confident / entropy 最大 / margin 最小）。
- **Query-by-committee (QBC)**：多个模型投票，选**分歧最大**的样本——我们流水线的多检测器共识天然就是 committee。
- **Expected model change / expected error reduction**：选标注后最会改变模型参数（如梯度最大）的样本。
- **Diversity / representativeness（core-set）**：兼顾输入分布覆盖，避免选回一堆相似难例。

检测任务专用：Plug and Play Active Learning for Object Detection（<https://arxiv.org/html/2211.11612v2>）在 annotation budget 约束下选最 informative 样本；CVPR 2025 室内 3D 检测工作同样采用 uncertainty+diversity 组合（<https://cvpr.thecvf.com/virtual/2025/poster/34027>）。

### 3.2 阈值怎么定

- **没有普适阈值**，通行做法是「预算驱动」：按不确定度排序取 top-K 或按分位数（如 top 5%）截断，而非固定置信度阈值。Encord 实践指南（<https://encord.com/blog/active-learning-computer-vision-guide/>）建议设置 stopping criteria（不确定度分布收敛/收益递减即停）。
- Voxel51 实测（见 §4.5）给出反直觉证据：**置信度 0.8–0.9 的高阈值过滤会因损失 recall 使下游 mAP 最多降 8 个点，最优阈值落在 0.2–0.5** 且随模型/数据集变化——阈值必须在自己的数据上校准，不能抄默认值。
- 检测特有的不确定度来源：box 回归方差、分类熵、MC-Dropout 多次前向的方差、ensemble 方差（<https://www.inovex.de/de/blog/active-learning-for-object-detection-using-uncertainty-aggregation/>）。

### 3.3 借鉴点

- 我们的循环第一步「模型回推数据集」同时产出两类信号：**模型-标注分歧**（错标嫌疑，走修正）与**模型高不确定**（难例，走人工补标/加样本）——后者即 active learning 采样，前者是下一节的 label error detection。两者共用一次推理。
- 多检测器共识层升级：从「共识产出标签」扩展为「分歧度作为 QBC 信号驱动采样优先级」。

## 4. 自训练 / 半监督（Self-Training / Semi-Supervised）

### 4.1 Noisy Student（Google 2019，经典必读）

**论文**：<https://arxiv.org/abs/1911.04252>；代码：<https://github.com/google-research/noisystudent>

三步循环：teacher（EfficientNet，标注 ImageNet 训练）对无标注图生成伪标签 → **equal-or-larger** student 在「真标签+伪标签」上训练，且**只给 student 加噪声**（dropout / stochastic depth / RandAugment，teacher 不加）→ student 升任 teacher 重复。

关键工程细节（论文全文，ar5iv：<https://ar5iv.labs.arxiv.org/html/1911.04252>）：

- **候选池过滤只做一次**：用一个 ImageNet 监督训练的 EfficientNet-B0 跑 300M JFT 图像，**置信度 > 0.3 才入选**（低置信≈域外图）；入选后**每类至多取置信度最高的 130K 张，不足的随机复制补齐到 130K/类**（匹配 ImageNet 类分布）→ 得到 130M 训练图（81M 唯一）。
- **软伪标签**为默认（对域外数据更好），非 one-hot。
- 迭代成绩：87.6% → 88.1% → 88.4% top-1（unlabeled:labeled batch 比 14:1 → 28:1）。
- 鲁棒性大幅提升（ImageNet-A 61.0→83.7 等）。

### 4.2 FixMatch 与检测系半监督

- **FixMatch**（<https://arxiv.org/abs/2001.07685>）：弱增强图上预测的**最大概率 > τ=0.95** 才保留伪标签，然后对强增强图施加一致性训练。0.95 是分类领域的标志性阈值，但仅是其 CIFAR 设定。
- **Unbiased Teacher**（ICLR 2021，<https://openreview.net/forum?id=MJIve1zgR_>；代码 <https://github.com/facebookresearch/unbiased-teacher>）：把半监督搬到检测，指出伪标签的**类别不平衡偏置**与确认偏误；解法=EMA teacher（参数指数滑动平均的稳定 teacher 出伪标签）+ pseudo-labeling 采样 + focal loss 重加权。v2（CVPR 2022，<https://openaccess.thecvf.com/content/CVPR2022/papers/Liu_Unbiased_Teacher_v2_Semi-Supervised_Object_Detection_for_Anchor-Free_and_Anchor-Based_CVPR_2022_paper.pdf>）提出 Listen2Student：动态判断 teacher 预测何时可靠。
- 阈值再思考：Rethinking Confidence Scores and Thresholds in Pseudolabeling（<https://openreview.net/forum?id=w4c5bLkhsz>）主张优化/自适应阈值而非固定值。

### 4.3 自我强化的坍缩问题（confirmation bias）

- 奠基分析：Arazo et al., Pseudo-labeling and Confirmation Bias in Deep Semi-supervised Learning（<https://arxiv.org/abs/1908.02983>）——错误伪标签随训练轮次强化自身置信度；缓解=正则项、curriculum labeling、MixUp。
- Debiased Self-Training（NeurIPS 2022，<https://proceedings.neurips.cc/paper_files/paper/2022/file/d10d6b28d74c4f0fcab588feeb6fe7d6-Paper-Conference.pdf>）：**解耦伪标签的生成与使用 + 估计伪标签误差最坏情况**。
- 通用共识的防线：置信度/质量阈值、teacher-student 解耦、课程式渐进、强增强一致性、**保留真标签锚**（labeled 数据始终参与每个 batch）。

### 4.4 借鉴点

- 若做「无标注视频帧扩样」：teacher 出软伪标签 + 类平衡上限（Noisy Student 式 130K/类思路，防头部类滚雪球）+ EMA teacher。
- **我们的循环不是纯自训练**：修正后的标签要经人工/VLM 验收才入库（SAM 3 模式），而非直接把模型输出当监督——这是避开 confirmation bias 的根本差异。

## 5. 标注错误挖掘（Label Error Detection）

### 5.1 Confident Learning / Cleanlab

**理论**：Northcutt et al., Confident Learning: Estimating Uncertainty in Dataset Labels（JAIR 2021，<https://www.jair.org/index.php/jair/article/view/12125/26676>；arXiv <https://arxiv.org/abs/1911.00068>）——用模型预测概率 + 噪声标签统计 **unnormalized confident joint**（估计噪声标签×潜在真标签的联合分布），据此**剪枝**错标样本后重训。

**冲击性结论**：Pervasive Label Errors in Test Sets（<https://arxiv.org/abs/2103.14749>）——MNIST/CIFAR-10/ImageNet 等 10 个基准测试集平均 ~3.4% 错标，修正后模型排名会改变。

**object detection 官方教程**（<https://docs.cleanlab.ai/stable/tutorials/object_detection.html>；博客 <https://cleanlab.ai/blog/learn/object-detection/>）：

- 输入：`labels[i]`（类 + `[x1,y1,x2,y2]` 框）与 `predictions[i][k]` 为 `(M,5)`（框+该类置信度）。
- **关键前提：预测必须是 out-of-sample**——用 **K 折交叉验证**（K-fold CV）训练/推理，避免模型见过自己的训练标签导致假性一致。这是整套方法成立的核心（Cleanlab 文档与 MIT Data-Centric AI 课程 <https://dcai.csail.mit.edu/2024/label-errors/> 反复强调）。
- `get_label_quality_scores` 输出每图 [0,1] 质量分（任一框或类错即拉低），`find_label_issues(..., return_indices_ranked_by_score=True)` 按分排序；`issues_from_scores(scores, threshold=0.5)` 默认阈值 0.5，**调低阈值=更少但更有把握的 issue 列表**。
- 漏检（忘了标框）也算 label error——覆盖 FP 与 FN 两个方向。

### 5.2 Dataset Cartography（训练动力学）

**论文**：Swayamdipta et al., EMNLP 2020（<https://aclanthology.org/2020.emnlp-main.746.pdf>；arXiv <https://arxiv.org/abs/2009.10795>；代码 <https://github.com/allenai/cartography>）。

- 训练时记录每样本对真标签的**置信度均值、变异性（std）、正确率**三个量，映射成 data map，分出 easy-to-learn / ambiguous / hard-to-learn 三区；**hard-to-learn（低置信+低变异）与错标高度重合**，可半自动筛出。
- 成本优势：只需训练时顺手记录，无需额外推理。
- 注意反例研究：When is dataset cartography ineffective?（<https://arxiv.org/html/2503.18290v1>，2025）显示其子集选择不总带来泛化收益——只当辅助信号，不当唯一裁决。

### 5.3 干跑对照与难例挖掘（视频/监控特化）

- **Model-vs-label disagreement**：训练好的检测器回推全数据集，高置信检测却无对应标注（漏标嫌疑）、有标注却持续检不出（错标或真难例）、IoU/类别持续不匹配（定位/类错）——这就是「干跑对照」，Cleanlab OD 教程是其工程化版本。
- **视频难例挖掘**：Jin et al., Unsupervised Hard Example Mining from Videos for Object Detection（<https://arxiv.org/abs/1808.04285>，PDF <https://jianghz.me/files/hard_ex.pdf>）——在监控视频上跑已训检测器，**把 FP 自动收集为难负样本**回炉重训，FP 稀疏且昂贵的问题由此解决。与我们的固定机位场景直接对口。
- **时序一致性信号**（固定机位监控独有）：同一 track 内检测闪烁（单人帧出现又消失）、轨迹突变、跨帧 box 尺寸跳变——均可作为错标/误检信号。Google 的静态相机时序上下文检测（<https://research.google/blog/leveraging-temporal-context-for-object-detection/>）验证了静态机位时序聚合的有效性。

### 5.4 借鉴点

- 主筛错通道：**K 折交叉验证式干跑**（把已标数据集切 K 份，每份由未见它的模型推理）→ Cleanlab OD 打分排序 → top-N 进 VLM 仲裁 → 人工兜底。若 K 折训练成本高，可用「当前模型 + 其他独立检测器」近似的 out-of-sample（我们有多检测器，天然满足）。
- 辅助信号：训练时记录 per-sample loss/置信轨迹（cartography），零额外推理成本。
- 监控特有：track 级时序一致性检验（帧级闪烁率）作为第三信号。

## 7. 数据飞轮综合设计：映射到我们的流水线

综合来源：SAM 1/2/3 数据引擎（§2）、Tesla 数据引擎（影子模式+trigger 挖掘+离线自动标注：<https://www.taivo.ai/tesla-data-engine/>、综述 <https://arxiv.org/html/2401.12888v1>、知乎智驾数据飞轮综述 <https://zhuanlan.zhihu.com/p/2044345237460583055>、六步闭环工程文 <https://www.kuizhuokj.com/?m=home&c=View&a=index&aid=7143>）、NVIDIA 数据飞轮定义（<https://www.nvidia.cn/glossary/data-flywheel/>）。

### 7.1 循环总体（信号源 → 筛选 → 修正 → 重训 → 防坍缩）

```
            ┌──────────────────────────────────────────────────────┐
            │                    现有已标数据集                      │
            └──────┬───────────────────────────────────────────────┘
                   │ ①干跑：训练好的 YOLO + 备用检测器回推全数据集
                   ▼
   ②信号融合打分（image-level 错标嫌疑分 + 难例分）
   ├─ 信号A 模型-标注分歧（高置信检测无标注 / 标注检不出 / IoU·类别不匹配）
   ├─ 信号B 多检测器分歧（既有共识层的 QBC 信号，现成复用）
   ├─ 信号C 训练动力学（per-sample loss 轨迹 / cartography 三量）
   ├─ 信号D 时序一致性（固定机位 track 闪烁率 / 轨迹突变）   [监控特有]
   └─ 信号E embedding 近邻类偏差（Encord Active 式）        [可选]
                   │ ③分层路由（预算驱动 top-K，非固定阈值）
                   ▼
   ┌─ 高置信自动路径：模型一致 + VLM 仲裁通过 → 直接修标（记 provenance=auto）
   ├─ VLM 仲裁路径：分歧样本 → VLM 判（沿用既有仲裁层）
   └─ 人工兜底路径：VLM abstain/高难样本 → 人修（记 provenance=human）
                   │ ④修正入库（原标归档不删，双写）
                   ▼
   ⑤重训触发（累计修正量 + 定期兜底 → 重训 YOLO）
                   │ ⑥门控：冻结金标评测集 champion-challenger 对比
                   ▼
   新模型上线 → 回到 ①（模型更强→预填/筛错更准→人更省）= 飞轮加速
```

### 7.2 信号源设计（对照调研依据）

| 信号 | 具体判据（草案，需在自己数据上校准） | 依据 |
|------|-------------------------------------|------|
| A 模型-标注分歧 | 单类 person：(a) conf≥τ 的检测无 IoU≥0.5 匹配标注 → 漏标嫌疑；(b) 标注连续 N 轮被低 conf 漏检 → 错标或真难例；(c) 匹配但 IoU 中位数低 → 定位错误 | Cleanlab OD（§5.1）；SAM Stage 3 的 IoU 头+稳定性双检（§2.1） |
| B 多检测器分歧 | 既有共识标注层的同意率/分歧度直接复用为采样优先级 | QBC（Settles §3.1） |
| C 训练动力学 | 训练时记录 per-image loss 与 conf 轨迹；低置信+低变异（hard-to-learn）→ 错标嫌疑 | Dataset cartography（§5.2） |
| D 时序一致性 | 同 track 内 person 检测仅单帧出现又消失（闪烁）→ FP/错标；track 尺寸/位置突变 → 校验 | Jin et al. 视频难例挖掘（§5.3）；Google 静态相机时序上下文 |
| E 近邻偏差 | 标签类别与其 embedding kNN 多数类不一致 | Encord Active annotation quality（§6） |

**out-of-sample 原则**（Cleanlab 核心）：干跑尽量用「没见过该份数据的模型」。实操上我们可用 (i) K 折重训（最严谨、成本高）或 (ii) 交叉用其他检测器/旧版模型近似（我们多检测器天然可用），或 (iii) 训练时的 held-out fold 预测。至少避免用「在同数据上收敛的模型」给同数据打分而不做修正。

### 7.3 修正与验收（SAM 3 模式）

1. **两步验收**：MV（这个标对不对）+ EV（该标的都标了吗）——检测数据尤其要查 EV 漏标（Cleanlab 明确把漏框算 label error）。
2. **VLM 仲裁升级路径**：把人工兜底的 accept/reject/修正记录积累下来，微调/沉淀为更固定的 AI verifier（SAM 3 用 Llama 3.2 微调，我们可用规则+轻量分类器或 VLM few-shot 固化），吞吐可期翻倍（SAM 3 实测 AI verifier 使吞吐约 2×）。
3. **provenance 标记**：每条标签记 human / vlm-verified / auto 三档（SAM 2/3 均严格区分人工/自动来源），后续可按来源分桶评估质量。
4. **双写不删**：原标注归档保留，修正另存版本——回滚与审计基础（也符合我们既有存档习惯）。
5. **人工止损规则**：单样本/单批审核超时即升级或搁置（SAM Stage 1 的 30 秒跳过规则）。

### 7.4 重训触发（何时再转一圈）

综合 MLOps 实践（Evidently AI <https://www.evidentlyai.com/ml-in-production/data-drift>、Aerospike <https://aerospike.com/blog/model-drift-machine-learning/>、Microsoft <https://techcommunity.microsoft.com/blog/fasttrackforazureblog/identifying-drift-in-ml-models-best-practices-for-generating-consistent-reliable/4040531>）与 LLM 飞轮工程文（<https://matt33.com/2026/07/11/llm-data-flywheel/>、<https://tianpan.co/zh/blog/2025/09/28/data-flywheels-llm-applications>）：

- **触发条件（满足其一）**：① 累计修正/新增样本量达到阈值（如数据集的 5% 或绝对 N 条）；② 干跑分歧率显著上升（数据/概念漂移早期信号，需持续多窗口确认而非单点）；③ 定期兜底（如每月一次，防止触发条件永不满足）。
- **门控（升级前必过）**：冻结金标评测集上 champion-challenger 对比，新模型不低于旧模型才替换——**评测集永不被飞轮自动修改**（SAM 2 的 val/test 纯人工标注制度）。
- **评测集隔离**：金标集抽样要按场景/时间分层，且不得进入训练（matt33 强调评测集按用户/时间隔离与近重复检测）。

### 7.5 防坍缩清单（self-training collapse 防线）

| 风险 | 防线 | 依据 |
|------|------|------|
| 错误标注被模型确认后自我强化（confirmation bias） | 修正必须过 VLM/人工验收才入训练集；纯 auto 标签只用于预填/参考不直接当监督 | Arazo 2019（§4.3）；SAM 全系设计 |
| 评测被污染（自评自） | 金标评测集冻结 + 独立标注 + 不参与训练 | SAM 2 val/test 制度；Cleanlab out-of-sample 原则 |
| 单模型偏置闭环 | 保留多检测器 ensemble 多样性（独立架构/数据来源）；交叉干跑 | Unbiased Teacher EMA/解耦思想（§4.2） |
| 头部类样本滚雪球 | 每类新增/修正样本设上限或均衡采样 | Noisy Student 每类 130K 上限（§4.1） |
| 阈值照抄失配 | 置信度阈值在自己的数据上校准（注意高阈值伤 recall 的反例），预算驱动 top-K 优于固定阈值 | Voxel51 阈值实验（§6）；Encord stopping criteria |
| 噪声累积不可见 | 持续监控：修正前后 IoU 分布、各 provenance 桶质量、类分布漂移、干跑分歧率趋势 | SAM 94%/>90% IoU 验收口径；Aerospike/Microsoft 监控建议 |
| 增益递减不自知 | 每圈记录「修正样本数 → mAP 增益」曲线，增益 < ε 即降频/停轮 | Active learning stopping criteria（Encord 指南） |

### 7.6 与现有流水线的具体衔接（草案）

1. **复用共识层作 committee**：det_mine 多检测器结果既出标签也出分歧分——分歧分是循环信号 B，无新增成本。
2. **干跑工具**：ONNX 化的 YOLO（已导出）批量回推既有训练集+审核集，输出预测-标注匹配报告（IoU 矩阵、漏检清单、多余检测清单）。
3. **VLM 仲裁层复用**：仲裁输入从「检测器间分歧框」扩展到「模型-标注分歧框」，提示词与坐标刻度对照（qwen 0-1000 / M3 像素 / doubao 0-1）沿用既有机制。
4. **人工兜底复用**：审核界面预填「原标注 vs 模型检测 vs VLM 意见」三方对照，人只裁决（Label Studio/CVAT 的 pre-annotation 模式即此形态）。
5. **首圈建议**：先在已人工审绿的样本上做干跑对照（信号 A），验证「模型在绿灯样本上的分歧率」作为基线——分歧显著高于基线的样本即错标嫌疑 top-K；这一步不动生产数据，风险最低。
