# sgcc 去重、训练路径与经验教训存档（2026-07-09）

> 本会话主线：审查 sgcc 去重状态 → 前景感知去重 → 本机 person.pt 微调失败（lr 破坏）→ 转 sgcc0 从头训 → yolo_train 工具完善。附经验教训。

## 1. 本次工作

### 1.1 sgcc 前景感知去重（20124 → 18384，-8.6%）

**背景**：审查发现当前 sgcc（20124 图）**未经任何去重**——旧 2026-06-25 SemDeDup pipeline 针对的是更早的 14284 旧 samples 池，产物（samples_dedup 13299）从未进训练；当前 sgcc 是实体复制 + video-extract 合并重构，完全绕过去重。video-extract 视频抽帧 + 监控同人多次 → 近重复 + train/val 泄漏风险。

**复用** 2026-06-25 前景感知 pipeline（背景同质，整图去重失效，改 person crop）：
1. `person_crop`：YOLO bbox 截前景 crop（忽略同质背景），20124 图 → 55991 crop
2. `person_embed`：DINOv2-small 384d SSL embedding（GPU ~1.5min）
3. `person_dedup`：SemDeDup（Faiss cos≥0.95 + 并查集）→ 55991 → 45151 近重复代表
4. `samples_dedup`：整图姿态簇指纹（frozenset）去重，相同姿态组合留 1

**结果**：20124 → 18384（-8.6%）。video-extract 5840→5146（-11.9% 静止段冗余），监控 top_ 7904→7217（-8.7% 同人多次），1_/2_ 4189→3937。533 负样本保留。阈值 0.95 保守（部分视频去重 0，证明无误删）。

**工具修复**（commit 05e004b）：
- `person_crop`：极小 bbox 经 jvi roi round 后尺寸为 0 → cv2.imwrite crash → 加空 crop 防护（skip 32 远景小人）
- `samples_dedup`：无 person crop 图（533 负样本空标 + 15 退化 bbox）被误丢 → 改为原样保留（负样本对训练假阳抑制重要）

### 1.2 本机 person.pt 微调失败（负优化，已废弃）

**配置**：person.pt + lr0=0.01（默认）+ patience 50 + epochs 200

**结果**：EarlyStopping 停在 ep51，best 卡 ep1 mAP50-95=0.689（**低于 person.pt 原本 0.720**，负优化）。

**根因**：lr0=0.01 微调已收敛的 person.pt → ep1 warmup（小 lr）后全 lr 大幅更新**破坏已学特征**（catastrophic forgetting），mAP 跌到 0.614；ep6 起 lr 衰减后回升，但 patience 从 ep1(0.689) 计数，50 轮内未超越 → 过早早停在低点。

**输出位置跑偏**：ultralytics `project="runs/detect"` 相对路径被拼到 SETTINGS runs_dir，save_dir 误存 `/home/jiang/py/js4/...`（非预期）。

### 1.3 转 sgcc0 从头训（yolo26n.pt COCO 预训练）

**配置**：yolo26n.pt（COCO 80 类预训练）+ sgcc-only（18384）+ 默认 lr0=0.01 + patience 30

**rsync**：9.3G 数据 → sgcc0（内网 12 MB/s，13min；非存档的 VPN 0.4MB/s）

**趋势**（截至发文 ep30）：best ep29 mAP50-95=0.862（**超 person.pt 0.720 达 +0.142**），mAP50=0.977，持续上升（无进步 0/30）。从头训 + 默认 lr0 路径正确，无微调破坏问题。

补 `--lr0/--lrf/--freeze/--optimizer/--cos-lr/--close-mosaic` 透传 ultralytics；`project` 自动 `Path.resolve()` 绝对化，根治 save_dir 跑偏。已同步 sgcc0。

## 2. 经验教训

### L1: 微调已收敛模型必须降 lr0（核心教训）
- person.pt（已 person 域收敛）+ 默认 lr0=0.01 → 破坏特征（实测 ep1 后 mAP 跌 0.07）
- **解法**：微调用 lr0=0.001（10× 小）+ freeze=10（冻结 backbone，只调 neck+head）
- COCO 预训练（yolo26n.pt）+ lr0=0.01 安全（首次域迁移，标准迁移学习，person.pt 当年就这样训成 0.956）
- **判断规则**：初始权重越"靠近目标域/越收敛"，lr0 越要小。person.pt 微调 ≠ yolo26n.pt 微调。
- 持续迭代推荐：每次新数据从上个 best.pt + lr0=0.001 + freeze=10 微调

### L2: pkill -f 会匹配当前 shell 自杀
- `pkill -f "jxl.bin.yolo_train"` 杀了执行该命令的 shell 自身（命令行含该字符串）→ exit 144，命令链中断
- **解法**：`kill <pid>`（记录 PID，用 pid 杀）或 `pkill -f "[y]olo_train"`（方括号字符类防自匹配）

### L3: ultralytics project 相对路径跑偏
- `project="runs/detect"`（相对）→ ultralytics 拼到 SETTINGS 的 runs_dir，save_dir 跑偏到无关目录
- **解法**：project 绝对化 `Path(project).resolve()`（已修入 yolo_train.py）

### L4: 去重工具不能丢负样本
- samples_dedup 把"无 person crop"图一律 drop，但负样本（无人图/空标）对训练假阳抑制重要
- **解法**：前景去重只作用于正样本；无前景图（负样本 + 退化标注）原样保留

### L5: CLI 薄封装要完整透参
- yolo_train.py 原本只透传 epochs/imgsz/batch/patience，漏 lr0/freeze → 微调想降 lr 却无参数可传（间接导致 L1 失败无法现场纠正）
- **解法**：封装要么完整透传关键超参，要么直接用 `.venv/bin/yolo detect train ... key=value`（参数全）。薄壳价值有限，要么做厚要么不封

### L6: "从头训"措辞——yolo26n.pt 是 COCO 预训练
- yolo26n.pt = COCO 80 类预训练权重（ultralytics 官方），**非随机初始化**
- 用 yolo26n.pt = 基于 COCO 预训练的迁移学习（标准）；真正 from scratch 是 yolo26n.yaml（架构，随机初始化，极少用）

### L7: 远程训练数据传输
- sgcc0 内网实测 12 MB/s（2026-06-27 存档记的 VPN <0.4MB/s 是旧环境），9.3G 仅 13min
- setsid 脱离 session（防 ssh 断终止训练，比 nohup 更彻底）
- jxl 环境 sgcc0 已就绪（~/py/jxl + .venv + uv + yolo26n.pt）

### L8: 训练前必查数据去重/泄漏状态
- 当前 sgcc 是重构的（实体复制 + video-extract 合并），完全绕过旧去重 pipeline
- 旧去重产物（samples_dedup/reid）针对更早 14284 池，未进训练
- **教训**：训练前审查数据去重/泄漏状态，不假设"之前做过去重"——去重可能针对别的池、产物可能未使用

### L9: 监控预警要听
- ep1 best 后 mAP 下降时已预警"patience 从 ep1 计数可能过早早停"，结果应验（ep51 早停 0.689）
- **教训**：训练初期异常（best 卡 ep1 + 后续下降）是 lr 过高信号，应及早重启降 lr，不要赌自然恢复
