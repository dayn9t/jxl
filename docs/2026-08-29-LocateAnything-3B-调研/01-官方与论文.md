## 1. 一句话定位与发布时间线

**定位**：LocateAnything 是 NVIDIA（联合高校）发布的统一生成式 grounding / detection 视觉-语言模型（3B），核心创新为 **Parallel Box Decoding（PBD，并行框解码）**——把一个 bounding box 或 point 当作"原子单元"在单步并行解码中输出完整坐标，取代传统 VLM 逐 token 串行吐坐标的方式，同时提升定位精度与解码吞吐（[官方页](https://research.nvidia.com/labs/lpr/locate-anything/)、[arXiv:2605.27365](https://arxiv.org/abs/2605.27365)）。

## 3. 任务定义全集（8 类任务与输入输出格式）

论文 Table 9 给出统一 prompt 模板（输入 = 图像 + 自然语言指令，坐标输出为归一化到 **[0,1000]** 的整数）：

| 任务 | 输出 | 指令模板（原文） |
|---|---|---|
| Object Detection | Box | "Locate all the instances that matches the following description: [CATEGORIES]." |
| Single Box | 单 Box | "Locate a single instance that matches the following description: [PHRASE]." |
| Phrase Grounding | 多 Box | 同 "Locate all the instances..." 模式，[PHRASE] 为自由描述 |
| Text Grounding（OCR 文字定位） | Box | "Please locate the text referred as [PHRASE]." |
| Scene Text Detection | Box | "Detect all the text in box format." |
| Document Layout Analysis | Box | "Detect all the objects in the image that belong to the category set: [CATEGORIES]."（另有 region-location 模板） |
| GUI Grounding | Point（或 Box） | "Point to: [PHRASE]." |
| Pointing（点定位） | Point | "Point to: [PHRASE]." |

（来源：[arXiv HTML v2](https://arxiv.org/html/2605.27365v2) Table 9）

**输出格式**（repo README）：
- Box：`<ref>label</ref><box><x1><y1><x2><y2></box>`，坐标为 [0,1000] 整数；
- Point：`<box><x><y></box>`；
- 无目标：`<box>none</box>`。

**Python Worker API**（`locateanything_worker.py`）：`worker.detect(img, ["person","car","bicycle"])`、`worker.ground_multi(img, "people wearing red shirts")`、`worker.detect_text(img)`、`worker.ground_gui(img, "the search button", output_type="point")`、`worker.point(img, "the traffic light")`。

**官方 HF 模型卡任务列表**：开放集/通用与密集多目标检测、phrase/referring expression grounding（单实例与多实例）、text grounding 与场景文字检测、文档版面分析、GUI 元素 grounding（box 或 point）、pointing。

**边界（官方明确声明）**：当前发布的 `nvidia/LocateAnything-3B` 权重**不支持 visual prompt（图像提示）推理**，visual-prompt-capable 权重"将在未来版本发布"；官方同时放出了 LoRA visual-prompt 微调脚本（默认 `USE_LLM_LORA=64`）供用户自行微调（Embodied README）。

## 4. 架构细节

### 4.1 底座 VLM

三件套（官方页 + 论文 + HF 模型卡一致）：

- **Vision encoder：Moon-ViT（MoonViT）**——native-resolution ViT，"extracts visual tokens at native resolution"。HF 模型卡给出具体组件：**MoonViT-SO-400M（MIT License）**。MoonViT 源自 Moonshot AI 的 Kimi-VL 技术报告（[arXiv:2504.07491](https://arxiv.org/html/2504.07491v1)），NaViT 式 Patch-n'-Pack 设计，任意分辨率不 resize/不 padding。单一来源注：MoonViT-SO-400M 的具体规格（参数量）仅见于 HF 模型卡，论文正文未详述。
- **LLM decoder：Qwen2.5-3B-Instruct**（HF 模型卡：第三方组件遵循 Qwen Research License）。
- **MLP projector** 桥接两者。

**参数量口径差异（如实记录）**：对外名义 **3B**（模型名 LocateAnything-3B）；HF 模型卡提取时 Safetensors 元数据列 "4B total, BF16"（含全部权重的大口径）。两个数字原样并存，官方未解释口径差。

### 4.2 Parallel Box Decoding（PBD）原理

（来源：[arXiv HTML v2](https://arxiv.org/html/2605.27365v2) Method 节 + [官方页](https://research.nvidia.com/labs/lpr/locate-anything/)）

- **动机**：传统 VLM grounding 把 2D 框序列化成 1D token 流逐个解码（NTP），"mismatches the coupled structure of box geometry" 且成为推理瓶颈。
- **做法**：每个 box/point 是一个"atomic unit"，坐标量化到 [0,1000]，打包成**定长 block（L=6）**：一个 box 的 4 个坐标 token + 2 个结构 token（如 `<box>`/`</box>`），不足处用 `<null>` padding；在**单次并行步（single forward pass）**内预测整块。
- **四种 block 类型**：Semantic（语言身份）、Box（4 个量化坐标）、Negative（目标不存在）、End（终止）。
- **联合分解**：P(B|Z,E) = ∏ P(b_i | b_<i, Z, E)。
- **与既有 MTP 的区别**：先验 multi-token prediction 是 "structure-agnostic"（随机切块/masked span），会产生跨框的伪模式；PBD 让每个 MTP block 对齐一个几何单元。
- **双流联合训练（dual-formulation）**：拼接序列 x_all = x_vis ⊕ x_q ⊕ x_ntp ⊕ x_blk；MTP 流保留每 block 一个 anchor token、其余以 [mask] 遮蔽；损失 L = L_ntp + L_mtp。注意力设计：共享上下文 + NTP 流为因果；block 间 block-causal；**block 内 bidirectional**；两流隔离防泄漏。
- **box 排序**：论文比较了四种空间排序策略，**X-Y Corner Order 最优**（消融）。
- **KV cache 管理**：每个 MTP 步后截断 KV cache 至已提交 token，驱逐 mask token 与重复 anchor。

### 4.3 三种推理模式与回退机制（Hybrid Inference）

- **Fast Mode（MTP）**：默认快速路径。
- **Slow Mode（NTP）**：逐 token 自回归，精度上限最高、速度最慢。
- **Hybrid Mode（默认）**：Fast 优先，检测到两类失败信号时回退 NTP——**Format Irregularity**（结构/坐标 token 混排的语法错误）与 **Spatial Ambiguity**（密集网格中中间坐标歧义）。
- **触发条件（原文数字）**：同时满足 "(1) the top-1 coordinate token's probability is below **0.7**，且 (2) top-5 coordinate token 概率对应的坐标 max-min 差超过 **80**"（[0,1000] 量化空间内）。
- **Corrected NTP Re-decoding**：丢弃问题 block → 回退到最后一个已验证前缀 → 用 NTP 仅重生成该 block → 切回 MTP。

### 4.4 推理配置

论文：temperature **0.7**、top-p **0.9**、repetition penalty **1.1**、block size n_future=**6**、最多 **8,192** new tokens、BF16、batch size 1（评测口径）。HF 模型卡：输入 RGB 图像最高 **2.5K 分辨率**、prompt 最长 **24K tokens**、生成最长 **8,192 tokens**；推荐 `generation_mode="hybrid"`、`max_new_tokens=8192`。加速 runtime：`--attn la_flash`（FlashAttention varlen 稀疏后端，任意 GPU 可用）；Hopper/Blackwell 可选 **MagiAttention**（v1.0.5）；无 MagiAttention 时 MTP 回退 PyTorch SDPA。

## 5. 训练数据（LocateAnything-Data）

### 5.1 总量（官方多来源一致）

- **12M unique images / 138M natural language queries / 785M annotated bounding boxes**（官方页、repo README、HF 模型卡、论文正文四处一致）。
- 论文附录口径补充："over **139M** queries with more than **22M negative samples**"（与正文 138M 并存，为含负样本的大口径）。
- HF 模型卡另写 "~140M natural-language queries"。数据集总体积 **2.41 TB**（数据集卡）。
- 域覆盖（HF 模型卡原文）："spanning **natural scenes, robotics, driving, GUI interaction, and documents**"。

### 5.2 任务配比（论文）

按 query 占比：**General OD 66.9%**（占 boxes **83.1%**）、**GUI grounding 16.5%**、**Referring 7.3%**、**OCR 3.6%**、**Layout 3.5%**、**Pointing 2.2%**。

论文 Table 10 精确查询数（queries / 其中负样本）：

| 任务 | Queries | 负样本 |
|---|---|---|
| Detection | 93,351,373 | 21,021,509 |
| GUI | 23,009,535 | 0 |
| Referring | 10,141,597 | 93,396 |
| OCR | 5,052,040 | 0 |
| Layout | 4,859,914 | 1,384,804 |
| Pointing | 3,148,098 | 353,366 |

### 5.3 源数据集（官方数据集卡按域列出）

- **通用检测/grounding**：COCO、RefCOCO/RefCOCO+/RefCOCOg/G-RefCOCO、Flickr30K、HumanRef-CoT、Objects365、Open Images V6、OWDOD、PACO、PartImageNet、Unsplash、V3Det
- **密集检测**：CrowdHuman、DeepFashion2、HumanParts、MOT17Det、MOT20Det、SKU-110K
- **Driving & robotics**：**BDD100K、EgoObjects、nuImages、PixMo Points、RoboAfford**（这证实了"自动驾驶/机器人域"的说法，官方页与论文正文未逐一点名这些数据集，域级来源为数据集卡）
- **GUI**：GroundCUA、OS-Atlas、ScaleCUA
- **Text/OCR**：ArT、BLIP3-OCR、IDL-OCR、HierText、ICDAR 2013/2015、LSVT、RCTW、ReCTS、SROIE、TextOCR、WildReceipt
- **文档/表格**：CDLA、DocLayNet、M6Doc、PubLayNet、TableBank、TabRecSet

论文还提及 SA-1B 参与数据引擎、GroundCUA 用 Qwen3-VL 按外观/空间/功能三类描述重标注。

### 5.4 数据引擎（论文）

Qwen3-VL 生成查询 → **Molmo** 预测点 → 有 GT 框时保留框内点作标注、无标注时由 **SAM 3** 点转框，或 **Rex-Omni** 直接预测框 → **Qwen3-VL 后验证**。混合人工/开源标注 + 模型辅助合成标注（HF 模型卡）。查询以"短英文任务型查询"为主（HF 模型卡 limitation）。

### 5.5 数据许可

数据集卡原文："**Each source dataset remains governed by its original license**"、"This repository does not grant additional rights to upstream media"。7 个数据集（CrowdHuman、DeepFashion2、Flickr30K、PartImageNet、Objects365、SKU-110K、Unsplash）需从上游自行取图；Unsplash 不支持官方 hydration。用途声明："prepared for academic research"。

## 6. 训练策略（论文 Table 7，四阶段）

| 阶段 | 数据 | LR | 可训练部分 | GPU | Steps | Seq len |
|---|---|---|---|---|---|---|
| 1. World Knowledge Injection | captions | 2×10⁻⁴ | 仅 MLP | 64 | 2,000 | 32,768 |
| 2. General VQA | — | 4×10⁻⁵ | 全部 | 256 | 20,000 | 32,768 |
| 3. Detection & Grounding | 138M queries | 4×10⁻⁵ | — | — | 25,000 | 25,600 |
| 4. Dense enhancement（"20% Previous + Dense"，如 MOT20Det、SKU110K） | — | 1×10⁻⁵ | — | — | 5,000 | 25,600 |

全部阶段：AdamW、weight decay **0.01**、cosine schedule。基础设施：**Stream Packing**（约 **36,864**-token 预算、**>95%** packing 效率）+ **MagiAttention** 处理异构掩码。训练脚本 `eaglevl/train/locany_finetune_magi_stream.py`（flag 如 `--block_size 6 --max_seq_length 16384`）；文档 `TRAINING.md`、`DATA_PREPARATION.md`、`RESULTS.md`。消融模型仅在 COCO 上训练（用于对照）。

## 7. 推理速度与精度（数字原样引用）

### 7.1 吞吐（单张 H100、batch 1，BPS = boxes/sec）

- **Hybrid 默认：12.7 BPS**——官方表述 "over **10× faster** than textual-based Qwen3-VL (**1.1 BPS**) and **2.5× faster** than quantized-based Rex-Omni (**5.0 BPS**)"（论文 Table 1 / 官方页 / README 三处一致）。
- 三模式分解（论文 Table 12，全量模型）：**Fast 15.3 BPS / Hybrid 12.7 / Slow 4.3**。
- 注意口径：官方页与消融表中 "Fast 16.9 BPS" 指**仅 COCO 训练的消融模型**（Table 6：PBD Fast 16.9 BPS / F1 49.6；Hybrid 13.2 BPS / 51.6；Slow 3.9 / 52.1），与全量模型的 15.3/12.7/4.3 不是同一模型，两套数字原样记录。
- 密集场景（20→300 框）：吞吐 "from **12 BPS to ~25 BPS**"，即 "**2× to 6×**" 加速。
- 竞品 BPS（Table 1）：Qwen3-VL-4B **1.1**、Qwen3-VL-8B **1.0**、MiMo-VL-7B **1.0**、Cosmos-Reason2-8B **1.0**、OVIS2.5-2B **1.3**、Rex-Omni-3B **5.0**。
- 效率探针（HF 模型卡，A100、4K 图、batch 4）：sdpa **8.26s / 35.12 GB** vs la_flash **8.03s / 11.71 GB** peak reserved memory。

### 7.2 主结果（F1，Hybrid 模式）

- **LVIS**：62.3 / 31.1 / 50.7（@0.5/@0.95/mean）vs Rex-Omni-3B 64.3 / 20.7 / 46.9 → mean F1 **+3.8**，@0.95 "**31.1 vs 20.7**"。COCO：70.1 / 19.3 / **54.7** vs 52.9（**+1.8**）。Grounding DINO-Swin-T LVIS 38.8 mean；SEED1.5-VL LVIS 46.7 / COCO 51.4。
- **密集检测**：Dense200 **58.7** vs Rex-Omni 58.3 / SEED1.5-VL 53.2；VisDrone **39.9** vs 35.8 / 27.4。
- **GUI：ScreenSpot-Pro 平均 Acc 60.3**（Dev T/I 70.8/50.3、Creative 60.1/46.9、CAD 57.9/40.6、Sci 69.4/58.2、Office 77.2/69.8、OS 65.4/43.8）vs GUI-Owl-32B 58.0、MAI-UI-2B 57.4、Qwen3-VL-30B-A3B* 53.7、GTA1-7B 50.1。
- **文档**：DocLayNet **76.8**（Rex-Omni 70.7，即 +6.1；DocLayout-YOLO 81.1 仍更高）、M6Doc **70.1**（+14.5）、TotalText **43.3**（PaddleOCRv5 25.7）。
- **Referring**：HumanRef **78.7**（Rex-Omni 79.9、SEED1.5-VL 81.6 更高）、RefCOCOg val/test **76.7 / 77.6**（Rex-Omni 73.6/74.3）。
- **Pointing（F1@Point）**：COCO **83.9**、LVIS **76.6**、Dense200 **87.6**、VisDrone **60.4**、HumanRef **84.7**、RefCOCOg val/test **91.3 / 91.0**（Rex-Omni-3B 对应 80.5/70.8/82.5/58.9/83.8/84.7/85.1）。
- **模式分解**（Table 12，Fast/Hybrid/Slow）：COCO 52.2/54.7/55.1；LVIS 47.0/50.7/52.6；Dense200 46.8/61.3/61.5；DocLayNet 67.2/77.7/80.4；HumanRef 66.8/78.5/79.1；ScreenSpot-Pro 59.7/60.3/60.5。

### 7.3 关键消融（COCO）

- 表示法（Table 6a）：Textual **1.3 BPS / F1 49.1**；Quantized 3.9 / 50.1；**PBD Slow 3.9 / 52.1**；Fast **16.9 / 49.6**；Hybrid 13.2 / 51.6。
- MTP 方案对比（Table 6b）：SDLM-B4 5.2/46.5、SDLM-B6 5.5/46.1、SDLM-B8 6.7/45.8、Block Diff-B6 4.7/44.8、**PBD Fast 16.9/49.6**。
- 双流联合训练（Table 6c）：仅 L_ntp 时 Slow 50.1；联合后 Slow **52.1**、Fast 49.6（16.9 BPS）、Hybrid 51.6（13.2 BPS）——官方页表述 "lifts Slow Mode upper bound from 50.1 to 52.1 F1"。
- 骨架泛化（Table 13，换 Qwen3-VL-4B 底座，COCO）：NTP 50.8 F1 / 2.8 BPS；PBD Slow 52.2 / 2.8；Fast 49.6 / 11.4；Hybrid 52.0 / 9.4（证明 PBD 与底座解耦可迁移）。

## 8. 模型变体、部署与生态

- **目前仅发布 3B 一个变体**（`nvidia/LocateAnything-3B`）；HF 模型卡与 repo 均未提及官方 distill/更小版本。社区侧（HF 统计，非官方承诺）：12 个 finetune、22 个量化衍生；知乎/IT 之家称 16GB 消费级显卡可跑（社区说法，未官方验证）。
- **Nemotron / Cosmos 集成**：HF 模型卡称 "integrated into NVIDIA's **Nemotron 3 Nano Omni, Nemotron, and Cosmos** products"；交叉印证：Cosmos 3 论文（[arXiv:2606.02800v4](https://arxiv.org/html/2606.02800v4)）写道 "We curate 2D grounding data from synthetic and existing data, with a majority coming from **LocateAnything**"；NVIDIA 官方宣传帖将 LocateAnything-3B 与 NEMOTRON 3 NANO OMNI 并列。集成深度细节（哪些产品内置权重 vs 用其数据）官方未展开。
- 社区生态（非官方）：ComfyUI-LocateAnything 节点、locate-anything.cpp（C++17/ggml 本地推理移植）。
- 局限（HF 模型卡原文）：仅研究/开发用途、**Linux only**、TensorRT / TensorRT-LLM / Triton "not yet supported"、无 MagiAttention 时 MTP 退回较慢的 SDPA、batched runtime 不支持训练标签路径、Fast 模式适合简单场景（鲁棒性低于 slow/hybrid）。
- 论文 future work："Currently, our model is primarily trained with supervised fine-tuning"，下一步用 RL 优化 block 级解码、降低 fallback 频率、攻密集/长尾难例。

## 13. 结论速览

LocateAnything 是 NVIDIA Eagle VLM 家族的 grounding 特化 3B 模型（MoonViT-SO-400M + Qwen2.5-3B-Instruct + MLP），以"box/point 为原子单元、L=6 定长 block、单步并行解码"的 PBD 方法统一了 8 类定位任务（检测/密集检测/REC/OCR 定位/场景文字/文档版面/GUI/pointing），在 12M 图 / 138M 查询 / 785M 框（含 BDD100K、nuImages、RoboAfford 等驾驶与机器人数据）上四阶段训练，Hybrid 模式单卡 H100 达 12.7 BPS（10× Qwen3-VL、2.5× Rex-Omni-3B），LVIS mean F1 50.7 超 Rex-Omni +3.8 且高 IoU（@0.95: 31.1 vs 20.7）优势显著，ScreenSpot-Pro 60.3 SOTA；2026-05-26 全套开源（代码 Apache 2.0 / 权重 NVIDIA 非商业许可 / 数据按源许可），2026-06 被 ECCV 2026 接收；当前权重暂不支持 visual prompt 推理（LoRA 脚本已发，官方权重未来发布）。
