## 1. 数据集卡 License Information 节（原文，前序报告全部遗漏）

数据集托管于 HuggingFace 组织 NVEagle：`NVEagle/LocateAnything-Data`（非 nvidia 组织）。License Information 节核心原文（来源：[HF 数据集卡](https://huggingface.co/datasets/NVEagle/LocateAnything-Data)，raw README 双重核对）：

> "LocateAnything-Data is a collection built from multiple upstream datasets. Each source dataset remains governed by its original license, terms of use, access conditions, and attribution requirements. Users must review and comply with the applicable terms of each source dataset before use."

> "This repository does not grant additional rights to upstream media."

Copyright concerns 小节：

> "This collection is prepared for academic research."

投诉机制：通过 HuggingFace Community discussions tab 提出，维护者审查后可移除受影响内容。

**三个关键事实：**

1. **无统一 license**——数据集不设整体许可，逐源继承上游条款（确认前序抽查，原句见上）。
2. **卡上没有任何一个源标注具体许可证名称**。我深读了整个 README（13 个章节标题全部提取），License Information 节不给任何 per-source license 名（无 CC-BY、无 Apache、什么都没有）。逐源查证完全是使用者的义务——这是合规审查的最大摩擦点。
3. **明确免责声明**："does not grant additional rights to upstream media"——NVIDIA 不授予任何额外权利，全部风险在使用者侧。

**另一处前序报告的口径修正**：前序报告引用的 12M 图像 / 138M 查询 / 785M 框来自模型卡与论文口径；**数据集卡本身不报这些规模数字**，只给出仓库体积 2.41 TB 与上月 30,087 次下载。引用数据规模时应注明出处是模型卡（"a large-scale multi-domain dataset (12M images, 138M+ queries, 785M bounding boxes)"）而非数据集卡。

## 3. 图像不随库分发的 7 个源与 hydration 机制

README 专设 "Media downloaded from upstream sources" 节，原文：

> "Media from the following datasets must be obtained from the original source."

**7 个不随库分发图像的数据集文件夹**：`crowdhuman`, `deepfashion2`, `flickr30k`, `partimagenet`, `object365`, `sku110k`, `unsplash`。仓库只含它们的 annotations、JSONL indexes、source-image mappings 与 metadataset 配置，**不含图像文件**。

各源期望的上游目录布局（hydration 输入约定）：

| Folder | 上游渠道 | source-root 下期望路径 |
|---|---|---|
| crowdhuman | CrowdHuman 官网 | `train/Images/<image>.jpg` |
| deepfashion2 | DeepFashion2 GitHub | `train/image/<six-digit-id>.jpg` |
| flickr30k | Flickr30K（U. Illinois 页面） | `flickr30k-images/<flickr-id>.jpg` |
| partimagenet | ImageNet | `train/<wnid>/<wnid>_<id>.JPEG` |
| object365 | Objects365 官网 | `images/train/patch*/objects365_v1_<id>.jpg` |
| sku110k | SKU-110K GitHub | `images/train_<id>.jpg` |
| unsplash | Unsplash — **hydration 不支持** | `raw_unsplash_images/<photo-id>.jpg` |

**hydration 步骤**（README 原文归纳）：(1) 从官方渠道下载图像并接受其条款；(2) 按上表布局摆放上游文件名；(3) 安装 `megatron-energon==7.4.0`；(4) 对每个数据集运行一次：

```
python tools/hydrate_restricted_media.py \
  --repo-root /data/LocateAnything-Data \
  --dataset crowdhuman \
  --source-root /data/upstream/CrowdHuman
```

辅助工具 `tools/download_subset.py` 支持 `--list` / `--dry-run` / `--dataset coco,paco` / `--annotations-only` 选择性下载。

**其他关键约束**：
- **Unsplash 例外**：Unsplash"不提供稳定程序重建该 release 引用的确切历史图像字节"，"Unsplash media hydration is therefore not currently supported"——标注与 source-image mapping 在库，但图像无法合规复现。
- **本地性约束**："Hydrated media remains local and must never be pushed back to the Hugging Face repository"。
- `metadataset.yaml` 只覆盖库内托管媒体；`metadataset-full.yaml` 仅在外部媒体池本地 hydration 完成后可用（unsplash 被排除在支持列表外）。
- 注意：hydration 的第一步就是"到上游下载并接受其条款"——对 CrowdHuman / ImageNet / Objects365 这类需注册接受条款的源，**获取数据的行为本身就意味着接受了 NC 条款**。

## 6. 合规风险结论（面向「拿该数据集微调 / 蒸馏 / 混入自有训练集」）

1. **不能整体套用单一许可**。任何使用前必须逐源过牌；NVIDIA 数据集卡连 per-source license 名都不给，等于把查证成本完全转给使用者。
2. **商用训练管线存在直接违约风险**：BDD100K、nuImages、MOT17/20、CrowdHuman、SKU-110K、Flickr30K、DeepFashion2、PartImageNet 共 8 个已证实 NC 源。混入自有训练集属于这些条款明文禁止的商用用途范畴。
3. **ShareAlike 传染不确定性**：nuImages（CC BY-NC-SA 4.0）与 MOT17/20（CC BY-NC-SA 3.0）的 SA 条款对"衍生数据库"（包括再标注/重写的 box/point 标注）是否触发同许可分发义务，法律上无定论——商用场景应按最坏情形处理（整源剔除）。
4. **蒸馏/伪标注闭环被模型许可双重阻断**：即使只用模型（不动数据集）生成伪标注再训练自有模型，LocateAnything-3B 本身"Commercial use is not permitted, except by NVIDIA and its affiliates"，伪标注产物的商用下游同样被模型许可卡死。这是第 1 项（商用评估）的直接法律输入：**模型与数据集两端都是 NC，不存在"只用一头"的商用路径**。
5. **剔除策略技术可行**：数据集按源组织（per-dataset 文件夹 + JSONL index + `tools/download_subset.py --dataset` 选择下载；`metadataset.yaml` 本来就只含库内托管媒体子集），可按白名单只取 COCO / Open Images / Objects365 等标注 CC BY 4.0 源——但注意 COCO/Open Images 的**图像**仍各有逐图/版权细节，且剔除 NC 源后数据规模与 driving/dense 能力大幅缩水（12M/138M/785M 是全量口径）。
6. **Unsplash 子集特殊**：hydration 官方不支持 → 无法复现该子集训练；如只用库内托管部分训练则自然不含 unsplash 图像；Unsplash License 的 no-compilation 条款使其商用归属长期灰色。
7. **商用授权路径**：模型端需联系 NVIDIA 获取单独商业授权（公开渠道无价格/流程信息）；数据端各 NC 源需分别联系权利人（Berkeley、NVIDIA nuScenes 团队、MOT Challenge、Megvii、Trax、UIUC、CUHK、ImageNet/Stanford 等）。

## 7. 事实与观点的区分

- 事实（多源/官方确认）：数据集卡 license 原文、7 个 hydration 源、hydration 脚本与参数、各上游许可证条款（引官方页）、模型 NC 许可、发布日期 05/26/2026。
- 单一来源标注：数据集卡 "2.41 TB / 30,087 downloads last month" 仅 HF 卡可见（单一来源）；SKU-110K "proprietary license by Trax" 的精确措辞经 HF 镜像与 MDPI 论文转述（原始 repo LICENSE 未逐字核对）。
- 社区观点（非事实）：ImageNet 预训练模型能否商用的 Reddit 讨论（普遍认为风险高/不允许）；PicDefense 对 Unsplash 免费档无赔偿的风险点评；"compile a similar service"是否涵盖 ML 数据集——无判例，未证实。
