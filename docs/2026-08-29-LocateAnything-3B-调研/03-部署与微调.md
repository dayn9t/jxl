## 3. 推理

### 3.1 官方路径：transformers（唯一官方支持）

- **版本强锁定 `transformers==4.57.1`**。官方安装命令（[模型卡 Installation 节](https://huggingface.co/nvidia/LocateAnything-3B)，ModelScope 同）：
  ```bash
  pip install opencv-python-headless==4.11.0.86 transformers==4.57.1 numpy==1.25.0 Pillow==11.1.0 peft torchvision decord==0.6.0 lmdb==1.7.5
  # torch 按 CUDA 版本单独安装（pytorch.org/get-started）
  ```
- 可选 **MagiAttention v1.0.5**（仅 Hopper/Blackwell，加速 MTP 推理）：从 SandAI-org/MagiAttention 仓库 `git checkout v1.0.5` 后 `pip install --no-build-isolation .`；未安装则自动回退 PyTorch SDPA——功能完整但 MTP 解码较慢。
- **必须 `trust_remote_code=True`**（架构未进 transformers 主线，全部建模代码在 repo 的 11 个 .py 文件里）。
- 官方推荐两种加载：
  ```python
  from transformers import pipeline, AutoModel
  pipe = pipeline("image-text-to-text", model="nvidia/LocateAnything-3B", trust_remote_code=True)
  model = AutoModel.from_pretrained("nvidia/LocateAnything-3B", trust_remote_code=True,
                                    torch_dtype=torch.bfloat16, device_map="auto")
  ```
- **推荐用法是模型卡自带的 `LocateAnythingWorker` 类**（可整类丢进 FastAPI / gRPC / Triton 服务框架）。其核心调用链（从模型卡原样摘录）：
  ```python
  self.tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)
  self.processor = AutoProcessor.from_pretrained(model_path, trust_remote_code=True)
  self.model = AutoModel.from_pretrained(model_path, torch_dtype=torch.bfloat16,
                                         trust_remote_code=True).to(device).eval()
  # predict():
  text = self.processor.py_apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
  images, videos = self.processor.process_vision_info(messages)
  inputs = self.processor(text=[text], images=images, videos=videos, return_tensors="pt").to(device)
  response = self.model.generate(
      pixel_values=inputs["pixel_values"].to(self.dtype),
      input_ids=inputs["input_ids"],
      attention_mask=inputs["attention_mask"],
      image_grid_hws=inputs.get("image_grid_hws", None),
      tokenizer=self.tokenizer, max_new_tokens=max_new_tokens, use_cache=True,
      generation_mode="hybrid",      # "fast"(MTP) | "slow"(AR) | "hybrid"
      temperature=0.7, do_sample=True, top_p=0.9, repetition_penalty=1.1, verbose=verbose)
  ```
  便捷方法：`detect` / `ground_single` / `ground_multi` / `ground_text` / `detect_text` / `ground_gui` / `point`，以及静态解析器 `parse_boxes` / `parse_points`。官方建议 `max_new_tokens=8192` + `generation_mode="hybrid"` 以避免截断并平衡速度与精度。
- **批量高吞吐**：repo 自带 `batch_infer.py` + `batch_utils/` + `kernel_utils/`，`la_flash` 后端为纯 FlashAttention-varlen 稀疏范围执行器（不建自定义 CUDA 扩展）：
  ```bash
  python batch_infer.py --model . --attn la_flash --scheduler pipeline \
    --batch-size 4 --image /path/to/image.jpg --query "person</c>car"
  ```
  官方 A100 4K 探针（真实 3840×2160 街景、query=vehicle、batch_size=4、`in_token_limit=25600`、hybrid MTP）：`sdpa` 后端 8.2600 s / 峰值预留 35.12 GB；`la_flash` 后端 8.0314 s / **峰值预留 11.71 GB**。

### 3.2 vLLM / SGLang / TensorRT-LLM / NIM：均无官方支持（2026-08 时点）

- **模型卡明文**："Runtime Engine(s): Transformers … **TensorRT, TensorRT-LLM, and Triton are not yet supported**"（[ModelScope 卡 Software Integration 节](https://modelscope.cn/models/nv-community/LocateAnything-3B)）。
- **vLLM/SGLang**：[官方 repo 讨论 #3](https://huggingface.co/nvidia/LocateAnything-3B/discussions/3)（2026-05-30 Vishva007 提问，14 赞）——NVIDIA 团队成员 ShihaoW 2026-06-02 回复坦承团队"缺乏高吞吐引擎经验"、"**没有官方集成或推荐 Docker 容器的近期计划**"，欢迎社区 PR。社区进展：Columbus688 借 Kimi-VL 适配代码 + Qwen2.5-VL processor 逻辑修复 `<image-1>` token 转换 bug，配合 **vLLM PR #44182**（新增 LogitsProcessor）后在笔记本上"works just so good"；Liuwang971 指出该 PR 缺 MTP 路径（MTP 约有 2x–2.5x 加速），并给出自己带 MTP 的项目；shigureui（06-04）共享了基于 vLLM embedding 输入的可运行 notebook [WuNein/LocateAnything-vLLM](https://github.com/WuNein/LocateAnything-vLLM)。以上均为社区方案，未经官方验证。
- **build.nvidia.com NIM API**：**未发现托管端点**。直接访问 `build.nvidia.com/nvidia/locateanything-3b` 只返回通用 NIM 落地页 shell（页面带 `robots: noindex`、无模型内容），多次搜索亦无任何 Hosted API 记录；与模型卡"仅 Transformers"的说法互相印证。llms.txt 模型清单抓取超时，未能逐一排除（见 gaps）。
- **落地为 OpenAI 兼容 API 的社区实录**（强烈建议读）：[NVIDIA 论坛帖](https://forums.developer.nvidia.com/t/getting-nvidia-locateanything-3b-running-as-an-openai-compatible-api-on-a-dgx-spark-gb10-blackwell/371829)（swann.schilling，2026-05-31，DGX Spark GB10 Blackwell 128 GB 统一内存）。要点：
  - "LocateAnything is not a vLLM-served model" → 用 Eagle 仓库官方 `LocateAnythingWorker` 挂 **FastAPI**（uvicorn 监听 8889），自建任务型 REST 端点 `/v1/locate`（支持 detect / ground / ground_single / detect_text / ground_gui / point，可指定 mode），非标准 OpenAI chat 接口；
  - 五个坑：① `decord` 无 ARM64 轮子（transformers 静态扫描导入，sys.modules 打桩无效 → 本地构建空实现 stub 包再 pip install）；② deepspeed / bitsandbytes / liger_kernel 在 ARM64 编译失败（纯推理用不到，`pip install --no-deps -e .` 绕过）；③ **MoonViT 视觉编码器权重从 `moonshotai/MoonViT-SO-400M` 单独拉取**，未认证会静默挂起，需同时设 `HF_TOKEN` 与 `HUGGING_FACE_HUB_TOKEN`（单一来源，未在官方卡中说明）；④ 统一内存机器上禁用 `device_map='auto'`（会卡元数据分析数分钟），直接 `.to(device)`；⑤ 必须用官方 Worker，不能裸调 `model.generate()`——PBD 依赖自定义 `generation_mode` 参数；
  - 实测性能：单图检测 5 个骰子 **1.35 s、3.7 BPS（boxes/sec）、零 AR 回退、约 25 tokens/s**。
  - 另有社区 HTTP 封装 [dliebner/LocateAnythingAPI](https://github.com/dliebner/LocateAnythingAPI)（OpenAI 兼容 `/v1/chat/completions` + 带遥测的 `/api/inference`，单一来源未实测）。

## 4. 硬件要求

- **官方支持矩阵**（模型卡 Software Integration）：Ampere（A100）/ Hopper（H100）/ Blackwell / Lovelace（L40、**RTX 4090**）；操作系统 **Linux**；BF16 + KV cache。嵌入式 Thor 需额外优化（量化/压缩/蒸馏）才可部署。未列 AMD/CPU/macOS。
- **BF16 显存实测**（[RTX 3090 vs Jetson AGX Thor 基准](https://multimodalflow.net/en/blog/locateanything-3b-benchmark-3090-vs-thor/)，无量化、640×480 测试图）：
  - 加载后显存 **7,406 MB**、推理峰值 **7,938 MB**（3090 与 Thor 数字相同，因为同为 BF16 权重）；
  - RTX 3090（24 GB，CUDA 12.4 / PyTorch 2.6.0+cu124 / transformers 4.57.1）：加载 8.1 s；短语 grounding 298 ms、文本检测 299 ms、pointing 300 ms、双类检测（hybrid）4,150 ms；10 次单类检测平均 301 ms（3.32 fps，波动 297–307 ms）；首次推理预热 6,760 ms、稳态 300 ms；
  - Jetson AGX Thor（128 GB 统一内存，CUDA 13.0 / PyTorch 2.12.0+cu130）：grounding 642 ms；10 次平均 674 ms（1.48 fps，波动 596–1004 ms）；仅用 128 GB 的 6%；功耗对比 ~350W（3090）vs ~60W（Thor）；
  - 意外发现：该测试中检测任务 `slow` 模式反而最快（3090 上 966 ms vs hybrid 4,150 ms、fast 2,020 ms）——小图/少框场景 MTP 并行收益可能为负，值得按自己的负载实测三档模式；
  - 两设备输出 **bit-identical 边界框**，验证 BF16 推理确定性。
- **消费级显卡结论**：权重 BF16 约 7.4 GB → **12 GB 卡（RTX 3060/4070 级）即可跑常规分辨率推理**；4K 大图 + batch + SDPA 后端峰值可到 35 GB（需 A100 80GB 级），换 `la_flash` 后端可压到 11.71 GB。第三方安装指南给的最低门槛为 8–12 GB VRAM（[globalaiforce 指南](https://globalaiforce.com/locateanything-how-to-install-and-set-up-2026-guide/)，单一来源）。国产环境实录：麒麟 V10 + RTX 4090（23 GB）+ CUDA 13.0 + transformers/Conda 部署成功（[openEuler/CSDN 记录](https://openeuler.csdn.net/6a36bbcd662f9a54cb822e8b.html)，单一来源）。
- **量化**：官方未出量化版；22 个社区量化（GGUF/NVFP4/ONNX-INT4/MLX-8bit/CoreML，见 §1.4）。Thor 基准作者判断 Thor 需 INT8/INT4 才够实时视频（原生精度仅 1.48 fps）。

## 5. 微调

### 5.1 官方微调代码：NVlabs/Eagle/Embodied（齐全）

官方训练/微调代码在 [github.com/NVlabs/Eagle/tree/main/Embodied](https://github.com/NVlabs/Eagle/tree/main/Embodied)（目录含 `eaglevl/`、`shell/`、`deepspeed_configs/`、`document/`（TRAINING.md / DATA_PREPARATION.md / RESULTS.md）、`evaluation/`、`locateanything_worker.py`、`LICENSE_MODEL`）。以下摘自 [Embodied/README.md](https://raw.githubusercontent.com/NVlabs/Eagle/main/Embodied/README.md)：

- **全参持续 SFT**：`eaglevl/train/locany_finetune_magi_stream.py`，官方示例（8 卡）：
  ```bash
  torchrun --nproc_per_node=8 \
    eaglevl/train/locany_finetune_magi_stream.py \
    --model_name_or_path nvidia/LocateAnything-3B \
    --meta_path "./locany_recipe/your_recipe.json" \
    --output_dir work_dirs/my_sft \
    --max_steps 25000 --learning_rate 2e-5 --bf16 True \
    --block_size 6 --attn_implementation magi --max_seq_length 16384 \
    --deepspeed "deepspeed_configs/zero_stage2_config.json"
  ```
  训练依赖（pyproject.toml 自动装）：`transformers==4.57.1, tokenizers==0.22.0, deepspeed==0.15.4, accelerate==1.5.2, timm>=1.0.11, liger_kernel==0.3.1, peft==0.12.0, decord`。
- **关键限制：训练走 MagiAttention 后端，仅支持 Hopper/Blackwell**。`la_flash` 只覆盖推理/评估（A100、L40 可用），README 明确"training should continue to use the standard model code path"——即 A100/消费卡训练非官方支持路径。repo 自带的批量运行时"does not support the training labels path"。
- **官方 LoRA 脚本**：`shell/locate-anything-lora-visual-prompt.sh`（用法 `bash shell/locate-anything-lora-visual-prompt.sh 1 work_dirs/locany_lora_visual_prompt`，需 export `HF_TOKEN` 和 `META_PATH=./locany_recipe/visual_prompt_recipe.json`）。环境变量开关：`MODEL_PATH`（默认 nvidia/LocateAnything-3B）、`USE_LLM_LORA`（rank，**默认 64**，0 关闭）、`USE_BACKBONE_LORA`（默认 0）、`FREEZE_LLM` / `FREEZE_BACKBONE` / `FREEZE_MLP`、`MAX_STEPS` / `LR` / `SAVE_STEPS` / `MAX_SEQ_LENGTH`。visual-prompt LoRA 默认：LLM LoRA rank 64 + 冻结 LLM 与视觉骨干 + **MLP projector 保持可训**。也可在 config 层开 LoRA（社区文章示例：`config.use_llm_lora = 64; config.use_backbone_lora = 64` 再 `AutoModel.from_pretrained(..., config=config, trust_remote_code=True)`）。
- **数据格式**（document/DATA_PREPARATION.md）：JSONL 标注 + recipe JSON 混合：
  ```json
  { "my_visual_prompt_data": {
      "annotation": "path/to/visual_prompt.jsonl", "root": "/data/images/",
      "repeat_time": 1.0, "data_augment": true, "visual_prompt": true } }
  ```
  `visual_prompt: true` 会把单类别检测正样本转成裁剪视觉 prompt 追加为额外图像占位符。**注意：公开权重不含 visual-prompt 推理能力**（"Visual-prompt-capable weights will be released in a future version"），要用此能力必须自己微调。
- 评测脚本：`evaluation/scripts/eval_coco.sh / eval_lvis.sh / eval_grounding.sh / eval_sspro.sh`。

### 5.2 社区微调实践：知乎《微调LocateAnything-3B 实现超高密度的目标检测》

已全文深读（[知乎专栏 deephub，2026-06-21 发](https://zhuanlan.zhihu.com/p/2052141785674208812)，原作 Yash M Gupta, PhD；转载：[博客园](https://www.cnblogs.com/deephub/p/20684302)、[阿里云开发者社区](https://developer.aliyun.com/article/1742641)）。场景：单图 100–500+ 密集重叠小目标（种子发芽托盘/谷物质检），人工画框不可行（300 框 ≈ 25 分钟/图，1000 图 > 400 工时）。四阶段半监督 pipeline，标注量降约 90%：

1. **点标注 + SAM2 转框**：点比框快约 10 倍（300 点 ≈ 5 分钟）。`sam2.1_hiera_large` 逐点出 mask 再取外接框；粘连目标点击上层可见中心，误合并时 watershed 后处理。
2. **训轻量检测器**：在 SAM2 伪标签上训 `yolo11n.pt`（epochs=50、imgsz=640、batch=16、patience=10、HSV/旋转/翻转/mosaic/mixup 增强），得到 100+ FPS 专用检测器。
3. **全量伪标签**：YOLO11 扫全部无标注图（conf=0.65 起、NMS IoU=0.5），输出为 LocateAnything 对话格式 JSONL（human/gpt conversations）；密集场景用「尺寸感知过滤」（面积偏离中位数 2 倍即弃）替代标准 NMS 防过度抑制。
4. **微调 LocateAnything-3B**：recipe JSON 给密集伪标签 `repeat:3/length:15000`、人工核验数据 `repeat:8/length:2000`（少而精、防学偏 YOLO）、弱计数字幕 `repeat:2/length:5000`；训练命令：
   ```bash
   torchrun --nproc_per_node=4 \
     eaglevl/train/locany_finetune_magi_stream.py \
     --model_name_or_path nvidia/LocateAnything-3B \
     --meta_path "./recipes/seed_finetune_recipe.json" \
     --output_dir work_dirs/locany_seed_sft \
     --max_steps 10000 --learning_rate 1e-5 --warmup_ratio 0.1 \
     --lr_scheduler_type cosine --bf16 True --block_size 6 \
     --attn_implementation magi --max_seq_length 8192 \
     --per_device_train_batch_size 1 --gradient_accumulation_steps 8 \
     --save_steps 2000 --logging_steps 10 --report_to tensorboard \
     --deepspeed "deepspeed_configs/zero_stage2_config.json"
   ```
   显存不够走 LoRA（`use_llm_lora=64` / `use_backbone_lora=64`）：**可训练参数从约 38 亿压到约 2 亿，单张 A100 或 2 张 RTX 4090 可完成**（注意与 §5.1 官方"训练需 Hopper/Blackwell MagiAttention"的口径张力，社区在非 Hopper 卡上跑 `--attn_implementation magi` 的可行性未验证）。
   进阶技巧：① ensemble prompting（"Locate every single seed …, including overlapping ones" 等 3 种措辞分别推理取最多框，再 soft-NMS/加权融合提召回）；② 无任何标注时用文本-视觉交叉注意力峰值 + `scipy.ndimage.maximum_filter` 找局部极大值当伪点喂回阶段 1（作者自注"理论"性质，未验证）。
   ⚠️ **该文的坐标格式代码是伪代码**：作者自注"具体 Token 化方式取决于 processor；此处展示逻辑结构"（写成了 `<>{x1} {y1} {x2} {y2}<>`），**实际格式见 §6 的官方 `<box><x1><y1><x2><y2></box>`、[0,1000] 整数**，照抄伪代码会训废。该文许可证表述（"NVIDIA Open Model License"）亦与 LICENSE 原文冲突（见 §2）。

## 6. 输入输出契约

### 6.1 输入

- **官方契约：Image + Text**（模型卡 Input Type(s) 原文 "Image and Text"）。图像：RGB、原生分辨率，**生产分辨率最高 2.5K**；文本 prompt 最长 **24K tokens**；训练检测/定位阶段最大序列 **25,600 tokens**；推理最多生成 **8,192 new tokens**（[HF 卡](https://huggingface.co/nvidia/LocateAnything-3B) / [ModelScope 卡](https://modelscope.cn/models/nv-community/LocateAnything-3B)）。
- **Prompt 模板**（模型卡 Supported Tasks 表，逐字引用）：

| 任务 | Worker 方法 | Prompt 模板 |
|---|---|---|
| 目标检测/文档布局 | `detect(img, [categories])` | `Locate all the instances that matches the following description: [CATEGORIES].` |
| 短语定位（单实例） | `ground_single(img, phrase)` | `Locate a single instance that matches the following description: [PHRASE].` |
| 短语定位（多实例） | `ground_multi(img, phrase)` | `Locate all the instances that match the following description: [PHRASE].` |
| 文本定位 | `ground_text(img, phrase)` | `Please locate the text referred as [PHRASE].` |
| 场景文字检测 | `detect_text(img)` | `Detect all the text in box format.` |
| GUI 定位（框） | `ground_gui(img, phrase, "box")` | `Locate the region that matches the following description: [PHRASE].` |
| GUI 定位（点）/ 指向 | `ground_gui(..., "point")` / `point(img, phrase)` | `Point to: [PHRASE].` |

  多类别用 **`</c>` 连接**（如 `person</c>car`；`[CATEGORIES]` 也可逗号分隔列表）。`[PHRASE]` 为自由文本。

### 6.2 输出与解析

- 输出为含结构化坐标 token 的文本：框 `<box> x1, y1, x2, y2 </box>`、点 `<box> x, y </box>`；**坐标为 [0, 1000] 归一化整数**（千分制量化）。无目标用 `<box>none</box>`。
- 输出组织为**定长 6 的块**（Semantic / Box / Negative / End），空位用 **`<null>`** 填充。
- 官方解析器（模型卡原样）：
  ```python
  # 框：r"<box><(\d+)><(\d+)><(\d+)><(\d+)></box>" → x1/1000*image_width …
  # 点：r"<box><(\d+)><(\d+)></box>" → x/1000*image_width, y/1000*image_height
  ```
- **生成模式**（PBD 专属参数 `generation_mode`，这是不能裸调 `model.generate()` 的原因）：`fast`（纯 MTP，最快，简单场景）/ `slow`（纯自回归，最稳）/ `hybrid`（默认，MTP 优先、不确定框回退 AR、框结束切回 MTP）。Worker 默认采样参数 `temperature=0.7, do_sample=True, top_p=0.9, repetition_penalty=1.1`。
- 消费注意事项（NVIDIA 论坛社区回复提醒）：模型对输入分辨率和 prompt 格式有特定要求，不符会得到「静默降级」的结果——务必按上表模板写 prompt。

### 6.3 视频帧支持

- **官方模型卡只声明 Image + Text 输入**；但代码留有视频通道：processor 调用带 `videos` 参数、`process_vision_info` 返回 `(images, videos)`、依赖列表含 `decord==0.6.0`（视频解码库）。DGX Spark 实测者反馈：在 Jetson/aarch64 用 decord 空 stub 满足导入即可，"grounding 任务用不到视频加载"（单一来源）。
- 社区证据：OpenBayes 在线 Demo 暴露 **"Max Video Frames" 参数**（控制视频任务抽取参与推理的最大帧数，[OpenBayes notebook](https://openbayes.com/console/public/notebooks/BOBBbLqe3BL)，单一来源）；HyperAI 新闻称支持"图像+视频目标指向"（[hyper.ai/cn/news/51673](https://hyper.ai/cn/news/51673)，单一来源）。
- **工程结论**：以官方契约为准——视频按「抽帧 → 多图输入」处理（原生分辨率 VLM 天然支持多图占位符），官方文档未给出视频专用的帧数/时序训练或推理协议，依赖视频能力的生产方案需自行验证。
