# 通用化样本构建工具链设计（2026-07-09）

> 将"视频→样本→标注→复核→去重→划分"工具链从 person 特化重整为**类别通用**，支持人头/人手/手机等任意类别。核心：**TargetProfile 单一数据源** + 全链路去 person 耦合 + 命名中性化（改名+别名）。

## 1. 背景与目标

现有 `src/jxl/bin/` 工具链（`det_mine` 多模型共识 + `doubao_relabel` VLM 复核 + `person_crop`/`person_dedup` 前景去重）为 person 特化构建，但多数算法类别无关。目标：参数化 person 耦合点 + 统一"目标 profile"，让任意类别复用整套链路。

**核心目标**：通用化（**非**端到端编排）。让现有工具支持任意类别。

**成功标准**：
- `det_mine --target phone` + `doubao_relabel --target phone` 产 phone YOLO 标注
- 新增类别（如 phone/head）只需加 `targets/phone.toml`，**不改代码**
- 现有 person 工作流不破（别名兼容）

## 2. 现状（探索结论）

| 环节 | 通用化 | person 耦合点 |
|------|--------|--------------|
| 抽帧 mkv_keyframes/video_to_frames/frame_sample | ✅ 全通用 | — |
| det_mine | 🟡 较强 | `--target` 已驱动 YOLOE/GDINO；残留 `--target-model` 默认 person.pt；RF-DETR cls-id 需手查 |
| doubao_relabel | 🔴 PROMPT 写死 | PROMPT 常量 person 化、输出 cls hardcode 0；已复用 rmb_ground 后端 |
| 去重 person_crop/embed/dedup | 🟡 算法通用 | 命名/docstring 强绑 person；`--person-class` 已参数化；reid(OSNet) 行人专用 |
| 转换 coco/mot/crowdhuman_to_yolo | 🟡 部分 | coco `--categories` 通用；mot/crowdhuman 本质行人数据集 |
| 组合 link_samples/jxl_split | ✅ 通用 | link_samples 默认 datasets_root 含 `/person/` |

**关键**：`rmb_ground` 是 VLM 通用后端（`doubao_relabel` 已 import 它），`doubao_relabel` 是"读 manifest + 调 rmb_ground + 写 label"薄壳，唯一重复是 PROMPT。`det_mine --target` 已部分通用。

## 3. 设计

### 3.1 TargetProfile 机制（核心，单一数据源）

**库** `src/jxl/target.py`（Functional Core，纯函数 + pydantic）：
```python
class TargetProfile(BaseModel):
    name: str                       # "person"
    yolo_text: str                  # YOLOE set_classes + GDINO prompt
    rfdetr_cls_id: int | None       # RF-DETR COCO id; None=跳过(head/hand 非 COCO)
    vlm_prompt: str                 # doubao_relabel PROMPT
    weights: str                    # target model 路径
    output_cls_id: int = 0          # YOLO label 输出 class

def load_target(name: str, profile_path: Path | None = None) -> TargetProfile:
    """--target <name> → 自动找 targets/<name>.toml(内置) 或 --target-profile <path>。"""
```

**profile 文件** `targets/<name>.toml`（项目内置 + 用户扩展）：
```toml
# targets/person.toml
name = "person"
yolo_text = "person"
rfdetr_cls_id = 0
vlm_prompt = """检测图中所有 person 的位置。严格只输出一个 JSON 数组..."""
weights = "/opt/howell/iap/current/ias/model/person.pt"
output_cls_id = 0
```

**查找顺序**：`--target-profile <path>` 显式 > `targets/<name>.toml`（项目内置）> 报错（不静默回退，符合 No Silent Degradation）。

**工具统一入口**：`--target person`（自动加载）或 `--target-profile <path>`（覆盖）。

### 3.2 工具接入 profile

| 工具 | 改动 |
|------|------|
| `det_mine` | 加 `--target`/`--target-profile`：target_model←profile.weights、YOLOE/GDINO←profile.yolo_text、RF-DETR cls←profile.rfdetr_cls_id（**None 跳过 RF-DETR**）、输出 cls←profile.output_cls_id |
| `doubao_relabel` | 删模块级 PROMPT 常量 + cls hardcode → 读 profile.vlm_prompt + output_cls_id |
| `crop_foreground`（原 person_crop）| 加 `--target`（映射 output_cls_id），保留 `--cls-id` 直接传 |
| `embed_dino`/`dedup_sem` | 算法不变；crop 按 profile.output_cls_id（经 crop_foreground 传入）|
| `link_samples` | 默认 `_DATASETS_ROOT` 去 `/person/`（改必填或相对 cwd）|

### 3.3 命名中性化（改名 + 别名兼容）

| 旧名 | 新名 |
|------|------|
| person_crop | **crop_foreground** |
| person_embed | **embed_dino** |
| person_dedup | **dedup_sem** |
| samples_dedup | **dedup_image_fp** |
| samples_core | **coreset_image** |
| person_dedup_reid / person_reid_embed | **保留旧名**，docstring 标"person 专用（OSNet 行人，不适他类）"|

**别名机制**：`bin/person_crop.py` 保留为薄转发（`from jxl.bin.crop_foreground import app` + `if __name__ == "__main__": app()`），旧调用/脚本/文档不破。新代码用中性名。

### 3.4 转换工具（不强行通用）

- `coco_to_yolo`：`--categories` 已通用，保留
- `mot_to_yolo`/`crowdhuman_to_yolo`：本质行人数据集，保留 person 耦合 + docstring 标注（他类用不到，YAGNI）

### 3.5 附带重构

- `xyxy_iou`：抽 `src/jxl/det/box_utils.py`，`hardmine.py` + `rmb_eval_grounding.py` 共用（消除重复，hardmine docstring 已点名）

**修改**：
- `src/jxl/bin/det_mine.py`（接 profile）
- `src/jxl/bin/doubao_relabel.py`（接 profile，删 PROMPT 常量）

## 5. 接口契约

- `load_target(name, profile_path=None) -> TargetProfile`：找不到 profile → 抛异常（不回退）
- `TargetProfile` pydantic v2 校验（rfdetr_cls_id=None 合法；weights 路径不校验存在，运行时 det_mine 报）
- 各 bin `--target`/`--target-profile` 二选一（至少一个，否则报错）
- det_mine RF-DETR 行为：`--validators` 默认（未显式）且 `rfdetr_cls_id=None` → 自动用 yoloe,gdino；`--validators` 显式含 rfdetr 但 `rfdetr_cls_id=None` → 报错（冲突，不静默降级）

## 6. 测试

- `target_test.py`：TargetProfile 校验（含 rfdetr_cls_id=None）、load_target 查找（内置/显式/缺失报错）
- `box_utils_test.py`：xyxy_iou 边界（重叠/包含/相离/同框）
- 各工具 `--target person` 回归（与现行为一致，不破现有 person 流程）
- 新类别 `--target phone` 冒烟（det_mine 产 YOLO，RF-DETR 跳过验证）

## 7. Global Constraints

- Python ~=3.12，`src/jxl/` mypy strict，ruff ALL（bin/ mypy 排除 + ruff per-file-ignore，既有惯例）
- pydantic v2（库锁定），tomllib 内置（无 pyyaml 依赖，与 link_samples 一致）
- 秘密（doubao api_key）从 `--cfg` json 读，**绝不硬编码**
- 命名遵循 j-coding-style case（PascalCase 类、snake_case 函数）
- 中文 docstring（项目 bin 惯例）

## 8. 范围外（YAGNI）

- **端到端编排**（视频→YOLO 一条命令 wrapper）：本次不做，工具接 profile 后可后续加
- **reid 线通用化**：OSNet 行人专用，不纳入通用 profile
- **mot/crowdhuman 转换他类**：本质行人数据集
- **新类别外部数据集**（OpenImages/Objects365）下载/转换：用通用 `convert_to_yolo.py` 兜底
- **VLM prompt 版本管理**：profile 内嵌即足够，不单独做 prompt 仓库

## 9. 设计原则对齐

- **单一数据源**（原则 8）：类别定义一处（targets/*.toml），不散落 5 处 CLI/硬编码
- **Functional Core**（原则 6）：target.py 纯 pydantic + 纯函数，可单测；bin 是 Imperative Shell
- **类型排除非法状态**（原则 7）：`rfdetr_cls_id: int | None` 类型表达"可选 RF-DETR"
- **可测试性**（原则 10）：load_target 纯函数 + pydantic 校验，确定性可测
