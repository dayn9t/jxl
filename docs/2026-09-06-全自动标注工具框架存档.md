# 全自动标注工具框架（存档待启动）

> 2026-09-06 用户口述思路整理存档。**本文档只做设计沉淀，未启动实现**；
> 当前优先级仍是 crop640 人工标注。启动时以本文为需求基线。

## 1. 目标

建立**全自动标注工具**：给定目标类（当前主目标：人）+ 应用场景约束，
产出可信标注，人工只兜底最小残余。

核心原则：**模型能力按场景画像，而非通用 benchmark**——同一模型在本场景
（电力监控 crop640 类数据）的能力 ≠ 公开数据集能力，一切以项目内真值评估为准。

## 3. 流水线框架（六层）

```
L0 场景 profile    目标类 + 定位约束(提示词) + 合规定义(分类体系) + 检测器权重表
L1 检测器池        多检测器并检; 场景化画像驱动 加权/降权/淘汰
L2 共识层          det_mine 加权争议分 + cascade（已有, 直接复用）
L3 VLM 仲裁        分歧帧商用 VLM 补票多数制（已有, 直接复用）
L4 合规过滤        场景约束双通道: 4a 前置注入 + 4b 后置分类（新增, 核心增量）
L5 人工兜底        残余队列 review_pack 网格（已有）
反馈环             人工真值 → 更新 L1 画像 → 调整权重（闭环, 持续生效）
```

L4 是本框架相对现状的核心增量，见 §4。

## 4. 场景约束双通道（本框架核心）

用户的洞察：**场景约束（如"肩部可见"）不应只在末端 VLM 判定时排除，
应尽量前置到定位阶段**，同时在末端保留分类过滤兜底。

### 4a 前置通道——定位提示词注入

把场景约束写进开放词汇模型的文本 prompt（如 `person with visible shoulders`）。
**可行性按模型类型分层**：

| 模型类型 | 前置可行性 | 处理 |
|---|---|---|
| 开放词汇检测器（yoloe/gdino） | ✅ prompt 可加限定 | prompt 注入约束 |
| VLM grounding（doubao/qwen/M3） | ✅ prompt 自由 | prompt 注入约束 |
| 闭集检测器（rfdetr/生产 person.pt） | ❌ 类别固定 | 只能靠 4b 后置过滤 |

### 4b 后置通道——合规分类器

对全部候选检测框（各模型检测到的目标）裁切 crop → 判定是否满足场景要求。

**电力场景三分类**（用户裁决，2026-09-06 首定"肩部可见"；同日二次细化：
**合格 = 至少一侧肩部轮廓可辨识 + 身体至少约 40% 可见**）：

| 类 | 定义（操作化建议） | 去向 |
|---|---|---|
| **C0 非人** | 框内无人（误检：树影/座椅/反光/海报人像等） | 丢弃，计入该模型误检统计 |
| **C1 不合规的人** | 框内有人，但**肩部不可见**（仅手/脚/腿/头局部或肩被遮挡/出画）**或身体可见 <40%** | 剔除，不产出标注 |
| **C2 合规的人** | 肩部至少一侧轮廓可辨识（正/背影均可；衣物遮挡但轮廓在也算）**且身体可见 ≥40%** | 合格，产出标注 |

**开放定义问题**（启动前需用户裁决）：
1. 单侧肩可见即 C2，还是要求双侧？
2. 肩部被裁切约一半（框边缘）算 C1 还是 C2？
3. 海报/屏幕/图纸里的人像 → 建议归 C0（非真实人），需确认
4. 多人挤在一个框内（检测器合并框）→ 建议按"最难目标"归类（有一个 C1 即 C1），需确认

**冷启动 → 常态化两阶段**：
- 冷启动：crop 池交商用 VLM 三分类（多 VLM 投票 + 分歧人工抽检）——复用 vlm_ensemble 多数制
- 常态化：用 VLM 标好的 crop 池训练轻量分类器（选型启动时定），替代 VLM 做日常过滤
  （成本/速度动机：VLM 按次计费且慢，分类器本地毫秒级）

## 5. 场景 profile 泛化

电力场景只是实例。推广形态：**一个场景 = 一份 profile**：

```toml
# targets/<scene>.toml（TargetProfile 扩展方向, 具体 schema 启动时设计）
target_class   = "person"                # 目标类
yolo_text      = "person ..."            # L1 检测器 prompt（含前置约束）
vlm_prompt     = "..."                   # L3 VLM prompt（含前置约束）
compliance     = "shoulder"              # L4b 合规定义 → 分类器路由
validator_weights = { rfdetr = 0.35, ... }  # L1 场景化画像权重（反馈环更新）
```

不同场景 = 不同提示词约束 + 不同合规分类器（可能多个分类器并存），
共享同一条 L0-L5 流水线。与现有 `targets/` 单一数据源机制自然衔接。

## 6. 场景化能力画像（L1 反馈环）

数据源：已确认标注池 + 人工真值（持续积累）。
机制：`model_matrix` 已能产出逐模型 P/R/F1 → 扩展为定期重算：
- 淘汰：场景 F1 持续垫底且权重无法补偿的模型，从检测器池移除
- 降权/升权：F1 变化反映到 `validator_weights`
- 注意选择偏差：当前真值集中在"分歧帧"（最难子集），画像偏严；
  人工标注积累后需用全量随机抽检校准

## 7. 与现有代码的衔接点

| 框架层 | 现有载体 | 增量 |
|---|---|---|
| L0 profile | `jxl/target.py` TargetProfile | compliance 分类器路由字段 |
| L2 共识 | `det_mine` | 无（直接复用） |
| L3 仲裁 | `doubao_arbitrate` / `vlm_ensemble` | prompt 读 profile 场景约束 |
| L4a 前置 | 各 detect_* 的 prompt 参数 | 约束注入 |
| L4b 分类 | 无 | 新增：crop 导出 → VLM 冷启动标注 → 分类器训练/推理 |
| L5 兜底 | `review_pack` | 无 |
| 反馈环 | `model_matrix` / `la_eval` 机制 | 定期化 + 权重回写 |
